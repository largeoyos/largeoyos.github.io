## Rust 教程

我有c的基础，教我rust,从头开始深入浅出，每次输出一节的内容

## 第一节：Rust 是什么，为什么值得学

---

### 从 C 的视角出发

此前已经有 C 的基础，这其实是学 Rust 最好的起点。C 给了你一个非常重要的直觉：**内存不是魔法**。你知道变量住在栈上还是堆上，知道指针是什么，知道 `malloc`/`free` 的存在。Rust 正是在这个层面上工作的语言，只不过它用一套全新的规则，让你在享受 C 级别性能的同时，**从根本上消灭一整类 bug**。

---

### Rust 想解决什么问题？

C 的最大痛点，你一定遇到过：

**悬空指针（dangling pointer）**：`free` 了内存之后还在用那块地址，程序轻则崩溃，重则被攻击者利用。

**双重释放（double free）**：同一块内存 `free` 了两次，堆结构损坏。

**数据竞争（data race）**：两个线程同时读写同一块内存，结果不可预测。

**缓冲区溢出（buffer overflow）**：经典的安全漏洞来源。

这些问题在 C 里靠程序员的纪律和经验来避免。而 Rust 的核心思想是：**把这些规则交给编译器来检查**，违反规则的代码根本无法编译通过。这不是运行时检查（像 Java 的垃圾回收），而是编译时的静态保证——所以性能开销几乎为零。

---

### Rust 的三个核心承诺

Rust 官方把自己定位为一门追求"**可靠性、性能、生产力**"的语言。对你来说最重要的是前两个：

**内存安全，无需 GC**：Rust 用"所有权（ownership）"系统在编译期追踪每一块内存的生命周期，自动插入释放代码，不需要垃圾回收器在运行时扫描内存。

**线程安全，编译期保证**：Rust 的类型系统能区分"可以跨线程共享的数据"和"不可以的"，数据竞争在编译期就被拒绝。

**零成本抽象**：你可以用高级语法（迭代器、闭包、泛型），编译出来的机器码和手写的底层 C 一样高效。

---

### 先写一个 Hello World，感受一下语法

在正式讲概念之前，先让你看一眼 Rust 代码长什么样：

```rust
// Rust 的主函数，和 C 的 main() 类似，但不需要返回值声明
fn main() {
    // println! 是一个宏（macro），注意感叹号
    // 宏在 Rust 里很常见，后面会详细解释
    println!("Hello, Rust!");

    // 变量用 let 声明，默认是不可变的（这和 C 完全相反！）
    let x = 5;
    println!("x 的值是：{}", x);

    // 如果想让变量可变，需要显式加 mut
    let mut y = 10;
    y = y + 1;
    println!("y 的值是：{}", y);
}
```

几个你马上会注意到的差异：

首先，**没有头文件**，也没有 `#include`。Rust 有自己的模块系统。

其次，**变量默认不可变**（immutable）。在 C 里，你要特意写 `const` 才能让变量不可变；在 Rust 里反过来了，你要特意写 `mut` 才能让变量可变。这个设计是故意的——它逼你思考"这个变量真的需要改变吗"。

第三，`println!` 后面有个感叹号，说明它是个**宏**，不是普通函数。暂时把它当成一个特殊的打印函数就好。

---

### 环境搭建

学 Rust 最标准的方式是用 **rustup**，它是 Rust 的工具链管理器（类似 C 里的 gcc 安装工具）。

在终端里运行：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

安装完成后，你会得到三个主要工具：`rustc`（编译器）、`cargo`（包管理器 + 构建工具）、`rustfmt`（代码格式化）。

实际上你很少直接用 `rustc`，大多数时候用 `cargo`：

```bash
cargo new hello_rust    # 创建新项目
cd hello_rust
cargo run               # 编译并运行
cargo build             # 只编译
```

---

### 本节小结与思考

这一节你需要带走的核心概念只有一个：**Rust 的内存安全不靠运行时，靠编译器的规则**。这个规则叫做**所有权系统**，是 Rust 最独特也最需要花时间理解的地方。

从下一节开始，我们就会一步步拆解这套规则——从最基础的变量、类型讲起，逐渐深入到所有权、借用、生命周期。

在继续之前，你可以先想一个问题：**C 里的这段代码有什么问题？**

```c
int* get_value() {
    int x = 42;
    return &x;  // 返回局部变量的地址
}
```

这是一个经典的悬空指针问题。下一节我们会看到，同样的代码在 Rust 里会发生什么——编译器会直接告诉你哪里错了，以及为什么。

## 第二节：变量、类型与不可变性

---

### 从 C 的变量观说起

在 C 里，你声明一个变量的时候，脑子里想的是"我在某个内存地址上放了一个值，类型决定了这块内存有多大"。这个底层直觉在 Rust 里完全适用，但 Rust 在上面加了一层**语义约束**：你不仅要告诉编译器这块内存有多大，还要告诉它**这块内存会不会被修改**。

---

### 不可变变量：`let`

Rust 用 `let` 声明变量，默认是**不可变的**：

```rust
fn main() {
    let x = 5;
    x = 6; // 编译错误！cannot assign twice to immutable variable
}
```

如果你来自 C，这会让你有点不适应。C 里默认一切都可以改，你要特意写 `const` 才能锁定。Rust 把这个默认值翻转了——这是一个深思熟虑的设计。

**为什么这样设计？** 因为大多数变量在实际程序里根本不需要改变。强迫你显式声明"我需要这个变量可变"，相当于在代码里留下了一个标记：_这里的状态会发生变化，请多加注意_。这对代码可读性和并发安全都有好处。

如果你确实需要修改变量，加上 `mut`：

```rust
fn main() {
    let mut count = 0;
    count = count + 1; // OK
    println!("{}", count); // 输出 1
}
```

---

### 常量：`const`

Rust 也有 `const`，但它和 `let` 有本质区别。`const` 是**真正的编译期常量**，必须在编译时就能确定值，而且必须显式标注类型：

```rust
const MAX_POINTS: u32 = 100_000; // 注意：用下划线分隔数字，增强可读性
```

和 C 的 `#define` 不同，`const` 是有类型的，编译器会做类型检查。和 C 的 `const` 也不同——C 的 `const` 变量本质上还是一块内存，只是不让你写；Rust 的 `const` 会被编译器直接内联展开，更接近 C 的 `#define`，但更安全。

---

### Shadowing：变量遮蔽

这是 Rust 里一个 C 没有的特性，初学者容易感到困惑，但其实非常实用。你可以用 `let` **重新声明同名变量**，新的声明会"遮蔽"旧的：

```rust
fn main() {
    let x = 5;
    let x = x + 1; // 新的 x 遮蔽了旧的 x，值为 6
    let x = x * 2; // 再次遮蔽，值为 12
    println!("{}", x); // 输出 12
}
```

你可能会问：这和 `mut` 有什么区别？区别有两点。第一，每次 `let` 都创建了一个**新变量**，旧变量并没有被修改；第二，遮蔽允许你**改变类型**：

```rust
fn main() {
    let spaces = "   ";        // 这是一个字符串类型
    let spaces = spaces.len(); // 这是一个整数类型，OK！

    // 如果用 mut 就不行：
    // let mut spaces = "   ";
    // spaces = spaces.len(); // 编译错误！类型不匹配
}
```

遮蔽常用于"对一个值做变换，然后用同一个名字引用新值"的场景，避免你写出 `spaces_str`、`spaces_len` 这样冗余的名字。

---

### 基本数据类型

Rust 是**静态强类型语言**，每个值都有一个确定的类型。很多时候编译器可以自动推断，但在必要时你需要显式标注。来看看基本类型，你会发现和 C 非常相似。

**整数类型**是最常用的。Rust 的整数类型名字很规律：`i` 前缀表示有符号，`u` 前缀表示无符号，后面的数字是位宽。比如 `i32` 就是 32 位有符号整数，对应 C 的 `int32_t`；`u8` 是 8 位无符号整数，对应 C 的 `uint8_t`。此外还有 `i64`、`u64`、`i128`、`u128`，以及 `isize`/`usize`——后者的宽度取决于平台（32 位系统就是 32 位，64 位系统就是 64 位），对应 C 的 `ptrdiff_t` 和 `size_t`。

**Rust 默认的整数类型是 `i32`**，这和 C 的 `int` 习惯一致。

```rust
let a: i32 = -100;
let b: u64 = 18_446_744_073_709_551_615; // u64 的最大值
let c = 42;       // 编译器推断为 i32
let d = 42u8;     // 用后缀指定类型为 u8
let e = 0xff;     // 十六进制
let f = 0b1010;   // 二进制
```

**浮点类型**只有两种：`f32`（单精度）和 `f64`（双精度）。默认是 `f64`，因为在现代 64 位 CPU 上，双精度的性能和单精度差不多，精度更高。

**布尔类型** `bool` 只有 `true` 和 `false` 两个值，占 1 字节。注意 Rust **没有** C 里"非零即真"的隐式转换，整数不能当布尔用。

**字符类型** `char` 在 Rust 里是 **4 字节的 Unicode 标量值**，不是 1 字节的 ASCII。这是和 C 的重要区别：`'A'` 和 `'中'` 都是合法的 `char`。

```rust
let heart: char = '❤';  // 完全合法
```

---

### 复合类型：元组与数组

C 里如果你想把几个值打包，你会用 `struct`。Rust 也有 `struct`，但它还提供两种更轻量的复合类型。

**元组（tuple）**可以把**不同类型**的值打包在一起，长度固定：

```rust
fn main() {
    let tup: (i32, f64, bool) = (500, 6.4, true);

    // 用点号加索引来访问元素
    println!("{}", tup.0); // 500
    println!("{}", tup.1); // 6.4

    // 也可以解构（destructuring），和 C 的结构体赋值有点像
    let (x, y, z) = tup;
    println!("{}", x); // 500
}
```

**数组（array）**和 C 的数组概念类似，元素**类型相同**，长度**固定**（在栈上分配），但 Rust 的数组会自动做**边界检查**：

```rust
fn main() {
    let arr: [i32; 5] = [1, 2, 3, 4, 5]; // 类型是 [i32; 5]，注意长度是类型的一部分

    println!("{}", arr[0]); // 1

    // 越界访问不会像 C 一样悄悄读到错误内存——Rust 会在运行时 panic（崩溃并给出清晰错误信息）
    // println!("{}", arr[10]); // 运行时 panic: index out of bounds

    // 快捷初始化：创建一个所有元素都是 0 的 5 元素数组
    let zeros = [0; 5]; // [0, 0, 0, 0, 0]
}
```

这里有一个重要的概念值得停下来想一想：Rust 数组的**长度是类型的一部分**。也就是说 `[i32; 5]` 和 `[i32; 6]` 是两个完全不同的类型，编译器不会让你把它们混用。这和 C 很不同——C 的数组名退化成指针之后长度信息就丢失了，这是 C 里无数 bug 的根源。

---

### 一个思考题

在结束这一节之前，思考一下这段代码：

```rust
fn main() {
    let x = 5;
    let x = x + 1;  // ①
    {
        let x = x * 2; // ②
        println!("内层 x = {}", x);
    }
    println!("外层 x = {}", x); // ③
}
```

`①②③` 处的 `x` 分别是什么值？`③` 处的 `x` 会是 `12` 吗？

答案是：内层输出 `12`，外层输出 `6`。`②` 处的遮蔽只在**花括号作用域**内有效，出了这个作用域，`x` 回到了 `6`。这和 C 的作用域规则完全一致，但 Rust 里每一层遮蔽都是一个真正的新变量，更加清晰。

---

### 本节小结

这一节的核心是 Rust 对变量的两个基本态度：**默认不可变**（用 `mut` 显式解锁），以及**类型系统比 C 更严格**（没有隐式类型转换，整数不能当布尔，数组长度是类型信息）。这些看起来是限制，但实际上每一条都对应 C 里真实存在的 bug 类型。

下一节我们进入 Rust 的核心心脏——**第三节：所有权（Ownership）**。这是 Rust 中最独特、最需要改变思维方式的部分，也是理解了之后会让你对内存管理有全新认识的概念。你在第一节末尾看到的那个悬空指针问题，下一节会完整地解释 Rust 如何从根本上杜绝它。
