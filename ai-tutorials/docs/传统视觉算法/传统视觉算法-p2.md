## 第三节：立体视觉基础——对极几何

上一节结尾我们留了一个悬念：单应矩阵在三维场景里会失效。这节课就是要彻底解释为什么，以及真正的解决方案是什么。

这一节数学稍多，但我会用大量几何直觉来帮你建立理解。你会发现，这里的数学并不是凭空冒出来的，而是对几个非常朴素的几何事实的精确描述。

---

### 从一个根本问题开始

先想一个问题：**一张普通的二维照片，为什么丢失了深度信息？**

相机成像的本质是一次**投影**——把三维世界"压扁"到二维平面上。这个过程中，沿着同一条光线的所有三维点，都会映射到图像上的同一个像素。

```
三维空间中的点 A、B、C 在同一条光线上
           ↓
它们在图像上落在同一个像素 p
           ↓
给你 p，你无法知道原来的点是 A、B 还是 C
```

这就是深度的"消失"。那么，怎么恢复深度？答案是**用第二台相机从另一个角度看**。两条光线的交点，就是三维空间中的真实位置。这就是立体视觉的根本原理，和人类双眼的工作方式完全一样。

---

### 对极几何的核心场景

设想两台相机，光心分别在 O1 和 O2。它们同时拍摄空间中的一个点 P。

现在，假设你只知道 P 在左相机图像上的投影点 p1，你能在右相机图像上缩小 P 的可能位置吗？

答案是**可以，而且可以从一整张图缩小到一条线**。

原因是这样的：P 一定在左相机光心 O1 和像素点 p1 连成的那条光线上。这条光线在三维空间里是确定的。把这条光线投影到右相机图像上，它会变成右图中的一条直线——这就是**对极线（Epipolar Line）**。

```
左图中的一个点  →  右图中的一条线
```

这个约束非常强大。做特征匹配时，原本需要在整张图上搜索对应点，有了对极约束，只需要沿一条线搜索，搜索空间从二维降到了一维。

---

### 三个关键概念

在进入数学之前，先把几个术语的几何含义搞清楚。

**基线（Baseline）**是两个相机光心 O1O2 的连线。这是立体视觉系统的"眼距"。

**极点（Epipole）**是基线与图像平面的交点。换句话说，就是一个相机的光心，投影到另一个相机图像上的位置。左图中的极点 e1 是 O2 在左图上的投影，右图中的极点 e2 是 O1 在右图上的投影。

**极线（Epipolar Line）**就是我们上面说的那条线。有一个关键性质：**所有极线都过极点**。这很直观——无论空间点 P 在哪里，连接 O1、P、p1 的平面（叫极平面）都包含基线，因此它与右图的交线（极线）总是过极点 e2。

---

### 基础矩阵 F：对极约束的代数表达

现在我们要把"对极线"这个几何关系，写成一个可以直接用于计算的代数方程。

设左图中某点的像素坐标为 p1=(u1,v1)，右图中对应点的坐标为 p2=(u2,v2)。对极约束说的是：**p2 必须在 p1 对应的极线上**。

这个约束可以写成一个极其简洁的形式：

p2TFp1=0

这里 F 是一个 3×3 的矩阵，叫做**基础矩阵（Fundamental Matrix）**。这个方程的几何意义是：给定左图点 p1，Fp1 就是右图中对应极线的方程（用齐次坐标表示的直线）；而 p2 在这条线上，所以点乘为零。

基础矩阵 F 完全由两相机的**相对位置和朝向**决定，与场景内容无关。它有以下性质：秩为2（不是满秩，因为对极约束本身有一个自由度），有7个自由度（3×3矩阵有9个元素，减去一个尺度因子，再减去秩为2的约束）。

给定足够多的匹配点对（至少7对，8点算法用8对），就可以从数据中估计出 F，而完全不需要知道相机参数。这就是 F 的强大之处——它是纯粹基于图像的。

---

### 本质矩阵 E：加入相机内参

基础矩阵描述的是**像素坐标**之间的关系。但像素坐标包含了相机的内部参数（焦距、主点偏移等），如果我们把这些内参"去掉"，用**归一化相机坐标**（即把三维点投影时不考虑内参，只除以深度）来描述对应关系，得到的就是**本质矩阵（Essential Matrix）E**。

两者的关系是：

E=K2TFK1

其中 K1、K2 是两个相机的内参矩阵（Camera Intrinsic Matrix）。内参矩阵长这样：

K=[fx0cx0fycy001]K=fx000fy0cxcy1

其中 fx,fyfx,fy 是像素单位的焦距，(cx,cy) 是主点（通常是图像中心）。

E 的对应约束方程形式和 F 一样，但作用于归一化坐标 p^p^：

p^2TEp^1=0

E 相比 F 更"干净"——它只编码了两相机之间的**旋转 R 和平移 t**，不掺杂内参的影响。具体来说：

E=[t]×R

其中[t]×是平移向量 t 的**反对称矩阵（叉积矩阵）**。如果你对这个符号陌生，可以把它理解为一种把"叉积运算"写成矩阵乘法的技巧。

E 有5个自由度（旋转3个，平移方向2个，深度尺度不可确定），因此理论上只需要5对点就能估计，这就是**五点算法（Five-Point Algorithm）**，它是现代视觉 SLAM 系统的标准工具。

---

### F 和 E 的区别，直觉总结

用一句话区分这两者：F 是"不知道相机参数时的工具"，E 是"知道相机参数时的工具"。知道内参的情况下，优先用 E，因为它的自由度更少，估计更稳定，而且可以直接分解出旋转和平移，对后续的三维重建至关重要。

---

### 从 E 中恢复 R 和 t

这是立体视觉的关键一步。已知 E，如何得到相机之间的相对旋转 R 和平移 t？

答案是对 E 做**奇异值分解（SVD）**。理论上 E 的两个奇异值相等（第三个为0），实际估计时会有噪声，但强制令 E 满足这个性质后，可以从 SVD 中提取出**四组 (R, t) 的候选解**。为什么有四组？因为翻转和镜像关系各贡献了一个歧义。

从四组候选解中找到正确答案的方法叫**手性检验（Cheirality Check）**：把一个匹配点对进行三角化，看三维点是否在两个相机的**前方**。正确的 (R, t) 会让大多数点落在两台相机前方，而错误的解则会让点跑到相机后面。

---

### 代码实战

```python
import cv2
import numpy as np

def estimate_fundamental_and_essential(img1, img2, K):
    """
    完整流程：ORB匹配 → 估计F → 估计E → 恢复R和t
    K: 相机内参矩阵 (3x3)
    """
    orb = cv2.ORB_create(nfeatures=2000)
    kp1, des1 = orb.detectAndCompute(img1, None)
    kp2, des2 = orb.detectAndCompute(img2, None)

    bf = cv2.BFMatcher(cv2.NORM_HAMMING)
    knn_matches = bf.knnMatch(des1, des2, k=2)
    good = [m for m, n in knn_matches if m.distance < 0.75 * n.distance]

    pts1 = np.float32([kp1[m.queryIdx].pt for m in good])
    pts2 = np.float32([kp2[m.trainIdx].pt for m in good])

    # 估计基础矩阵 F
    # cv2.FM_RANSAC 表示用RANSAC去除误匹配，1.0是重投影误差阈值
    F, mask_f = cv2.findFundamentalMat(pts1, pts2,
                                        cv2.FM_RANSAC,
                                        ransacReprojThreshold=1.0,
                                        confidence=0.99)

    # 只保留满足对极约束的内点
    inlier_pts1 = pts1[mask_f.ravel() == 1]
    inlier_pts2 = pts2[mask_f.ravel() == 1]

    print(f"基础矩阵估计，内点数: {inlier_pts1.shape[0]}/{len(good)}")
    print(f"验证对极约束（应接近0）: {verify_epipolar(F, inlier_pts1, inlier_pts2):.6f}")

    # 估计本质矩阵 E（需要内参 K）
    E, mask_e = cv2.findEssentialMat(inlier_pts1, inlier_pts2,
                                      K,
                                      method=cv2.RANSAC,
                                      prob=0.99,
                                      threshold=1.0)

    # 从 E 中恢复 R 和 t（内部做SVD分解和手性检验）
    # retval 是通过手性检验的内点数量
    retval, R, t, mask_pose = cv2.recoverPose(E, inlier_pts1, inlier_pts2, K)

    print(f"\n相机旋转矩阵 R:\n{R}")
    print(f"\n相机平移方向 t (单位向量):\n{t.ravel()}")
    print(f"\n注意: t 只有方向，没有尺度（单目相机的固有局限）")

    return F, E, R, t, inlier_pts1, inlier_pts2

def verify_epipolar(F, pts1, pts2):
    """
    验证对极约束 p2^T F p1 = 0
    返回所有点对的平均绝对值（越接近0说明F越准确）
    """
    errors = []
    for p1, p2 in zip(pts1, pts2):
        # 转换为齐次坐标（加上第三维1）
        x1 = np.array([p1[0], p1[1], 1.0])
        x2 = np.array([p2[0], p2[1], 1.0])
        # 计算 p2^T F p1
        error = abs(x2 @ F @ x1)
        errors.append(error)
    return np.mean(errors)

def draw_epipolar_lines(img1, img2, pts1, pts2, F, n=10):
    """
    可视化对极线：在右图中画出左图各点对应的极线
    如果F正确，右图中的每个匹配点都应该精确地落在对应的极线上
    """
    img1_color = cv2.cvtColor(img1, cv2.COLOR_GRAY2BGR)
    img2_color = cv2.cvtColor(img2, cv2.COLOR_GRAY2BGR)

    # 随机选 n 个点来可视化，避免太乱
    indices = np.random.choice(len(pts1), min(n, len(pts1)), replace=False)

    for i in indices:
        # 生成随机颜色，方便区分不同点对
        color = tuple(np.random.randint(0, 255, 3).tolist())

        # 在左图画出对应点（圆圈）
        p1 = tuple(pts1[i].astype(int))
        cv2.circle(img1_color, p1, 5, color, -1)

        # 计算右图中的极线：l = F @ p1（齐次坐标）
        p1_h = np.array([pts1[i][0], pts1[i][1], 1.0])
        line = F @ p1_h  # line = [a, b, c]，表示直线 ax + by + c = 0

        # 极线是无限长的，我们截取图像宽度范围内的部分来画
        h, w = img2.shape[:2]
        # 令 x=0 和 x=w-1，解出对应的 y
        x0, y0 = 0, int(-line[2] / line[1]) if abs(line[1]) > 1e-6 else 0
        x1_, y1 = w - 1, int(-(line[2] + line[0] * (w-1)) / line[1]) if abs(line[1]) > 1e-6 else 0

        cv2.line(img2_color, (x0, y0), (x1_, y1), color, 1)

        # 在右图画出对应点（应该精确地落在极线上）
        p2 = tuple(pts2[i].astype(int))
        cv2.circle(img2_color, p2, 5, color, -1)

    return img1_color, img2_color
```

### 单目相机的尺度不确定性

有一件事你必须心里清楚：从本质矩阵 E 恢复出的平移 t，**只有方向，没有绝对长度**。

这不是算法的缺陷，而是单目相机的**数学本质**——如果你把整个场景放大两倍，同时把相机移动距离也放大两倍，拍出来的两张图完全一样。你无法从纯图像中区分这两种情况。

这个问题叫做**尺度不确定性（Scale Ambiguity）**，解决方案有以下几种思路。使用双目相机（已知基线长度）是最直接的方案；或者在场景中放置已知尺寸的参照物；再或者融合 IMU（惯性测量单元），从加速度计获取绝对尺度。这也是为什么高精度的视觉里程计系统通常是视觉+IMU的组合（VIO）。

---

### 本节小结

这一节建立了立体视觉的数学基础。核心思路是一个从直觉到代数的推导过程：两台相机看同一个点 → 三者构成一个极平面 → 对应点必须在极线上 → 这个约束用矩阵 F 或 E 来编码 → 从 E 中分解出相机的相对运动 (R,t)。

理解了这些，你就掌握了几乎所有视觉 SLAM 系统的几何核心。

留两个思考题。**第一**：我们说单应矩阵 H 适用于平面场景，基础矩阵 F 适用于一般三维场景——那如果场景确实是平面的，用 F 会出什么问题？（提示：想想自由度）。**第二**：为什么估计 E 比估计 F 需要更少的点对（5对 vs 7/8对）？这背后的直觉是什么？

下一节我们进入**立体匹配与深度估计**——在已知两相机精确相对位置的前提下，如何为图像中的每一个像素都计算出深度，生成稠密的**视差图**和**深度图**。

## 第四节：立体匹配与深度估计

上一节我们解决了"两台相机之间的几何关系是什么"这个问题，拿到了旋转矩阵 R 和平移向量 t。这一节我们要往前走一步，回答一个更实用的问题：**怎么用两张图，为每个像素都算出一个深度值，生成一张完整的深度图？**

这个过程叫做**立体匹配（Stereo Matching）**，是自动驾驶、机器人避障、三维重建的核心模块之一。

---

### 从对极几何到视差：一个关键简化

上一节里，极线可以是任意方向的斜线，搜索对应点时需要沿着这条斜线走。这在计算上并不方便。工程中有一个标准做法叫做**图像整流（Image Rectification）**，它通过对两张图做单应变换，使得：

**所有极线都变成水平的，而且在两张图中处于同一行。**

整流之后的效果如下图所示。左图中某一行的点，在右图中的对应点一定在**同一行**，而且一定在**对应点的左侧**（假设左相机在左边）。

```
左图第 i 行的点 p_left = (u, i)
对应的右图点   p_right = (u - d, i)   ← 同一行，向左偏移了 d 个像素
```

这个偏移量 `d` 就叫做**视差（Disparity）**。视差越大，说明这个点离相机越近；视差越小，说明越远。

视差和深度的关系可以从相似三角形推导出来，结果非常简洁：

Z=f⋅BdZ=df⋅B

其中 Z 是深度，f 是焦距（像素单位），B 是基线长度（两相机光心距离，物理单位），d 是视差（像素单位）。这个公式值得记住，它是立体视觉的核心公式。注意深度和视差成**反比**——这意味着近处的深度分辨率高，远处的分辨率低，这和人类眼睛的感知完全一致。

---

### 立体匹配的核心问题：代价计算

整流之后，立体匹配变成了一个看似简单的问题：对于左图每个像素 (u,v)，在右图**同一行**搜索视差范围 [0,Dmax] 内的最佳匹配点，找到视差 d，就得到深度。

但"最佳匹配"怎么定义？这就引出了**匹配代价（Matching Cost）**的概念。最常见的两种是 SAD 和 SSD。

**SAD（Sum of Absolute Differences）**是在以两个候选像素为中心的小窗口内，逐像素计算灰度差的绝对值之和。窗口越相似，SAD 越小，匹配越好。

SAD(u,v,d)=∑(x,y)∈W∣IL(u+x,v+y)−IR(u−d+x,v+y)∣SAD(u,v,d)=(x,y)∈W∑∣IL(u+x,v+y)−IR(u−d+x,v+y)∣

**SSD（Sum of Squared Differences）**把绝对值换成了平方，对大误差更敏感，噪声鲁棒性稍弱但理论性质更好。

这两种方法都有一个关键参数：**窗口大小**。窗口太小，匹配不稳定（信息太少，噪声影响大）；窗口太大，边缘处的视差会被模糊（相当于在深度不连续处做了平均）。这是一个经典的偏差-方差权衡，在实际使用中需要根据场景调节。

---

### BM 算法：块匹配的工程实现

OpenCV 中最简单的立体匹配算法是 **StereoBM（Block Matching）**，它的核心就是上面描述的滑窗 SAD 匹配，加上一些工程优化。

理解 BM 的局限性和它工作良好的条件，比记住它的参数更重要。BM 在**纹理丰富的区域**效果好——因为纹理提供了独特的外观，方便匹配；在**均匀区域**（比如白墙、天空）效果很差——因为没有纹理，到处都"看起来一样"，匹配完全随机。此外，**深度不连续的边缘区域**（前景物体的轮廓附近）也是 BM 的噩梦，因为左图窗口里同时包含了两个深度层的像素，造成匹配混乱。

```python
import cv2
import numpy as np
import matplotlib.pyplot as plt

def compute_disparity_bm(img_left, img_right):
    """
    使用 StereoBM 计算视差图
    两张图必须已经经过整流（或本身就是标准双目相机的输出）
    """
    # 转为灰度图（BM只接受灰度）
    if len(img_left.shape) == 3:
        gray_left  = cv2.cvtColor(img_left,  cv2.COLOR_BGR2GRAY)
        gray_right = cv2.cvtColor(img_right, cv2.COLOR_BGR2GRAY)
    else:
        gray_left, gray_right = img_left, img_right

    # numDisparities: 搜索的视差范围，必须是16的倍数
    # 这个值决定了能感知的最近距离：越大越近，但计算越慢
    # blockSize: 匹配窗口大小，必须是奇数，范围5~255
    bm = cv2.StereoBM_create(numDisparities=64, blockSize=15)

    # 额外参数调节（可选，但对质量影响很大）
    bm.setPreFilterType(cv2.STEREO_BM_PREFILTER_XSOBEL)  # 预处理：提取边缘增强纹理
    bm.setPreFilterSize(9)
    bm.setPreFilterCap(31)
    bm.setTextureThreshold(10)    # 纹理阈值：低于此值的区域不计算视差（设为无效）
    bm.setUniquenessRatio(15)     # 唯一性比率：最优视差必须比次优视差好多少%

    # 计算视差图（结果乘以16，需要除以16得到实际视差值）
    disparity_raw = bm.compute(gray_left, gray_right)
    disparity = disparity_raw.astype(np.float32) / 16.0

    # 无效区域（值为-1）置为0
    disparity[disparity < 0] = 0

    return disparity
```

### SGBM 算法：半全局匹配

BM 的根本问题是它**每个像素独立决策**——它只看一个小窗口，完全不管邻居的视差是否合理。这导致结果噪声很大，尤其是在纹理稀少的区域。

**SGBM（Semi-Global Block Matching）**引入了一个关键改进：**视差的平滑性约束**。真实世界里，相邻像素的视差通常是连续变化的（除了深度不连续的边缘）。SGBM 把这个先验知识编码进了一个能量函数：

E(D)=∑p[C(p,Dp)+∑q∈NpP1⋅[∣Dp−Dq∣=1]+∑q∈NpP2⋅[∣Dp−Dq∣>1]]E(D)=p∑C(p,Dp)+q∈Np∑P1⋅[∣Dp−Dq∣=1]+q∈Np∑P2⋅[∣Dp−Dq∣>1]

这个公式的三项分别代表不同的惩罚。第一项 C(p,Dp) 是像素 p 选择视差 Dp 时的匹配代价（就是前面的 SAD/SSD）。第二项是对**小视差跳变**（±1像素）施加一个较小的惩罚 P1，允许视差有轻微变化。第三项是对**大视差跳变**（超过1像素）施加一个较大的惩罚 P2，强烈抑制视差的突变。

最小化这个能量函数就能同时满足"局部匹配好"和"全局平滑"两个目标。完全最优化这个能量是 NP-hard 的（二维 MRF 优化），SGBM 的聪明之处在于它用**多方向的一维动态规划**来近似——从8个方向（上下左右+四个对角线）分别做动态规划，然后把代价累加，得到一个近似但质量很高的解。这就是"Semi-Global"（半全局）这个名字的来源。

```python
def compute_disparity_sgbm(img_left, img_right):
    """
    使用 SGBM 计算高质量视差图
    SGBM 支持彩色图像输入
    """
    if len(img_left.shape) == 3:
        channels = img_left.shape[2]
    else:
        channels = 1

    window_size = 5

    # P1 和 P2 是平滑性惩罚参数，是 SGBM 最关键的两个参数
    # 通常 P1 = 8 * channels * window_size^2
    #      P2 = 32 * channels * window_size^2
    # P2 必须 > P1，两者之差控制视差变化的"允许速率"
    P1 = 8  * channels * window_size ** 2
    P2 = 32 * channels * window_size ** 2

    sgbm = cv2.StereoSGBM_create(
        minDisparity=0,
        numDisparities=128,   # 最大搜索视差，128意味着最大深度缩减到基线的约128/f倍
        blockSize=window_size,
        P1=P1,
        P2=P2,
        disp12MaxDiff=1,      # 左右一致性检验的最大允许差异（像素）
        uniquenessRatio=10,   # 唯一性比率，和BM的含义相同
        speckleWindowSize=100, # 噪声斑点过滤：小于100像素的连通区域视为噪声
        speckleRange=32,      # 同一连通区域内视差变化的最大允许范围
        mode=cv2.STEREO_SGBM_MODE_SGBM_3WAY  # 3方向近似，速度和质量的折中
    )

    disparity_raw = sgbm.compute(img_left, img_right)
    disparity = disparity_raw.astype(np.float32) / 16.0
    disparity[disparity < 0] = 0

    return disparity
```

### 从视差图到三维点云

有了视差图，结合相机内参和基线，就可以把每个像素"反投影"回三维空间，得到**点云（Point Cloud）**。

```python
def disparity_to_pointcloud(disparity, Q, img_color=None):
    """
    将视差图转换为三维点云
    Q 是重投影矩阵，由 cv2.stereoRectify() 输出
    Q 编码了焦距、基线、主点等所有信息
    """
    # reprojectImageTo3D 将每个像素的视差值转换为 (X, Y, Z) 三维坐标
    # Q 矩阵的作用：
    #   X = (u - cx) * Z / fx
    #   Y = (v - cy) * Z / fy
    #   Z = f * B / d  （就是我们之前的公式）
    points_3d = cv2.reprojectImageTo3D(disparity, Q)

    # 过滤掉无效点（视差为0的点，对应无穷远或无效区域）
    mask_valid = disparity > 0.1

    points = points_3d[mask_valid]

    if img_color is not None:
        # 给点云附上颜色信息，方便可视化
        colors = img_color[mask_valid]
        return points, colors

    return points, None

def depth_from_disparity(disparity, focal_length, baseline):
    """
    直接用公式 Z = f*B/d 计算深度图
    比 reprojectImageTo3D 更直观，适合理解原理
    """
    # 避免除以零
    depth = np.zeros_like(disparity)
    valid = disparity > 0.1
    depth[valid] = (focal_length * baseline) / disparity[valid]
    return depth
```

### 左右一致性检验：发现不可靠的视差

有一个非常实用的后处理技巧叫做**左右一致性检验（Left-Right Consistency Check）**，可以自动标记出不可靠的视差点。

思路很简单：先用左图为参考计算一遍视差图 DL，再用右图为参考计算一遍视差图 DR。理论上，如果点 p 在 DL 中的视差是 d，那么右图中坐标 (u−d,v) 的视差 DR(u−d,v) 也应该大约等于 d。如果两者差别超过阈值（通常是1像素），说明这个点的视差不可靠，很可能是遮挡区域或纹理缺失区域。

```python
def left_right_consistency_check(disp_left, disp_right, threshold=1.0):
    """
    左右一致性检验，返回可靠视差的掩膜
    遮挡区域（只在一侧可见的点）会被标记为无效
    """
    h, w = disp_left.shape
    mask_valid = np.zeros((h, w), dtype=bool)

    for v in range(h):
        for u in range(w):
            d = int(disp_left[v, u])
            if d <= 0:
                continue
            u_right = u - d
            if 0 <= u_right < w:
                # 检验左右视差是否一致
                if abs(disp_left[v, u] - disp_right[v, u_right]) <= threshold:
                    mask_valid[v, u] = True

    return mask_valid
    # 注意：上面的循环用于演示原理，实际使用中应向量化以提速
    # OpenCV 的 StereoSGBM 通过 disp12MaxDiff 参数内置了这个检验
```

### 完整流程总结

把这一节的内容串成一条完整的流水线，从标定好的双目相机到深度图，步骤是这样的。

首先，用 `cv2.stereoCalibrate()` 标定双目相机，得到两个相机的内参 K1,K2 和它们的相对位姿 R,tR,t。然后，用 `cv2.stereoRectify()` 计算整流变换矩阵和重投影矩阵 Q。接着，用 `cv2.remap()` 对两张图做整流，使极线水平对齐。之后，用 SGBM 计算视差图。最后，用 Z=fB/d 或 `reprojectImageTo3D` 转换为深度图或点云。

### 本节小结

这一节我们完成了从"理解两相机关系"到"生成稠密深度图"的跨越。核心公式 Z=fB/d 是整节课的精华——深度反比于视差，基线越长，深度分辨率越高（但同时遮挡问题也越严重，这是立体视觉永恒的权衡）。BM 和 SGBM 的本质区别在于有没有引入空间平滑性约束，SGBM 用半全局动态规划在速度和质量之间找到了一个工程上的甜点。

留两个思考题。**第一**：根据公式 Z=fB/d，如果视差的测量误差是 ±1 个像素，那么深度误差是多少？它和距离 Z 的关系是什么？（这道题非常重要，它解释了为什么激光雷达在远距离比立体相机更精确）。**第二**：SGBM 的参数 P2 应该是个固定值，还是根据图像梯度自适应变化？在深度不连续的边缘处，你希望 P2 是大还是小？

下一节我们转向一个全新的话题——**光流**。我们不再假设相机是静止的，而是要追踪场景中每个像素在时间上的运动，这是视频分析和运动估计的基础。
