## 第五节：光流基础——Lucas-Kanade 算法

前四节我们一直在处理**两张静态图片之间**的关系。从这节开始，我们引入时间维度，开始处理**视频序列**——图像不再是孤立的两张，而是连续的帧流。

光流要回答的问题是：**图像中每个像素，在下一帧里移动到哪里了？**

---

### 什么是光流

想象你盯着一段视频，视频里有一个运动的足球。你的眼睛会自然地追踪球的运动轨迹。光流做的事情和这完全一样——为图像中的每个像素，计算一个二维运动向量 (u,v)，表示这个像素在下一帧里向右移动了 u 个像素、向上移动了 v 个像素。

所有像素的运动向量合在一起，就形成一个**光流场（Optical Flow Field）**，它描述了整幅图像的运动模式。

光流有两大类用途。一是**运动分析**——从光流场里能看出哪些区域在运动、运动方向如何，可以用来做目标追踪、动作识别、视频分割。二是**相机运动估计**——如果场景是静止的，光流完全来自相机自身的运动，从中可以估计相机的平移和旋转，这就是**视觉里程计**的基础。

---

### 光流的基本假设：亮度恒定

所有光流算法都建立在一个核心假设上：

> **亮度恒定假设（Brightness Constancy Assumption）**：一个像素点在运动前后，灰度值保持不变。

用数学语言写出来：设像素在 t 时刻的位置是 (x,y)，经过时间 dt 后移动到 (x+dx,y+dy)，则：

I(x,y,t)=I(x+dx,y+dy,t+dt)

对右边做泰勒展开（保留一阶项）：

I(x+dx,y+dy,t+dt)≈I(x,y,t)+∂I∂xdx+∂I∂ydy+∂I∂tdtI(x+dx,y+dy,t+dt)≈I(x,y,t)+∂x∂Idx+∂y∂Idy+∂t∂Idt

代入亮度恒定假设，左右消去 I(x,y,t)：

∂I∂xdx+∂I∂ydy+∂I∂tdt=0∂x∂Idx+∂y∂Idy+∂t∂Idt=0

两边除以 dt，令 u=dx/dt，v=dy/dt：

Ix⋅u+Iy⋅v+It=0

这就是**光流方程**。其中 Ix,IyIx,Iy 是图像在空间上的梯度（可以用 Sobel 算子计算），It 是图像在时间上的梯度（即相邻两帧的像素差），u,vu,v 是我们要求的光流。

---

### 孔径问题：一个方程，两个未知数

光流方程是一个等式，但有 u 和 v 两个未知数。方程组欠定，有无穷多个解。

这个问题有一个很形象的名字叫**孔径问题（Aperture Problem）**。想象你通过一个小孔观察一条移动的边缘线。如果这条线是斜的，你只能看出它在垂直于自身方向上的运动分量，沿线方向的运动完全无法感知。你看到的"运动"，取决于你观察的窗口（孔径）有多大，以及窗口内的信息有多丰富。

```
一条斜线向右移动：
        /              /
       /    →→→       /
      /              /

通过小孔观察，你只能感知到垂直于线方向的移动分量
沿线方向的分量完全不可见
```

要解决这个问题，需要引入**额外的约束**。不同的光流算法，本质上是对这个额外约束的不同假设。Lucas-Kanade 算法用的是**局部一致性假设**。

---

### Lucas-Kanade 算法：局部窗口内的最小二乘

Lucas-Kanade（LK）算法的额外假设非常直观：

> **局部一致性假设**：在一个小窗口内（比如 5×5 像素），所有像素的光流向量 (u,v) 都相同。

这个假设在平滑区域是合理的——相邻像素属于同一个物体，运动当然一样。

这样，一个 5×5=25 个像素的窗口，就给出了 25 个光流方程，而未知数还是 2 个 (u,v)。方程组超定了，用最小二乘法求解：

[∑Ix2∑IxIy∑IxIy∑Iy2][uv]=−[∑IxIt∑IyIt]

左边的 2×2 矩阵 M 非常眼熟——它就是 Harris 角点检测里的**结构张量（Structure Tensor）**！这不是巧合：LK 算法在 M 的两个特征值都很大的地方才能可靠工作，而这正好对应了 Harris 角点的条件。这就是为什么**LK 光流通常只用于追踪角点，而不是所有像素**——角点在各个方向都有梯度变化，能提供完整的约束，唯一确定 (u,v)。

求解这个方程组，就得到了窗口中心像素的光流 (u,v)。

---

### 金字塔 LK：处理大位移

LK 算法有一个固有限制：泰勒展开只在位移很小（远小于1像素）时精确，实际中假设位移在几个像素以内比较合理。如果物体移动很快（比如一帧跨越了20个像素），LK 就会失效。

解决方案同样是**图像金字塔**。先在最粗的尺度（图像缩小多倍后）计算一个粗略的光流，然后把这个结果作为初始值，在下一层更精细的图像上继续迭代求精，一层一层往下，最终在原始分辨率上得到精确结果。

在最粗层，大位移被缩小成了小位移，正好在 LK 的有效范围内。这就是**金字塔 Lucas-Kanade**，也是 OpenCV 中 `calcOpticalFlowPyrLK` 实现的算法。

---

### 代码实战

```python
import cv2
import numpy as np
import matplotlib.pyplot as plt

def lucas_kanade_tracking(video_path=None, use_camera=False):
    """
    金字塔 LK 光流追踪：在视频中追踪角点的运动轨迹
    """
    # 打开视频或摄像头
    if use_camera:
        cap = cv2.VideoCapture(0)
    else:
        cap = cv2.VideoCapture(video_path)

    # ShiTomasi 角点检测参数（比 Harris 更稳定，是 LK 追踪的标准前端）
    shi_tomasi_params = dict(
        maxCorners=200,      # 最多追踪200个角点
        qualityLevel=0.01,   # 角点质量阈值（最强角点响应的1%以上才保留）
        minDistance=10,      # 角点之间的最小距离（像素），避免过于密集
        blockSize=7          # 计算角点时的窗口大小
    )

    # LK 光流参数
    lk_params = dict(
        winSize=(21, 21),    # 局部一致性窗口大小，越大越稳定但对运动边界越模糊
        maxLevel=3,          # 金字塔层数，层数越多能处理的最大位移越大
        criteria=(           # 迭代终止条件：最大迭代次数 OR 收敛精度
            cv2.TERM_CRITERIA_EPS | cv2.TERM_CRITERIA_COUNT,
            30,    # 最大迭代次数
            0.01   # 收敛精度（像素）
        )

    # 读取第一帧，检测初始角点
    ret, first_frame = cap.read()
    prev_gray = cv2.cvtColor(first_frame, cv2.COLOR_BGR2GRAY)

    # goodFeaturesToTrack 是 ShiTomasi 角点检测的 OpenCV 接口
    prev_points = cv2.goodFeaturesToTrack(prev_gray, mask=None, **shi_tomasi_params)

    # 用于画轨迹的画布（累积每帧的运动轨迹）
    trajectory_mask = np.zeros_like(first_frame)

    # 给每个追踪点分配一个固定颜色，方便区分
    colors = np.random.randint(0, 255, (200, 3))

    frame_count = 0

    while True:
        ret, frame = cap.read()
        if not ret:
            break

        curr_gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)

        # 核心：计算 LK 光流
        # prev_points: 上一帧的角点坐标
        # curr_points: 这些角点在当前帧的预测位置（输出）
        # status: 每个点是否追踪成功（1=成功，0=失败）
        # error: 每个点的追踪误差（越小越好）
        curr_points, status, error = cv2.calcOpticalFlowPyrLK(
            prev_gray, curr_gray, prev_points, None, **lk_params
        )

        # 只保留追踪成功的点
        if curr_points is not None:
            good_curr = curr_points[status == 1]
            good_prev = prev_points[status == 1]
        else:
            break

        # 画出每个点的运动轨迹和当前位置
        for i, (curr, prev) in enumerate(zip(good_curr, good_prev)):
            a, b = curr.ravel().astype(int)   # 当前位置
            c, d = prev.ravel().astype(int)   # 上一帧位置

            color = colors[i % len(colors)].tolist()

            # 在轨迹画布上画线（保留历史轨迹）
            trajectory_mask = cv2.line(trajectory_mask, (a, b), (c, d), color, 2)
            # 在当前帧画点
            frame = cv2.circle(frame, (a, b), 4, color, -1)

        # 把轨迹叠加到当前帧
        output = cv2.add(frame, trajectory_mask)

        # 计算光流统计信息
        if len(good_curr) > 0:
            flow_vectors = good_curr - good_prev
            mean_magnitude = np.mean(np.linalg.norm(flow_vectors, axis=1))
            cv2.putText(output, f"Tracking: {len(good_curr)} pts | "
                               f"Mean flow: {mean_magnitude:.1f}px",
                        (10, 30), cv2.FONT_HERSHEY_SIMPLEX, 0.7, (255,255,255), 2)

        cv2.imshow('LK Optical Flow Tracking', output)

        # 更新：当前帧变成下一次的上一帧
        prev_gray = curr_gray.copy()
        prev_points = good_curr.reshape(-1, 1, 2)

        frame_count += 1

        # 每隔50帧重新检测角点（因为追踪点会因遮挡或出界而减少）
        if frame_count % 50 == 0 or len(good_curr) < 20:
            prev_points = cv2.goodFeaturesToTrack(prev_gray, mask=None,
                                                   **shi_tomasi_params)
            trajectory_mask = np.zeros_like(first_frame)  # 清空轨迹
            frame_count = 0

        if cv2.waitKey(30) & 0xFF == ord('q'):
            break

    cap.release()
    cv2.destroyAllWindows()

def visualize_flow_vectors(img1, img2, step=16):
    """
    在两帧之间计算稀疏光流并可视化为箭头场
    step: 每隔多少像素采样一个点
    """
    gray1 = cv2.cvtColor(img1, cv2.COLOR_BGR2GRAY)
    gray2 = cv2.cvtColor(img2, cv2.COLOR_BGR2GRAY)

    h, w = gray1.shape

    # 在网格上均匀采样点
    y_coords, x_coords = np.mgrid[step//2:h:step, step//2:w:step]
    points = np.float32(np.stack([x_coords.ravel(), y_coords.ravel()], axis=1))
    points = points.reshape(-1, 1, 2)

    # 计算这些网格点的光流
    lk_params = dict(winSize=(21,21), maxLevel=3,
                     criteria=(cv2.TERM_CRITERIA_EPS | cv2.TERM_CRITERIA_COUNT, 30, 0.01))
    new_points, status, _ = cv2.calcOpticalFlowPyrLK(gray1, gray2, points, None, **lk_params)

    # 画箭头
    result = img1.copy()
    for i, (new, old) in enumerate(zip(new_points, points)):
        if status[i] == 0:
            continue
        x_old, y_old = old.ravel().astype(int)
        x_new, y_new = new.ravel().astype(int)

        # 计算位移大小，用来决定颜色（大位移=红色，小位移=蓝色）
        magnitude = np.sqrt((x_new-x_old)**2 + (y_new-y_old)**2)
        color_intensity = min(int(magnitude * 20), 255)
        color = (0, 255 - color_intensity, color_intensity)  # 蓝→红

        if magnitude > 0.5:  # 过滤掉几乎不动的点
            cv2.arrowedLine(result,
                           (x_old, y_old), (x_new, y_new),
                           color, 1, tipLength=0.4)

    return result
```

---

### LK 算法的假设与局限

理解算法的局限和理解算法本身同样重要。LK 建立在三个假设上，每个假设在某些场景下都会失效。

**亮度恒定假设**在光照变化时失效，比如有闪光灯、快速曝光变化、强烈的镜面反射区域。**局部一致性假设**在运动边界处失效——运动边界两侧属于不同物体，光流不连续，但 LK 的窗口跨越了边界，强行求一个"折中"的光流，导致边界位置的光流不准确。**小位移假设**在快速运动时失效，即使用了金字塔也有上限——如果物体在两帧之间跨越的距离超过了最粗层图像的几个像素，就彻底追踪不上了。

针对这些局限，工程上的常见应对策略是：提高帧率（让帧间位移更小）；在光照变化时重新初始化追踪点；追踪失败的点（status=0）及时丢弃并补充新的角点。

---

### 本节小结

这一节的核心是从光流方程的推导到 LK 算法的建立。整个逻辑链是：亮度恒定假设 → 光流方程（一个等式两个未知数）→ 孔径问题（欠定）→ 局部一致性假设（在窗口内建立超定方程组）→ 最小二乘求解 → 金字塔处理大位移。

一个值得反复回味的联系：LK 的结构张量和 Harris 角点检测的矩阵是同一个东西。这不是巧合，而是说明"容易追踪的点"和"好的角点"本质上是同一回事——在各个方向都有显著梯度变化的点。

留两个思考题。**第一**：如果场景完全静止但相机在平移，光流场会呈现什么样的模式？如果相机在旋转呢？（思考这个问题有助于理解第七节的视觉里程计）。**第二**：LK 算法能追踪的角点数量受什么限制？如果你想同时追踪10000个点，有什么办法提速？

下一节我们讲**稠密光流（Dense Optical Flow）**——不再只追踪稀疏的角点，而是为图像中**每一个像素**都计算一个光流向量，得到完整的运动场。这带来了全新的应用场景，也带来了更大的计算挑战。

## 第六节：稠密光流与运动分析——Farneback 算法

上一节的 LK 算法是**稀疏光流**——只追踪几百个精心挑选的角点。这一节我们要做的事情更彻底：**为图像中的每一个像素都计算光流向量**，得到一张和原图等大的"运动图"。

这就是**稠密光流（Dense Optical Flow）**。

---

### 为什么需要稠密光流

稀疏光流的问题在于，它只知道角点的运动，对于大片均匀区域（比如一个人的背部、一辆车的车身）完全没有信息。很多应用场景需要完整的运动场：

**视频压缩**：H.264 等视频编码标准的核心就是运动估计——用光流预测下一帧，只编码"预测误差"，大幅减少数据量。**动作识别**：判断一个人在做什么动作，需要分析全身每个部位的运动，稀疏角点不够用。**视频插帧**：在两帧之间插入一帧，需要知道每个像素的运动方向，才能合成自然的中间帧。**背景分离**：把运动的前景物体从静止背景中分离出来。

---

### Farneback 算法的核心思想

OpenCV 内置的稠密光流算法是 **Gunnar Farneback 在2003年提出的方法**。它的思路和 LK 截然不同，不是从"亮度恒定方程"出发，而是从**多项式展开**出发。

#### 第一步：用二次多项式近似图像

Farneback 的基本思路是：与其直接比较像素灰度值，不如先把图像的局部区域用一个**二次多项式**来近似描述：

I(x)≈xTAx+bTx+c

其中 x=(x,y) 是局部坐标，A 是一个 2×2 的对称矩阵（描述局部曲率），b 是一个二维向量（描述局部梯度），c 是常数项（描述局部均值）。

这三组系数 (A,b,c) 完整地描述了一个局部邻域的"形状"。通过加权最小二乘拟合（用高斯权重，越靠近中心权重越大），可以在每个像素处估计出这些系数。

#### 第二步：用多项式变换推导光流

假设第一帧在像素 x 处的多项式是：

I1(x)≈xTA1x+b1Tx+c1

第二帧在**发生了位移 d** 之后的同一个物理点，对应的多项式变成了：

I2(x)≈(x−d)TA2(x−d)+b2T(x−d)+c2

把括号展开，然后假设两帧的曲率矩阵相似（A1≈A2=A），比较两个多项式的线性系数，可以推导出：

d=−12A−1(b2−b1)d=−21A−1(b2−b1)

这就是 Farneback 算法的核心公式。注意它的优雅之处：光流 d 直接由两帧的多项式系数之差决定，没有迭代，没有搜索，是一个**解析解**。

#### 第三步：迭代精化

和 LK 一样，Farneback 也用金字塔来处理大位移，并通过多次迭代来精化结果。每次迭代时，把上一次的光流估计作为"初始偏移"，在此基础上继续求解残余位移，逐步逼近真实光流。

---

### 代码实战

```python
import cv2
import numpy as np
import matplotlib.pyplot as plt

def compute_dense_flow(img1, img2):
    """
    用 Farneback 算法计算稠密光流
    返回光流场 flow，shape 为 (H, W, 2)
    flow[:,:,0] 是 x 方向位移，flow[:,:,1] 是 y 方向位移
    """
    gray1 = cv2.cvtColor(img1, cv2.COLOR_BGR2GRAY)
    gray2 = cv2.cvtColor(img2, cv2.COLOR_BGR2GRAY)

    flow = cv2.calcOpticalFlowFarneback(
        gray1, gray2,
        flow=None,        # 初始光流估计，None表示从零开始
        pyr_scale=0.5,    # 金字塔缩放比例，0.5表示每层缩小一半
        levels=3,         # 金字塔层数，越多能处理的最大位移越大
        winsize=15,       # 多项式拟合的邻域窗口大小，越大越平滑但边缘越模糊
        iterations=3,     # 每层金字塔的迭代次数
        poly_n=5,         # 多项式展开的邻域半径（像素），通常5或7
        poly_sigma=1.2,   # 多项式拟合时高斯权重的标准差
        flags=0
    )

    return flow

def flow_to_hsv_visualization(flow):
    """
    把光流场转换为 HSV 彩色图像可视化
    这是稠密光流最经典的可视化方式：
    - 色调（Hue）    → 运动方向（角度）
    - 饱和度（Sat） → 固定为255（全饱和，颜色鲜艳）
    - 明度（Value）  → 运动速度（幅度），越亮越快
    """
    h, w = flow.shape[:2]
    hsv = np.zeros((h, w, 3), dtype=np.uint8)
    hsv[:, :, 1] = 255  # 饱和度固定最大

    # 计算每个像素的运动方向和幅度
    magnitude, angle = cv2.cartToPolar(flow[:, :, 0], flow[:, :, 1])

    # 方向映射到色调（0~360度 → 0~180，因为OpenCV的H范围是0~180）
    hsv[:, :, 0] = angle * 180 / np.pi / 2

    # 幅度归一化后映射到明度
    hsv[:, :, 2] = cv2.normalize(magnitude, None, 0, 255, cv2.NORM_MINMAX)

    # HSV 转 BGR，方便显示
    bgr = cv2.cvtColor(hsv, cv2.COLOR_HSV2BGR)
    return bgr, magnitude, angle

def flow_to_arrow_visualization(img, flow, step=16, scale=3):
    """
    把稠密光流可视化为稀疏箭头场（每隔step像素画一个箭头）
    箭头方向=运动方向，箭头长度=运动速度×scale
    """
    result = img.copy()
    h, w = flow.shape[:2]

    for y in range(step//2, h, step):
        for x in range(step//2, w, step):
            fx, fy = flow[y, x]
            magnitude = np.sqrt(fx**2 + fy**2)

            if magnitude < 0.5:  # 过滤静止区域
                continue

            # 起点和终点
            start = (x, y)
            end = (int(x + fx * scale), int(y + fy * scale))

            # 用幅度决定颜色：慢=蓝，快=红
            ratio = min(magnitude / 10.0, 1.0)
            color = (int(255*(1-ratio)), 0, int(255*ratio))

            cv2.arrowedLine(result, start, end, color,
                           thickness=1, tipLength=0.3)

    return result

def realtime_dense_flow(video_source=0):
    """
    实时稠密光流演示
    """
    cap = cv2.VideoCapture(video_source)
    ret, prev_frame = cap.read()
    prev_gray = cv2.cvtColor(prev_frame, cv2.COLOR_BGR2GRAY)

    while True:
        ret, curr_frame = cap.read()
        if not ret:
            break

        curr_gray = cv2.cvtColor(curr_frame, cv2.COLOR_BGR2GRAY)

        # 计算稠密光流

        )

        # 两种可视化并排显示
        hsv_vis, magnitude, angle = flow_to_hsv_visualization(flow)
        arrow_vis = flow_to_arrow_visualization(curr_frame, flow, step=20)

        # 计算全局运动统计
        mean_flow = np.mean(magnitude)
        max_flow  = np.max(magnitude)
        moving_ratio = np.mean(magnitude > 1.0) * 100  # 运动像素占比

        info = f"Mean:{mean_flow:.1f}px  Max:{max_flow:.1f}px  Moving:{moving_ratio:.1f}%"
```

### 运动分析：从光流场提取有用信息

拿到稠密光流场之后，可以做很多有意思的分析。

#### 运动分割：把运动物体从背景中分离

```python
def motion_segmentation(flow, threshold=2.0):
    """
    基于光流幅度的简单运动分割
    运动幅度超过阈值的区域 = 前景（运动物体）
    """
    magnitude, _ = cv2.cartToPolar(flow[:,:,0], flow[:,:,1])

    # 二值化：运动区域为白，静止区域为黑
    motion_mask = (magnitude > threshold).astype(np.uint8) * 255

    # 形态学处理：消除噪声小点，填充孔洞
    kernel = cv2.getStructuringElement(cv2.MORPH_ELLIPSE, (5, 5))
    motion_mask = cv2.morphologyEx(motion_mask, cv2.MORPH_OPEN,  kernel)
    motion_mask = cv2.morphologyEx(motion_mask, cv2.MORPH_CLOSE, kernel)

    return motion_mask
```

#### 相机运动估计：从光流判断相机在做什么

当场景静止时，整个光流场完全由相机运动产生，不同运动模式在光流场上有不同的特征：

```python
def estimate_camera_motion_from_flow(flow):
    """
    从稠密光流场粗略估计相机运动类型
    这是一个简化版本，用于建立直觉
    """
    h, w = flow.shape[:2]
    cx, cy = w // 2, h // 2  # 图像中心

    fx = flow[:, :, 0]  # x方向光流
    fy = flow[:, :, 1]  # y方向光流

    # 全局平均光流：代表相机的整体平移分量
    mean_fx = np.mean(fx)
    mean_fy = np.mean(fy)

    # 光流场的旋转分量：
    # 相机绕光轴旋转时，光流呈现旋转模式
    # 在图像中心附近，旋转光流的切向分量最纯净
    # 估计方法：计算图像中心区域的"旋转一致性"
    center_flow_x = fx[cy-50:cy+50, cx-50:cx+50]
    center_flow_y = fy[cy-50:cy+50, cx-50:cx+50]

    # 膨胀/收缩分量：相机前进时，光流从中心向外发散
    # 计算每个像素的光流方向与"从中心向外"方向的一致性
    y_coords, x_coords = np.mgrid[0:h, 0:w]
    radial_x = (x_coords - cx).astype(np.float32)
    radial_y = (y_coords - cy).astype(np.float32)
    radial_norm = np.sqrt(radial_x**2 + radial_y**2) + 1e-6

    # 点积：光流与径向方向的对齐程度
    # 正值 = 向外 = 相机前进；负值 = 向内 = 相机后退
    radial_component = (fx * radial_x + fy * radial_y) / radial_norm
    mean_radial = np.mean(radial_component)

    # 综合判断
    translation = np.sqrt(mean_fx**2 + mean_fy**2)

    print(f"光流分析结果:")
    print(f"  平移分量: ({mean_fx:+.2f}, {mean_fy:+.2f}) px — ", end="")
    if   mean_fx >  1: print("相机向左移动")
    elif mean_fx < -1: print("相机向右移动")
    else:              print("无明显水平平移")

    print(f"  径向分量: {mean_radial:+.2f} — ", end="")
    if   mean_radial >  0.5: print("相机前进（光流向外发散）")
    elif mean_radial < -0.5: print("相机后退（光流向内汇聚）")
    else:                    print("无明显前进/后退")

    return mean_fx, mean_fy, mean_radial
```

#### 焦点扩散（Focus of Expansion）：找到相机前进方向

当相机向前移动时，光流场会从某个点向外"发散"，这个点叫做**扩散焦点（Focus of Expansion，FoE）**，它在图像上的位置，就是相机前进方向在图像平面上的投影。自动驾驶系统用这个点来判断车辆的行驶方向。

```python
def find_focus_of_expansion(flow):
    """
    用最小二乘法估计扩散焦点（FoE）位置
    原理：在FoE处，每个像素的光流方向都指向远离FoE的方向
    即：光流向量与"从FoE到该像素"的向量平行
    """
    h, w = flow.shape[:2]
    fx = flow[:, :, 0].ravel()
    fy = flow[:, :, 1].ravel()

    y_coords, x_coords = np.mgrid[0:h, 0:w]
    x = x_coords.ravel().astype(np.float32)
    y = y_coords.ravel().astype(np.float32)

    # 对于FoE在 (cx, cy) 处，有约束：
    # fy * (xi - cx) = fx * (yi - cy)
    # 整理：fy * xi - fx * yi = fy * cx - fx * cy
    # 这是一个关于 (cx, cy) 的线性方程组，用最小二乘求解

    # 只用运动幅度较大的像素（信噪比更高）
    magnitude = np.sqrt(fx**2 + fy**2)
    valid = magnitude > 1.0

    A = np.stack([fy[valid], -fx[valid]], axis=1)
    b = fy[valid] * x[valid] - fx[valid] * y[valid]

    # 最小二乘解
    result, _, _, _ = np.linalg.lstsq(A, b, rcond=None)
    foe_x, foe_y = result

    return int(foe_x), int(foe_y)
```

### Farneback vs LK：对比总结

学完这两个算法，来做一个系统性的比较，帮你在实际项目中做选择：

|维度|LK 稀疏光流|Farneback 稠密光流|
|---|---|---|
|输出|几百个点的位移|每个像素的位移|
|速度|极快，可轻松实时|较慢，需要优化才能实时|
|适用场景|特征追踪、SLAM|运动分割、视频处理|
|数学基础|亮度恒定+局部一致|多项式展开|
|均匀区域|不处理（跳过）|有结果但不可靠|
|实现复杂度|简单|较复杂|

在实际工程中的选择原则是：需要**追踪特定目标**（比如特征点、人脸关键点）就用 LK；需要**分析整体运动场**（比如背景分离、视频特效）就用 Farneback。
