### 一、Verilog 的本质：你在描述硬件，不是写程序

#### 软件思维 vs 硬件思维

写 C 代码：

```c
a = 1;
b = 2;
c = a + b;
```

CPU 按顺序执行三条指令，一条做完做下一条。

写 Verilog 代码：

```verilog
assign a = 1;
assign b = 2;
assign c = a + b;
```

**这三行不是"按顺序执行"——它们是同时存在的三条物理连线**。`assign` 描述了"a 这根线永远等于 1"这个事实。三个赋值同时生效，**没有先后顺序**。

这就是 Verilog 最反直觉的地方：所有 `assign` 和所有 `always` 块**并行存在**。它们不是步骤，是**电路的不同部分**。

写 Verilog 时，你的脑子里应该浮现出门、触发器、连线，而不是变量和赋值。**先想电路，后写代码**——这是 FPGA 设计的核心心法。

#### 编程语言 vs 硬件描述语言的根本区别

|C 语言|Verilog|
|---|---|
|描述"做什么"（行为）|描述"是什么"（结构）|
|顺序执行|并行存在|
|变量是内存里的值|信号是物理导线|
|函数调用有开销|模块例化是物理复制|
|只占用代码空间|占用硬件资源（面积、功耗）|

带着这个对照表往下看。

### 二、Verilog 模块：硬件设计的基本单位

#### 模块的结构

```verilog
module 模块名 (端口列表);
    // 端口声明
    // 内部信号声明
    // 逻辑描述
endmodule
```

一个最简单的例子——2 输入与门：

```verilog
module and_gate (
    input  wire a,
    input  wire b,
    output wire y
);
    assign y = a & b;
endmodule
```

逐行解读：

- `module and_gate (...)`：定义一个名为 `and_gate` 的模块
- `input wire a`：a 是输入端口，类型为 wire（连线）
- `output wire y`：y 是输出端口
- `assign y = a & b`：y 这根线被驱动为 a 和 b 的与

**模块就是硬件中的一个芯片或一个功能块**。整个 FPGA 设计就是一堆模块层层例化、互相连接。

#### 端口的方向

- `input`：信号进入模块
- `output`：信号离开模块
- `inout`：双向（用于三态总线，FPGA 内部很少用）

#### 数据类型：wire 和 reg

这是初学者最容易困惑的两个类型，但其实很简单。

**wire（线网）**：

- 物理上的一根导线
- 必须由 `assign` 或模块输出**持续驱动**
- 不能存储值，只是传递

**reg（寄存器）**：

- 名字误导人——它**不一定综合成触发器**！
- 只是 Verilog 语法上"在 always 块里被赋值的变量"必须声明为 reg
- 综合后是什么取决于代码结构：
 - 在 `always @(posedge clk)` 里赋值 → 综合成触发器
 - 在 `always @(*)` 里赋值 → 综合成组合逻辑（连线）

**判断准则（重要）**：

|你想要的电路|在哪个 always 里赋值|声明为|
|---|---|---|
|组合逻辑（连线）|`always @(*)` 或用 `assign`|reg / wire|
|时序逻辑（触发器）|`always @(posedge clk)`|reg|

记住：**是 always 块的敏感列表决定综合结果，不是数据类型**。

### 三、组合逻辑的三种写法

#### 写法 1：assign（连续赋值）

```verilog
assign y = a & b;
assign sum = a + b;
assign mux_out = sel ? in1 : in0;  // 三目运算符 = 2 选 1 MUX
```

适合简单的、一行能写完的逻辑。

#### 写法 2：always @(*) 块

```verilog
reg [3:0] y;
always @(*) begin
    case (sel)
        2'd0: y = in0;
        2'd1: y = in1;
        2'd2: y = in2;
        2'd3: y = in3;
        default: y = 4'd0;
    endcase
end
```

`always @(*)` 表示"敏感列表自动包含右侧所有信号"——任何输入变化，块内逻辑重新计算。这就是组合逻辑的本质。

适合复杂的多分支逻辑，特别是 case、if-else 嵌套。

#### 写法 3：模块例化

把已有的模块当作一个"芯片"用：

```verilog
and_gate u1 (.a(x), .b(y), .y(z));
```

这是层次化设计的基础，下面专门讲。

#### 组合逻辑陷阱：意外推断出锁存器

```verilog
always @(*) begin
    if (sel)
        y = a;
    // 没写 else！
end
```

当 `sel=0` 时 y 没被赋值——为了保持 y 的值，综合工具会插入一个**锁存器（latch）**。这是 FPGA 设计的常见 BUG，工具会发出 warning。

**两个铁律避免锁存器**：

1. `always @(*)` 中所有控制路径都必须给所有输出赋值
2. case 语句永远写 `default`

修正：

```verilog
always @(*) begin
    if (sel)
        y = a;
    else
        y = 1'b0;  // 必须给个默认值
end
```

或者在 `always` 块开头给所有输出赋默认值：

```verilog
always @(*) begin
    y = 1'b0;          // 默认值
    if (sel) y = a;    // 条件覆盖
end
```

后一种风格更安全。

### 四、时序逻辑的标准写法

#### 基本模板：边沿触发的 D 触发器

```verilog
reg q;
always @(posedge clk) begin
    q <= d;
end
```

这就是一个 D 触发器：每个时钟上升沿，q 被赋值为 d。

#### 带异步复位

```verilog
always @(posedge clk or posedge rst) begin
    if (rst)
        q <= 1'b0;
    else
        q <= d;
end
```

复位优先级最高——rst=1 时不管时钟，立刻清零。

#### 带同步复位

```verilog
always @(posedge clk) begin
    if (rst)
        q <= 1'b0;
    else
        q <= d;
end
```

同步复位只在时钟沿生效。优劣对比：

||异步复位|同步复位|
|---|---|---|
|响应速度|立即|等时钟沿|
|时序约束|复位释放时需特殊处理|简单|
|资源消耗|少（专用引脚）|略多|
|FPGA 推荐|看厂家：Xilinx 偏同步，Intel 偏异步||

实际项目中两种都常见，跟着团队风格走即可。

#### 阻塞赋值 vs 非阻塞赋值（最关键的概念！）

这是 Verilog 最容易翻车的地方，工业界因为这个 BUG 损失过芯片流片的钱。

**两种赋值符号**：

- `=`：**阻塞赋值** (blocking assignment)
- `<=`：**非阻塞赋值** (non-blocking assignment)

**行为差异**：

考虑这两段代码：

```verilog
// 版本 A：阻塞赋值
always @(posedge clk) begin
    a = b;
    c = a;
end
```

```verilog
// 版本 B：非阻塞赋值
always @(posedge clk) begin
    a <= b;
    c <= a;
end
```

假设时钟沿之前 a=1, b=2，时钟沿之后会发生什么？

**版本 A（阻塞）**：

- `a = b` 立即执行 → a 变成 2
- `c = a` 立即执行 → c 变成 2（用的是新的 a）
- 结果：a=2, c=2

**版本 B（非阻塞）**：

- `a <= b` 计算右值 2，**暂存**，先不更新
- `c <= a` 计算右值 1（旧的 a），**暂存**
- 时钟沿结束时**统一更新**：a=2, c=1
- 结果：a=2, c=1

**B 才是真实硬件的行为**——两个 D 触发器并行采样，c 看到的是采样瞬间 a 的旧值，不是新值。

#### 铁律（必须刻在脑子里）

> **时序逻辑 (always @(posedge clk)) 用非阻塞赋值 `<=`** **组合逻辑 (always @(*)) 用阻塞赋值 `=`**

违反这个规则的代码可能仿真和综合结果不一致——这是 FPGA 设计中最难调的 BUG。永远遵守这条规则，无例外。

### 五、用 Verilog 重新实现前面学过的电路

理论讲完了，现在用代码把整门课的电路过一遍。这一节是这一层的核心。

#### 5.1 多路选择器

```verilog
// 4 选 1 MUX
module mux4 (
    input  wire [3:0] in,
    input  wire [1:0] sel,
    output wire       out
);
    assign out = in[sel];   // 直接索引！Verilog 可以这么写
endmodule
```

或者用 case：

```verilog
module mux4_case (
    input  wire [7:0] in0, in1, in2, in3,
    input  wire [1:0] sel,
    output reg  [7:0] out
);
    always @(*) begin
        case (sel)
            2'd0: out = in0;
            2'd1: out = in1;
            2'd2: out = in2;
            2'd3: out = in3;
            default: out = 8'd0;
        endcase
    end
endmodule
```

注意：因为 out 在 always 块里赋值，必须声明为 reg；但综合后是组合逻辑（MUX），不是触发器。

#### 5.2 译码器

```verilog
// 3-8 译码器
module decoder3_8 (
    input  wire [2:0] in,
    output reg  [7:0] out
);
    always @(*) begin
        out = 8'd0;
        out[in] = 1'b1;   // 把 in 指定的那一位置 1
    end
endmodule
```

或者用移位：`assign out = 8'b1 << in;`

#### 5.3 加法器

直接用 `+`，综合工具会选最优结构（小位宽用行波，大位宽用先行进位，FPGA 用专用进位链）：

```verilog
module adder8 (
    input  wire [7:0] a, b,
    input  wire       cin,
    output wire [7:0] sum,
    output wire       cout
);
    assign {cout, sum} = a + b + cin;   // 9 位拼接，最高位是进位
endmodule
```

`{cout, sum}` 是位拼接，9 位结果中最高位放 cout，低 8 位放 sum——非常优雅地处理了进位输出。

#### 5.4 D 触发器（带使能、异步复位）

```verilog
module dff_en (
    input  wire clk,
    input  wire rst,
    input  wire en,
    input  wire d,
    output reg  q
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            q <= 1'b0;
        else if (en)
            q <= d;
        // 没有 else，en=0 时 q 保持
    end
endmodule
```

注意：在时序 always 块里**不写 else 不会推断锁存器**，因为 q 已经是触发器，"保持"是触发器的天然行为。这与组合逻辑的规则不同。

#### 5.5 移位寄存器

```verilog
module shift_reg8 (
    input  wire       clk,
    input  wire       rst,
    input  wire       si,        // 串行输入
    output wire [7:0] q
);
    reg [7:0] shift;
    always @(posedge clk or posedge rst) begin
        if (rst)
            shift <= 8'd0;
        else
            shift <= {shift[6:0], si};   // 左移，si 进入最低位
    end
    assign q = shift;
endmodule
```

一行 `{shift[6:0], si}` 就完成了移位——这是 Verilog 比纯电路图直观的地方。

#### 5.6 计数器

```verilog
// 模 10 计数器
module counter_mod10 (
    input  wire       clk,
    input  wire       rst,
    output reg  [3:0] count,
    output wire       carry
);
    always @(posedge clk or posedge rst) begin
        if (rst)
            count <= 4'd0;
        else if (count == 4'd9)
            count <= 4'd0;
        else
            count <= count + 1'b1;
    end
    assign carry = (count == 4'd9);   // 计到 9 时进位
endmodule
```

#### 5.7 状态机（用前面讲的三段式）

复习一遍序列检测器（检测 `1101`，可重叠）：

```verilog
module seq_detector_1101 (
    input  wire clk,
    input  wire rst,
    input  wire in,
    output wire detected
);

    // 状态编码
    parameter S0 = 3'd0;
    parameter S1 = 3'd1;   // 已收到 1
    parameter S2 = 3'd2;   // 已收到 11
    parameter S3 = 3'd3;   // 已收到 110
    parameter S4 = 3'd4;   // 已收到 1101

    reg [2:0] cur_state, next_state;

    // === 第一段：状态寄存器 ===
    always @(posedge clk or posedge rst) begin
        if (rst)
            cur_state <= S0;
        else
            cur_state <= next_state;
    end

    // === 第二段：次态逻辑 ===
    always @(*) begin
        case (cur_state)
            S0: next_state = in ? S1 : S0;
            S1: next_state = in ? S2 : S0;
            S2: next_state = in ? S2 : S3;
            S3: next_state = in ? S4 : S0;
            S4: next_state = in ? S2 : S3;
            default: next_state = S0;
        endcase
    end

    // === 第三段：输出逻辑 (Moore) ===
    assign detected = (cur_state == S4);

endmodule
```

注意几个细节：

- 状态寄存器用非阻塞 `<=`（时序）
- 次态逻辑用阻塞 `=`（组合）
- case 写 `default`
- 输出用 `assign` 也行，简单的 Moore 输出常这么写

这就是工业级状态机的标准写法。**记住这个模板**。

### 六、模块层次化与例化：搭积木

复杂设计不会写在一个模块里，而是层层嵌套。看一个例子——用 4 个 D 触发器搭一个 4 位寄存器：

```verilog
module register4 (
    input  wire       clk,
    input  wire       rst,
    input  wire [3:0] d,
    output wire [3:0] q
);
    // 例化 4 个 D 触发器
    dff_simple u0 (.clk(clk), .rst(rst), .d(d[0]), .q(q[0]));
    dff_simple u1 (.clk(clk), .rst(rst), .d(d[1]), .q(q[1]));
    dff_simple u2 (.clk(clk), .rst(rst), .d(d[2]), .q(q[2]));
    dff_simple u3 (.clk(clk), .rst(rst), .d(d[3]), .q(q[3]));
endmodule
```

`u0`~`u3` 是**例化名**——同一个模块定义可以例化多次，每次产生一个独立的硬件实例。

**例化 ≠ 函数调用**！每次例化都会**真实复制一份硬件**。这与软件中函数调用复用代码完全不同。

#### 端口连接的两种风格

```verilog
// 按位置（不推荐，容易错）
dff_simple u0 (clk, rst, d[0], q[0]);

// 按名字（推荐！）
dff_simple u0 (.clk(clk), .rst(rst), .d(d[0]), .q(q[0]));
```

按名字连接清晰、安全、抗端口顺序变化。**永远用按名字连接**。

#### generate 块：批量例化

上面 4 个 dff 写得很冗长。批量例化：

```verilog
genvar i;
generate
    for (i = 0; i < 4; i = i + 1) begin: gen_dff
        dff_simple u (.clk(clk), .rst(rst), .d(d[i]), .q(q[i]));
    end
endgenerate
```

generate 是**编译时展开**的，不是运行时循环。展开后还是 4 个独立的硬件实例。

### 七、写出"可综合"的代码：FPGA 实战要点

Verilog 语法很多，但 FPGA 综合工具只支持一个**子集**。教材上很多语法（initial 块、#delay、forever）只能用于仿真，不能综合到硬件。

#### 可综合代码的五条铁律

**1. 用统一的时钟**（同步设计）

避免一个模块里出现多个 `posedge clk1`、`posedge clk2`。如果必须跨时钟域，专门加同步器（双触发器同步等技术）。

**2. 不要在不同 always 块里给同一个信号赋值**

```verilog
// ❌ 错误
always @(posedge clk) q <= d1;
always @(posedge clk) q <= d2;   // 多驱动！综合报错
```

每个信号必须有且仅有一个驱动源。

**3. 时序用 `<=`，组合用 `=`**

铁律重申。

**4. always @(*) 必须无锁存器**

每条路径都给所有输出赋值，case 写 default。

**5. 避免组合逻辑反馈环路**

```verilog
assign a = b & c;
assign b = a | d;   // a 又依赖 b，组合环！
```

这种代码综合可能成功但行为不可预测，是严重错误。任何反馈都应该过触发器。

#### 不可综合的常见语法（仅限仿真）

```verilog
initial begin              // 仿真专用
    a = 0;
    #10 a = 1;             // 延时只在仿真有效
end

forever begin              // 仿真专用
    #5 clk = ~clk;
end
```

写综合代码时永远不要用 `initial`、`#delay`、`forever`、`while` 等。

### 八、仿真与测试平台 (Testbench)

设计完模块要验证它对不对——写一个 testbench 给它输入激励、看输出。这部分代码**只用来仿真，不综合**。

```verilog
`timescale 1ns / 1ps

module tb_seq_detector;
    reg clk, rst, in;
    wire detected;

    // 例化被测模块 (DUT = Device Under Test)
    seq_detector_1101 dut (
        .clk(clk),
        .rst(rst),
        .in(in),
        .detected(detected)
    );

    // 时钟生成
    initial clk = 0;
    always #5 clk = ~clk;   // 周期 10ns，频率 100MHz

    // 激励
    initial begin
        rst = 1; in = 0;
        #20 rst = 0;

        // 输入序列 1101 1011 0110 1
        @(posedge clk) in = 1;
        @(posedge clk) in = 0;
        @(posedge clk) in = 1;   // 这里 detected 应该 = 1
        @(posedge clk) in = 1;
        // ...

        #100 $finish;
    end

    // 监视输出
    initial begin
        $monitor("Time=%0t  in=%b  state=%d  detected=%b",
                  $time, in, dut.cur_state, detected);
    end
endmodule
```

仿真时用 ModelSim、Icarus Verilog、Vivado 仿真器等工具，能看到波形图，直观验证电路对不对。

**好工程师的习惯**：每写一个模块就写一个 testbench 测它。等到把所有模块拼起来再测，BUG 几乎无法定位。

### 九、FPGA 设计完整流程

把前面所有内容串起来，从想法到 FPGA 板子上跑起来的完整流程：

```
   需求分析
      │
      │ 画框图，确定模块划分、接口
      ▼
   架构设计 (RTL 设计)
      │
      │ 写 Verilog 代码
      ▼
   功能仿真 (Behavioral Simulation)
      │
      │ Testbench 验证逻辑正确
      ▼
   综合 (Synthesis)
      │
      │ 工具把 Verilog 转换成门级网表
      │ (Vivado / Quartus / Yosys)
      ▼
   布局布线 (Place & Route)
      │
      │ 在 FPGA 物理资源上分配位置、连线
      ▼
   时序分析 (Static Timing Analysis)
      │
      │ 检查所有路径满足 setup/hold
      │ 不通过 → 优化代码或加流水线
      ▼
   生成比特流 (Bitstream)
      │
      │ FPGA 配置文件
      ▼
   下载到板子
      │
      ▼
   板上调试 (用 ILA/SignalTap 抓波形)
```

每一步对应特定工具，初学者用厂家提供的集成开发环境（Xilinx Vivado / Intel Quartus）一键完成整个流程。

### 这门课的总回顾

我们一起走过的路：

```
第一层：数制与编码
   ↓ 二进制为何抗干扰，补码为何优雅
第二层：布尔代数与逻辑门
   ↓ 与非门为何是基石
第三层：组合逻辑
   ↓ 卡诺图、加法器、MUX 这些"积木"
第四层：时序逻辑
   ↓ 触发器、寄存器，引入"时间"
第五层：状态机
   ↓ 描述任何顺序行为的通用语言
第六层：Verilog
   ↓ 把一切落地到 FPGA
```

每一层都不是孤立的——你写 Verilog 时还在用布尔代数，用状态机时还要懂时序参数，做 FPGA 时序优化时还要回头想加法器结构。**所有内容是一张网，不是一条线**。

### 课后练习（综合大题）

**1. 设计一个简易数字钟**：

- 输入：50MHz 时钟、复位、时调整、分调整按钮
- 输出：6 位 BCD 码（时:分:秒）
- 用 Verilog 实现，画出顶层模块的层次结构图

**2. 设计 UART 发送器**：

- 输入：8 位数据、发送使能、波特率（假设 115200）
- 输出：tx 串行线、busy 状态
- 画出状态转移图，写出三段式 Verilog

**3. 时序分析题**：

- 触发器参数为 $t_{su}=1\,\mathrm{ns}$、$t_h=0.5\,\mathrm{ns}$、$t_{co}=2\,\mathrm{ns}$。
- 你设计了一段代码，关键路径上有 5 个 LUT 串联，每个 LUT 延迟 0.8ns，加上布线延迟 2ns
- 这个设计能跑到多少 MHz？
- 如果要跑 200MHz 怎么办？

**4. 找 BUG 题**：

```verilog
always @(posedge clk) begin
    a = b + c;
    d = a * 2;
end
```

- 这段代码有什么问题？
- 综合出来是什么电路？
- 你想让它综合成"两级流水线"应该怎么改？
