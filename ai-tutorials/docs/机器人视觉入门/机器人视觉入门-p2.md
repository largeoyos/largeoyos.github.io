### CMake 是什么，为什么每章都要用它？

你会注意到每一章都有一个 `CMakeLists.txt` 文件，每次都要走 `mkdir build → cmake .. → make` 这套流程。这值得花一分钟理解，因为你以后会做几十次。

CMake 是一个**构建系统生成器**，它本身不编译代码，而是读取 `CMakeLists.txt` 里描述的编译规则，然后生成真正的 `Makefile`，再由 `make` 来执行编译。这个两层设计的好处是跨平台——同一份 `CMakeLists.txt` 在 Linux 上生成 Makefile，在 Windows 上可以生成 Visual Studio 工程文件。

`mkdir build && cd build` 这个操作叫做 **out-of-source build**，把所有编译产生的中间文件都放在 `build/` 目录里，不污染源码目录。这是一个好习惯，书里的所有章节都这样做。

打开任意一章的 `CMakeLists.txt`，你会看到类似这样的内容：

cmake

```cmake
cmake_minimum_required(VERSION 2.8)   # 要求的最低 CMake 版本
project(HelloSLAM)                     # 项目名称

find_package(OpenCV REQUIRED)          # 查找 OpenCV，找不到就报错
include_directories(${OpenCV_INCLUDE_DIRS})  # 告诉编译器头文件在哪里

add_executable(helloSLAM helloSLAM.cpp)     # 从源文件生成可执行文件
target_link_libraries(helloSLAM ${OpenCV_LIBS})  # 链接 OpenCV 库
```

这几行的意思你现在就能读懂：找到 OpenCV，把 `helloSLAM.cpp` 编译成可执行文件，链接 OpenCV 的库文件。后面每一章的 `CMakeLists.txt` 都是这个模式的扩展。

## 第二章：李群与李代数——旋转为什么这么麻烦

这一章是全书数学含量最高的地方，很多人在这里卡住。但如果你真正理解了这一章，后面所有的优化推导都会变得自然。我们慢慢来。

---

### 先理解问题：旋转为什么不能直接优化？

回忆第二节讲过的旋转矩阵 R，它必须满足两个约束：RTR=I 且 det(R)=1。这两个约束让旋转矩阵活在一个非常"扭曲"的空间里，不是普通的欧氏空间。

SLAM 后端要做的事情是优化位姿——也就是不断调整 R 和 t，让重投影误差最小。优化的标准做法是梯度下降：当前值加上一个小的更新量，反复迭代。但问题是，如果你对旋转矩阵 R 直接加一个小量 ΔR，得到的 R+ΔR 几乎肯定**不再是合法的旋转矩阵**了——约束被破坏了。

这就好比你要在一个球面上做优化，但你的加法操作会把你带离球面。你需要一种在球面上"行走"的方式，而不是在外面的空间里乱跑。

李群和李代数就是解决这个问题的数学工具。

---

### 群是什么？先建立直觉

"群"这个词听起来很抽象，但它描述的是一个非常具体的结构。一个**群（Group）**是一个集合加上一种运算，这种运算满足四个性质：封闭性（两个元素运算后还在集合里）、结合律、有单位元（相当于"什么都不做"的元素）、每个元素有逆元（相当于"撤销操作"）。

旋转矩阵的集合在矩阵乘法下构成一个群，叫做**特殊正交群 SO(3)**。"封闭性"意味着两个旋转矩阵相乘还是旋转矩阵（两次旋转叠加还是旋转）；单位元是单位矩阵 I（不旋转）；逆元是 RT（反向旋转）。

变换矩阵的集合（旋转加平移）在矩阵乘法下构成**特殊欧氏群 SE(3)**，这正是 SLAM 里描述位姿的那个 4×4 矩阵的家族。

群只有乘法，没有加法。这正是问题所在——优化需要"加一个小量"，但群里没有加法。

---

### 李代数：给旋转装上"加法"

这里是这一章最核心的思想，请仔细跟着想。

任何旋转矩阵都可以理解为**从单位矩阵出发，沿着某个方向连续旋转到达的结果**。这个"方向"可以用一个三维向量 ϕϕ 来描述，它的方向是旋转轴，长度是旋转角度。

这个从向量到旋转矩阵的映射，就是**指数映射（Exponential Map）**：

R=exp(ϕ∧)R=exp(ϕ∧)

其中 ϕ∧ϕ∧ 是把三维向量 ϕ=[ϕ1,ϕ2,ϕ3]Tϕ=[ϕ1,ϕ2,ϕ3]T 变成一个反对称矩阵的操作：

ϕ∧=[0−ϕ3ϕ2ϕ30−ϕ1−ϕ2ϕ10]ϕ∧=0ϕ3−ϕ2−ϕ30ϕ1ϕ2−ϕ10

这个三维向量空间（所有可能的 ϕϕ 构成的空间）就叫做 SO(3) 的**李代数 so(3)**。

李代数的关键价值在于：它是一个普通的线性空间，可以做加法，可以乘以标量。而旋转矩阵（李群）不行。通过指数映射，我们可以在李代数里做加法，然后映射回旋转矩阵。这就是"给旋转装上加法"的本质。

---

### 指数映射的具体计算：罗德里格斯公式

exp(ϕ∧) 这个矩阵指数怎么算？展开泰勒级数之后，经过一番推导（书里第四章有完整推导，你现在不需要自己推），会得到一个非常优雅的封闭形式，叫做**罗德里格斯公式（Rodrigues' Formula）**：

R=cosθ⋅I+(1−cosθ)nnT+sinθ⋅n∧R=cosθ⋅I+(1−cosθ)nnT+sinθ⋅n∧

其中 θ=∥ϕ∥θ=∥ϕ∥ 是旋转角度，n=ϕ/θn=ϕ/θ 是单位旋转轴向量。

这个公式有直观的几何含义：一个任意旋转都可以分解为"绕某个轴转某个角度"，这也是四元数的基础思想。

反过来，从旋转矩阵 R 求对应的李代数 ϕϕ，叫做**对数映射**：

ϕ=ln(R)∨ϕ=ln(R)∨

其中 ∨∨ 是 ∧∧ 的逆操作，把反对称矩阵变回向量。

---

### SE(3) 的李代数

类似的思路可以推广到变换矩阵。SE(3) 对应的李代数 se(3) 的元素是一个六维向量 ξ=[ρ,ϕ]Tξ=[ρ,ϕ]T，其中 ϕ∈so(3)ϕ∈so(3) 对应旋转部分，ρ 对应平移部分。指数映射把它变成 4×4 的变换矩阵。

这六维向量正是 SLAM 后端优化时真正使用的优化变量。优化器在 se(3) 这个六维线性空间里做迭代更新，每次更新完再通过指数映射变回合法的变换矩阵，完美绕开了旋转矩阵的约束问题。

---

### 用李代数做扰动求导

理解了李代数之后，还有一个重要的应用：对旋转矩阵求导。

在优化里，我们需要计算"误差关于位姿的导数"——也就是当位姿变化一点点时，误差变化多少。但旋转矩阵不能直接求导，因为它不在线性空间里。

解决方案是**左扰动模型**：在 R 的左边乘以一个微小旋转 exp(δϕ∧)，然后对 δϕδϕ 求导，令 δϕ→0δϕ→0。

对于一个常见操作"旋转矩阵作用在一个点上"Rp，对 R 的左扰动导数是：

∂Rp∂δϕ=−(Rp)∧∂δϕ∂Rp=−(Rp)∧

这个结论你现在先记住结论，后面写 Bundle Adjustment 的雅可比矩阵时会直接用到它。

在此之前，先看一下 `useEigen.cpp` 的核心部分，理解每一行在做什么：

```cpp
#include <iostream>
#include <Eigen/Core>
#include <Eigen/Geometry>

int main() {
    // 定义一个旋转矩阵：绕 Z 轴旋转 45 度
    // AngleAxisd 就是罗德里格斯公式的封装：给定旋转轴和角度
    Eigen::AngleAxisd rotation_vector(M_PI / 4, Eigen::Vector3d(0, 0, 1));

    // 转换为旋转矩阵
    Eigen::Matrix3d R = rotation_vector.toRotationMatrix();
    std::cout << "旋转矩阵 R =\n" << R << std::endl;

    // 验证 R^T * R = I（正交性）
    std::cout << "R^T * R =\n" << R.transpose() * R << std::endl;

    // 旋转矩阵转四元数
    Eigen::Quaterniond q(R);
    std::cout << "四元数 = " << q.coeffs().transpose() << std::endl;
    // coeffs() 的顺序是 (x, y, z, w)，注意不是 (w, x, y, z)
    // 这个顺序是 Eigen 的约定，和其他库不同，是常见的踩坑点

    // 用旋转矩阵旋转一个向量
    Eigen::Vector3d v(1, 0, 0);
    Eigen::Vector3d v_rotated = R * v;
    std::cout << "旋转后的向量 = " << v_rotated.transpose() << std::endl;
    // 绕 Z 轴旋转 45 度，(1,0,0) 应该变成 (√2/2, √2/2, 0) ≈ (0.707, 0.707, 0)

    // 变换矩阵：把旋转和平移合并成 4x4 矩阵（第二节讲过的 T）
    Eigen::Isometry3d T = Eigen::Isometry3d::Identity();
    T.rotate(R);                          // 设置旋转部分
    T.pretranslate(Eigen::Vector3d(1, 3, 4));  // 设置平移部分
    std::cout << "变换矩阵 T =\n" << T.matrix() << std::endl;

    return 0;
}
```

运行之后观察输出，重点验证两件事：`R^T * R` 应该非常接近单位矩阵（数值误差在 10−16 量级）；旋转后的向量应该约等于 (0.707,0)。这两个结果验证了罗德里格斯公式的正确性。

### 这一章的核心收获

学完这一章，你应该建立的核心直觉是：旋转矩阵（李群）和李代数之间通过指数映射/对数映射互相转换，李代数是线性空间可以做加法，李群有乘法但没有加法。优化在李代数里做，结果通过指数映射变回旋转矩阵。这个"在切空间里优化，映射回流形"的思想，不只在 SLAM 里，在所有涉及旋转优化的问题里都是标准做法。

### OpenCV 的图像存储方式：Mat

在动手写投影代码之前，有一个基础概念必须先搞清楚，否则后面读代码会很困惑——OpenCV 用 `cv::Mat` 这个类来存储图像，你需要理解它的内存布局。

一张彩色图像在 `cv::Mat` 里是一个三维数组：高度（行数）× 宽度（列数）× 通道数（RGB 图像是 3 个通道）。访问像素的方式有两种，各有适用场景：

```cpp
#include <opencv2/opencv.hpp>
#include <iostream>

int main() {
    // 读取图像，IMREAD_COLOR 表示读入彩色图
    cv::Mat img = cv::imread("test.jpg", cv::IMREAD_COLOR);

    // 检查图像是否成功读取，这是个好习惯，空图像会让后续代码直接崩溃
    if (img.empty()) {
        std::cerr << "图像读取失败！" << std::endl;
        return -1;
    }

    // 图像的基本信息
    std::cout << "图像尺寸: " << img.rows << " x " << img.cols << std::endl;
    std::cout << "通道数: " << img.channels() << std::endl;
    // type() 返回一个编码了数据类型和通道数的整数
    // CV_8UC3 表示 8位无符号整数、3通道，也就是最常见的 BGR 彩色图
    std::cout << "数据类型: " << img.type() << std::endl;

    // 方式一：用 at<>() 访问单个像素，类型安全但较慢
    // 注意：OpenCV 默认是 BGR 顺序，不是 RGB，这是个经典踩坑点
    cv::Vec3b pixel = img.at<cv::Vec3b>(100, 200); // 第100行第200列
    std::cout << "像素值 BGR: "
              << (int)pixel[0] << " "   // Blue
              << (int)pixel[1] << " "   // Green
              << (int)pixel[2] << std::endl; // Red

    // 方式二：用指针直接访问内存，速度快，用于需要遍历整张图像的场景
    for (int y = 0; y < img.rows; y++) {
        uchar* row_ptr = img.ptr<uchar>(y); // 指向第 y 行的起始地址
        for (int x = 0; x < img.cols; x++) {
            // 每个像素占 3 个字节（BGR），所以要乘以 3
            uchar b = row_ptr[x * 3];
            uchar g = row_ptr[x * 3 + 1];
            uchar r = row_ptr[x * 3 + 2];
        }

    return 0;
}
```

有一个细节值得特别注意：OpenCV 存储彩色图像的通道顺序是 **BGR**，不是 RGB。这和大多数其他库（比如 matplotlib、PyTorch）的习惯相反，是 OpenCV 的历史遗留问题，不知道这一点会导致颜色显示异常，是初学者最常踩的坑之一。

```cpp
#include <opencv2/opencv.hpp>
#include <Eigen/Core>
#include <pangolin/pangolin.h>

// 相机内参，这些数字来自 TUM 数据集的相机标定结果
// 对照第三节的公式：fx, fy 是像素焦距，cx, cy 是主点坐标
double fx = 517.3, fy = 516.5, cx = 318.6, cy = 255.3;

// 深度图的缩放因子：TUM 数据集把深度值乘以 5000 存储为整数
// 所以读出来之后要除以 5000 才能得到以米为单位的真实深度
double depthScale = 5000.0;

int main() {
    // 读入彩色图和对应的深度图
    cv::Mat color = cv::imread("../color/1.png");
    cv::Mat depth = cv::imread("../depth/1.pgm", cv::IMREAD_UNCHANGED);
    // IMREAD_UNCHANGED 很重要：深度图是 16 位整数格式
    // 如果用默认的 IMREAD_COLOR，OpenCV 会把它转成 8 位，精度全部丢失

    // 存储生成的点云，每个点是 (X, Y, Z, R, G, B)
    std::vector<Eigen::Vector6d> pointcloud;

    for (int v = 0; v < color.rows; v++) {       // 遍历每一行（v 对应像素纵坐标）
        for (int u = 0; u < color.cols; u++) {   // 遍历每一列（u 对应像素横坐标）

            // 读取深度值，转换为米
            unsigned short d = depth.ptr<unsigned short>(v)[u];
            if (d == 0) continue; // 深度为 0 表示无效测量，跳过
            double Z = d / depthScale;

            // 这里就是第三节公式的逆运算：从像素坐标 + 深度，恢复三维坐标
            // 原本：u = fx * X/Z + cx，反解得 X = (u - cx) * Z / fx
            double X = (u - cx) * Z / fx;
            double Y = (v - cy) * Z / fy;
            // Z 直接就是深度值

            // 读取该像素的颜色
            cv::Vec3b bgr = color.ptr<cv::Vec3b>(v)[u];

            // 把三维坐标和颜色存入点云
            Eigen::Vector6d point;
            point << X, Y, Z,
                     bgr[2] / 255.0,  // R（注意 BGR 转 RGB）
                     bgr[1] / 255.0,  // G
                     bgr[0] / 255.0;  // B
            pointcloud.push_back(point);
        }

    // 用 Pangolin 可视化生成的点云
    // ...（可视化代码较长，书里有完整版本）

    return 0;
}
```

运行这段代码之后，你会看到一个三维点云窗口。这是你第一次亲手把一张平面图像"展开"成三维空间里的点集。如果你转动视角，会看到桌面、椅子、墙壁都有了真实的三维结构——这就是第六节讲的稠密建图的最基础形式。

### 图像间的像素操作：为特征提取做准备

除了投影模型，这一章还介绍了几个重要的图像操作，它们是第四节视觉里程计的基础。

**图像灰度化**是特征提取的前置步骤，因为 ORB 特征检测只需要亮度信息，不需要颜色：

```cpp
cv::Mat gray;
// cvtColor 是 OpenCV 里颜色空间转换的通用函数
// COLOR_BGR2GRAY 把 BGR 三通道图变成单通道灰度图
// 转换公式：gray = 0.114*B + 0.587*G + 0.299*R
// 注意权重不相等，因为人眼对绿色最敏感
cv::cvtColor(color, gray, cv::COLOR_BGR2GRAY);
```

**图像去噪**用高斯模糊，它在提取特征之前平滑掉传感器噪声：

```cpp
cv::Mat blurred;
// GaussianBlur 参数：输入图、输出图、卷积核大小、x方向标准差
// 卷积核大小必须是奇数，这里 (7,7) 表示 7x7 的高斯核
// 核越大，模糊程度越强，但也会越多地抹掉真实的图像细节
cv::GaussianBlur(gray, blurred, cv::Size(7, 7), 0);
```

这两个操作的背后都是**卷积**——用一个小矩阵（卷积核）在图像上滑动，每个位置做加权求和。高斯模糊的卷积核权重呈二维高斯分布，中心权重大、边缘权重小，所以结果是一个平滑的加权平均。这也是深度学习里卷积神经网络（CNN）中"卷积层"的直接来源。

### 这一章最重要的实验：验证双目视差

书的第五章还有一个双目相机的实验，对应我们第六节讲过的视差公式 Z=fB/d。这个实验用 OpenCV 的立体匹配算法，从左右两张图像计算每个像素的视差，然后转换成深度图：

```bash
# 在 ch5/build 目录下
./stereoVision
```

运行之后你会同时看到左图、右图、视差图三个窗口。观察视差图时注意两点：近处物体的视差值大（颜色亮），远处物体的视差值小（颜色暗），这和公式 Z=fB/d 完全吻合；纹理缺乏的区域（比如纯色的地板或墙壁）视差图会出现噪声和空洞，这正是我们第六节提到的"双目在纹理缺乏区域会失败"的直观体现。
