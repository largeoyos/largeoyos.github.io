## 第五章：特征点法与视觉里程计——第一条真实轨迹

这一章是全书前半段的高潮。我们把前四章所有的准备工作——位姿表示、李代数、相机投影——全部组装在一起，写出一个完整的视觉里程计前端，并在真实图像上跑出第一条相机运动轨迹。

---

### 整体流程回顾

在动手之前，先把第四节讲过的流程在脑子里过一遍，因为这一章的代码结构和这个流程完全对应。给定两帧图像，我们要做三件事：在每帧里提取 ORB 特征点，在两帧之间匹配特征点，然后从匹配关系里解算出两帧之间的变换矩阵 T。这三步就是视觉里程计前端的全部。

---

### 第一步：ORB 特征提取

ORB 特征由两部分组成，理解这两部分的分工很重要。**FAST 角点检测器**负责找位置——它扫描图像，寻找那些周围像素亮度变化剧烈的点，也就是角点。**BRIEF 描述子**负责描述外观——对于每个找到的角点，它在周围随机采样若干对像素，比较每对像素的亮度大小，用 0 或 1 记录结果，最终得到一个二进制串作为这个角点的"身份证"。

ORB 在 BRIEF 的基础上加了两个改进：用图像矩计算每个角点的主方向，让描述子具备旋转不变性；用图像金字塔（把图像缩放到不同尺寸后分别提取特征）让描述子具备尺度不变性。这两个改进让 ORB 在相机发生旋转或远近变化时仍然能正确匹配特征点。

```cpp
#include <iostream>
#include <opencv2/opencv.hpp>
#include <opencv2/features2d.hpp>

int main() {
    cv::Mat img1 = cv::imread("../1.png", cv::IMREAD_GRAYSCALE);
    cv::Mat img2 = cv::imread("../2.png", cv::IMREAD_GRAYSCALE);

    // 创建 ORB 检测器
    // 500 是每帧最多提取的特征点数量，这个数字是精度和速度之间的权衡
    // 太少会导致匹配不稳定，太多会拖慢实时性
    cv::Ptr<cv::ORB> orb = cv::ORB::create(500);

    std::vector<cv::KeyPoint> kp1, kp2;  // 存储特征点位置
    cv::Mat desc1, desc2;                 // 存储描述子，每行一个特征点的二进制串

    // detectAndCompute 一次完成检测和描述子计算
    // 第三个参数是掩码（mask），nullptr 表示处理整张图像
    orb->detectAndCompute(img1, nullptr, kp1, desc1);
    orb->detectAndCompute(img2, nullptr, kp2, desc2);

    std::cout << "第一帧特征点数量: " << kp1.size() << std::endl;
    std::cout << "第二帧特征点数量: " << kp2.size() << std::endl;

    // 可视化特征点，直观感受一下哪些位置被选中了
    cv::Mat img1_kp;
    cv::drawKeypoints(img1, kp1, img1_kp, cv::Scalar::all(-1),
                      cv::DrawMatchesFlags::DRAW_RICH_KEYPOINTS);
    // DRAW_RICH_KEYPOINTS 会画出特征点的大小和方向，
    // 圆的大小代表尺度（在哪一层金字塔上检测到的），线段代表主方向
    cv::imshow("ORB 特征点", img1_kp);
    cv::waitKey(0);

    return 0;
}
```

运行之后看一下特征点的分布。你会发现特征点倾向于聚集在纹理丰富的区域——物体边缘、角点、有图案的表面——而在纯色区域几乎没有特征点。这正是 FAST 角点检测器的设计所预期的行为。

### 第二步：特征匹配与误匹配过滤

有了两帧的描述子，接下来要找出哪些特征点是同一个三维路标在两帧里的投影。匹配的度量是**汉明距离**——两个二进制串之间不同的位数，距离越小说明越相似。

但原始匹配结果里充满了误匹配，直接用来估计运动会得到完全错误的结果。过滤误匹配的标准方法是**比率测试（Ratio Test）**，由 SIFT 算法的作者 Lowe 提出：对于第一帧里的每个特征点，找到第二帧里最近的两个匹配，如果最近距离和次近距离的比值大于一个阈值（通常是 0.7），说明这个匹配不够"独特"，可能是误匹配，丢弃它。

```cpp
// 使用 BFMatcher（暴力匹配器）做 KNN 匹配，每个点找最近的 2 个候选
cv::BFMatcher matcher(cv::NORM_HAMMING);
std::vector<std::vector<cv::DMatch>> knn_matches;
matcher.knnMatch(desc1, desc2, knn_matches, 2);  // k=2，找最近两个

// Lowe 比率测试过滤误匹配
std::vector<cv::DMatch> good_matches;
for (auto& m : knn_matches) {
    // m[0] 是最近匹配，m[1] 是次近匹配
    // 如果最近距离远小于次近距离，说明这个匹配有唯一性，比较可靠
    if (m[0].distance < 0.7 * m[1].distance) {
        good_matches.push_back(m[0]);
    }

std::cout << "原始匹配数: " << knn_matches.size() << std::endl;
std::cout << "过滤后匹配数: " << good_matches.size() << std::endl;

// 可视化匹配结果，绿线连接对应的特征点对
cv::Mat img_matches;
cv::drawMatches(img1, kp1, img2, kp2, good_matches, img_matches);
cv::imshow("特征匹配", img_matches);
cv::waitKey(0);
```

观察匹配可视化结果时，注意两件事。第一，连线应该大致平行且方向一致——如果相机向右移动，所有特征点都应该在第二帧里偏向左边，连线应该大致都斜向同一方向。第二，如果你看到有连线方向完全不对（比如大部分连线向左，但有几条向右），那些就是残余的误匹配，后续的 RANSAC 会把它们过滤掉。

### 第三步：用对极几何估计运动

现在我们有了一组特征点匹配对，每对匹配给出第一帧里的像素坐标 p1(i) 和第二帧里的像素坐标 p2(i)。从这些匹配对估计相机运动，使用的是第四节讲过的对极几何。

OpenCV 把这个过程封装得很好，但理解函数背后在做什么非常重要，否则你遇到问题时无从调试。

```cpp
// 把匹配的特征点坐标提取出来，存入 Point2f 向量
std::vector<cv::Point2f> pts1, pts2;
for (auto& m : good_matches) {
    // kp1[m.queryIdx] 是第一帧里的特征点，kp2[m.trainIdx] 是第二帧里的
    pts1.push_back(kp1[m.queryIdx].pt);
    pts2.push_back(kp2[m.trainIdx].pt);
}

// 构造内参矩阵 K（对应第三节公式里的那个 3x3 矩阵）
// 这些数值来自相机标定，对不同的相机/数据集要换成对应的值
cv::Mat K = (cv::Mat_<double>(3, 3)
    520.9, 0,     325.1,   // fx, 0, cx
    0,     521.0, 249.7,   // 0, fy, cy
    0,     0,     1);      // 0,  0,  1

// 计算本质矩阵 E
// findEssentialMat 内部用 RANSAC，自动过滤剩余的误匹配
// 0.999 是 RANSAC 的置信度，1.0 是内点判断的像素误差阈值
cv::Mat E = cv::findEssentialMat(pts1, pts2, K,
                                  cv::RANSAC, 0.999, 1.0);

// 从本质矩阵分解出旋转矩阵 R 和平移向量 t
// 注意：单目相机无法恢复平移的绝对尺度，t 是单位长度的方向向量
cv::Mat R, t;
cv::recoverPose(E, pts1, pts2, K, R, t);

std::cout << "旋转矩阵 R:\n" << R << std::endl;
std::cout << "平移向量 t:\n" << t << std::endl;
```

`recoverPose` 返回的 `R` 就是一个合法的旋转矩阵（你可以验证 RTR=I），`t` 是单位长度的平移方向。这两个量合在一起就是第二节讲的变换矩阵 T 的旋转和平移分量。

### 第四步：用 PnP 做更准确的估计

对极几何的方法有一个固有的弱点：无法恢复平移的绝对尺度。如果我们有深度信息（比如使用 RGB-D 相机），可以改用 **PnP（Perspective-n-Point）**，它直接从三维点和二维像素的对应关系里解出位姿，结果包含正确的绝对尺度。

```cpp
// 假设我们有深度图，可以从第一帧的特征点恢复出三维坐标
std::vector<cv::Point3f> pts_3d;  // 三维点（在第一帧相机坐标系下）
std::vector<cv::Point2f> pts_2d;  // 对应的第二帧像素坐标

for (auto& m : good_matches) {
    cv::Point2f p1 = kp1[m.queryIdx].pt;

    // 从深度图读取深度值，depth 是 16 位深度图
    // 注意像素坐标取整，因为图像索引只能是整数
    unsigned short d = depth.ptr<unsigned short>(
        (int)p1.y)[(int)p1.x];
    if (d == 0) continue;  // 深度无效，跳过这对匹配

    float Z = d / 5000.0;  // 转换为米
    // 用内参的逆变换，从像素坐标恢复三维坐标（第三节的公式）
    float X = (p1.x - cx) * Z / fx;
    float Y = (p1.y - cy) * Z / fy;

    pts_3d.push_back(cv::Point3f(X, Y, Z));
    pts_2d.push_back(kp2[m.trainIdx].pt);
}

// solvePnPRansac：内置 RANSAC 的 PnP 求解
// 输出是旋转向量 rvec 和平移向量 tvec
cv::Mat rvec, tvec;
cv::solvePnPRansac(pts_3d, pts_2d, K, cv::Mat(),
                   rvec, tvec);

// rvec 是旋转向量（李代数 so(3) 元素，方向是旋转轴，长度是旋转角）
// 转换为旋转矩阵
cv::Mat R_pnp;
cv::Rodrigues(rvec, R_pnp);  // 这里用的就是第二章讲的罗德里格斯公式！

std::cout << "PnP 旋转矩阵:\n" << R_pnp << std::endl;
std::cout << "PnP 平移向量:\n" << tvec << std::endl;
```

注意 `cv::Rodrigues` 这个函数——它实现的正是第二章讲的罗德里格斯公式，把旋转向量（李代数元素）转换成旋转矩阵（李群元素）。在这里你第一次看到第二章的数学直接出现在视觉里程计的代码里。

### 这一章最值得思考的地方

运行代码后可进行一个对照实验：把 Lowe 比率测试的阈值从 0.7 改成 0.9，重新运行并观察匹配数量与最终轨迹精度的变化。阈值变大意味着保留更多匹配，其中也会包含更多误匹配。RANSAC 能处理一定比例的误匹配，但比例过高时也会失效，估计出的 R 和 t 会出现明显偏差。该实验可以直观展示误匹配过滤对整个系统的重要性。

还有一个值得注意的现象：在特征点数量很少的帧（比如相机对准一面白墙的时候），`findEssentialMat` 可能会返回一个质量很差的本质矩阵，`recoverPose` 的结果也会不可靠。这正是我们在第四节里提到的"特征缺失环境下视觉 SLAM 的失败场景"——现在你在代码里亲眼看到它是怎么发生的了。

### 小结与下一章预告

这一章我们完成了视觉 SLAM 前端的完整实现：ORB 特征提取、比率测试过滤误匹配、对极几何估计本质矩阵、PnP 求解绝对位姿。你现在有了一个能在真实图像上运行的视觉里程计。

但你应该也注意到了一个问题：这个前端是逐帧处理的，每次只考虑相邻两帧，误差会不断累积漂移。下一章**第六章：非线性优化**正是为了解决这个问题，它讲的是如何把所有历史观测放在一起，用最小二乘优化找到全局最自洽的位姿序列——也就是第五节讲过的 Bundle Adjustment 的数学细节和代码实现。那一章会用到 Ceres 和 g2o 两个优化库，是后端的核心，代码跑完之后你会看到优化前后轨迹精度的显著差距。
