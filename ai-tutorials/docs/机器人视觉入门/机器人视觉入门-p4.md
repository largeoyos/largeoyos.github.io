## 第六章：非线性优化——让轨迹全局自洽

上一章我们跑出了第一条相机轨迹，但它有一个根本性的缺陷：每次只看相邻两帧，误差单向累积，走得越远偏得越多。这一章我们解决这个问题，把所有历史观测放在一起，用非线性优化找到全局最优的位姿序列。这正是第五节讲过的 Bundle Adjustment 的完整实现。

---

### 先把问题想清楚：我们在优化什么？

回忆第五节的重投影误差公式：

eij=pij−π(K,Ti,Pj)

我们想调整所有位姿 {Ti} 和所有路标点 {Pj}，让所有重投影误差的平方和最小。这是一个非线性最小二乘问题，因为投影函数 π(⋅) 里有除以 Z 的操作，是非线性的。

非线性最小二乘没有封闭解，只能用迭代方法逼近。最核心的算法是**高斯-牛顿法**，理解它是这一章的重点。

---

### 高斯-牛顿法：把非线性问题反复线性化

高斯-牛顿法的思路非常直观。假设当前对所有变量有一个估计值 x（把所有位姿和路标点打包成一个大向量），误差函数是 f(x)。我们想找到一个更新量 Δx，使得 f(x+Δx) 比 f(x) 更小。

对 f(x+Δx) 在 x 处做一阶泰勒展开：

f(x+Δx)≈f(x)+JΔx

其中 J 是 f 关于 x 的**雅可比矩阵**，每一行是误差的一个分量对所有变量的偏导数。把这个线性近似代入最小二乘目标，对 Δx 求导并令其为零，得到一个线性方程组，叫做**正规方程（Normal Equation）**：

JTJ⋅Δx=−JTf(x)

通常把左边的系数矩阵记作 H（叫做近似的 Hessian 矩阵），右边记作 g（叫做梯度向量）：

HΔx=g

解出 Δx 之后，用它更新当前估计，然后重新计算雅可比，再解一次正规方程，如此反复直到 Δx 足够小（收敛）。这就是高斯-牛顿迭代的全部。

**Levenberg-Marquardt（LM）**是高斯-牛顿的改进版，它在正规方程里加了一个阻尼项：

(H+λI)Δx=g

当 λ 很大时，更新步长变小，算法退化为梯度下降（稳定但慢）；当 λ 很小时，算法接近高斯-牛顿（快但可能不稳定）。LM 会根据每次迭代的效果动态调整 λ，兼顾了速度和稳定性，是 SLAM 后端优化的标准选择。

---

### 雅可比矩阵：推导一次，受益终身

整个优化里最需要手动推导的部分是雅可比矩阵 J。具体来说，我们需要推导重投影误差 eij 对位姿 Ti（用李代数 ξi∈se(3)ξi∈se(3) 表示）和路标点坐标 Pj 的偏导数。

先看对路标点坐标的导数，相对简单。设路标点在相机坐标系下是Pc=[X,Y,Z]T，投影得到像素[u,v]T，其中：

u=fxXZ+cx,v=fyYZ+cyu=fxZX+cx,v=fyZY+cy

对 Pc 求偏导：

∂e∂Pc=−[fxZ0−fxXZ20fyZ−fyYZ2]∂Pc∂e=−[Zfx00Zfy−Z2fxX−Z2fyY]

再看对位姿李代数的导数，用第二章讲的左扰动模型。对位姿施加一个微小扰动 δξ，利用链式法则：

∂e∂δξ=−[fxZ0−fxXZ2−fxXYZ2fx+fxX2Z2−fxYZ0fyZ−fyYZ2−fyY2Z2fyXYZ2fyXZ]∂δξ∂e=−[Zfx00Zfy−Z2fxX−Z2fyY−Z2fxXY−fy−Z2fyY2fx+Z2fxX2Z2fyXY−ZfxYZfyX]

这是一个 2×6 的矩阵，6 对应位姿的 6 个自由度（3 个平移 + 3 个旋转）。你不需要死记这个公式，但需要知道它怎么来的——就是投影函数对李代数变量用链式法则展开，中间用了第二章的扰动模型。书里第六章有完整推导过程，建议至少手推一遍，推导过程本身就是对前几章所有内容的一次综合复习。

### 工具选择：Ceres 还是 g2o？

手推雅可比、手写高斯-牛顿迭代、手动处理稀疏矩阵求解……这些工作量巨大且容易出错。实际工程里我们用优化库来处理这些细节，书里介绍了两个最主流的选择。

**Ceres Solver** 是谷歌开发的通用非线性最小二乘库。这让代码非常简洁，但自动微分会引入一定的运行时开销。

**g2o（General Graph Optimization）** 是专门为 SLAM 设计的图优化框架。它的核心概念正是第五节讲的图结构：你显式地往图里添加顶点（位姿节点、路标点节点）和边（观测约束），然后调用优化器。g2o 要求你手动提供雅可比矩阵，计算效率更高，ORB-SLAM3 的后端就用 g2o。

### 用 Ceres 实现曲线拟合：先热身

书里先用一个曲线拟合的例子让你熟悉 Ceres 的接口，然后再做 Bundle Adjustment。曲线拟合比 BA 简单，但用的是完全相同的 API，是很好的热身。

```cpp
#include <ceres/ceres.h>

// 代价函数类：描述一个观测点对参数的约束
// 模板参数 <1, 3> 表示：残差维度是 1，待优化参数维度是 3
struct CurveFittingCost {
    // 构造函数：把观测数据存进来
    CurveFittingCost(double x, double y) : x_(x), y_(y) {}

    // operator() 是核心：给定当前参数估计，计算残差
    // Ceres 会自动对这个函数求导（自动微分）
    template<typename T>
    bool operator()(const T* const abc, T* residual) const {
        // 模型：y = exp(a*x^2 + b*x + c)
        // 残差 = 观测值 - 模型预测值
        residual[0] = T(y_) - ceres::exp(
            abc[0] * T(x_) * T(x_) +   // a*x^2
            abc[1] * T(x_) +             // b*x
            abc[2]);                      // c
        return true;
    }

    const double x_, y_;  // 存储观测数据
};

int main() {
    // 待优化的参数，给一个初始估计值
    double abc[3] = {0, 0, 0};  // 真实值大约是 {1, 2, 1}

    ceres::Problem problem;

    // 把每个观测点加入优化问题
    // AutoDiffCostFunction 告诉 Ceres 用自动微分计算导数
    for (int i = 0; i < observations.size(); i++) {
        problem.AddResidualBlock(
            new ceres::AutoDiffCostFunction<CurveFittingCost, 1, 3>(
                new CurveFittingCost(observations[i].x, observations[i].y)),
            nullptr,  // 损失函数，nullptr 表示用普通最小二乘
            abc);     // 待优化的参数块
    }

    // 配置求解器并运行
    ceres::Solver::Options options;
    options.linear_solver_type = ceres::DENSE_NORMAL_CHOLESKY;
    options.minimizer_progress_to_stdout = true;  // 打印每次迭代的信息

    ceres::Solver::Summary summary;
    ceres::Solve(options, &problem, &summary);

    std::cout << "优化结果: a=" << abc[0]
              << " b=" << abc[1]
              << " c=" << abc[2] << std::endl;
    return 0;
}
```

运行这段代码时，观察 Ceres 打印的迭代信息，你会看到每次迭代的代价函数值在下降，Δx 在减小，直到收敛。这个过程就是高斯-牛顿迭代在真实运行。

### 用 g2o 实现 Bundle Adjustment

热身完毕，进入这一章最重要的实验——用 g2o 对真实的相机位姿和路标点做 Bundle Adjustment：

```cpp
#include <g2o/core/base_vertex.h>
#include <g2o/core/base_binary_edge.h>
#include <g2o/core/block_solver.h>
#include <g2o/core/optimization_algorithm_levenberg.h>
#include <g2o/solvers/dense/linear_solver_dense.h>

// 顶点：相机位姿，用 SE(3) 的李代数 6 维向量参数化
// BaseVertex<6, SE3Quat> 表示：优化变量维度是 6，内部存储类型是 SE3Quat
class VertexPose : public g2o::BaseVertex<6, Sophus::SE3d> {
public:
    // 重置为单位变换
    void setToOriginImpl() override { _estimate = Sophus::SE3d(); }

    // 更新：在李代数空间做加法，然后映射回李群
    // 这正是第二章讲的"在李代数里优化"的代码实现！
    void oplusImpl(const double* update) override {
        Eigen::Matrix<double, 6, 1> delta;
        delta << update[0], update[1], update[2],
                 update[3], update[4], update[5];
        // Sophus::SE3d::exp() 就是指数映射，把李代数元素变回变换矩阵
        _estimate = Sophus::SE3d::exp(delta) * _estimate;
    }

    bool read(std::istream&) override { return true; }
    bool write(std::ostream&) override const { return true; }
};

// 顶点：路标点，三维坐标
class VertexPoint : public g2o::BaseVertex<3, Eigen::Vector3d> {
public:
    void setToOriginImpl() override { _estimate = Eigen::Vector3d::Zero(); }
    void oplusImpl(const double* update) override {
        _estimate += Eigen::Vector3d(update[0], update[1], update[2]);
    }
    bool read(std::istream&) override { return true; }
    bool write(std::ostream&) override const { return true; }
};

// 边：重投影误差，连接一个位姿顶点和一个路标点顶点
// BaseBinaryEdge<2, Vector2d, VertexPose, VertexPoint>
// 表示：误差维度 2，观测类型 Vector2d，连接的两类顶点
class EdgeProjection : public g2o::BaseBinaryEdge<2, Eigen::Vector2d,
                                                   VertexPose, VertexPoint> {
public:
    EdgeProjection(const Eigen::Matrix3d& K) : K_(K) {}

    // 计算重投影误差：这里就是第五节公式的代码实现
    void computeError() override {
        const VertexPose* pose = static_cast<VertexPose*>(_vertices[0]);
        const VertexPoint* point = static_cast<VertexPoint*>(_vertices[1]);

        // 把路标点从世界坐标系变换到相机坐标系
        Eigen::Vector3d Pc = pose->estimate() * point->estimate();

        // 投影到像素平面（对应第三节的投影公式）
        double u = K_(0,0) * Pc[0] / Pc[2] + K_(0,2);
        double v = K_(1,1) * Pc[1] / Pc[2] + K_(1,2);

        // 误差 = 观测像素坐标 - 投影得到的像素坐标
        _error = _measurement - Eigen::Vector2d(u, v);
    }

    // 手动提供雅可比矩阵，对应本章前面推导的那个 2x6 和 2x3 矩阵
    void linearizeOplus() override {
        const VertexPose* pose = static_cast<VertexPose*>(_vertices[0]);
        const VertexPoint* point = static_cast<VertexPoint*>(_vertices[1]);
        Eigen::Vector3d Pc = pose->estimate() * point->estimate();

        double X = Pc[0], Y = Pc[1], Z = Pc[2];
        double fx = K_(0,0), fy = K_(1,1);
        double Z2 = Z * Z;

        // 对位姿的雅可比（2x6），就是前面推导的那个公式
        _jacobianOplusXi
            -fx/Z,    0,  fx*X/Z2,  fx*X*Y/Z2,      -fx*(1+X*X/Z2),  fx*Y/Z,
               0,  -fy/Z,  fy*Y/Z2,  fy*(1+Y*Y/Z2),  -fy*X*Y/Z2,    -fy*X/Z;

        // 对路标点的雅可比（2x3）
        Eigen::Matrix3d R = pose->estimate().rotationMatrix();
        _jacobianOplusXj = _jacobianOplusXi.block<2,3>(0,3) * R;
        // 注意这里用的是旋转矩阵的前三列，因为路标点的更新是在世界坐标系里
    }

private:
    Eigen::Matrix3d K_;
};
```

有了这些类的定义之后，构建并求解优化问题就非常清晰了：

```cpp
int main() {
    // 配置求解器
    // BlockSolver<6,3> 表示：位姿块维度 6，路标点块维度 3
    // 这个信息让 g2o 能利用 BA 问题的稀疏结构来加速求解
    typedef g2o::BlockSolver<g2o::BlockSolverTraits<6, 3>> BlockSolverType;
    typedef g2o::LinearSolverDense<BlockSolverType::PoseMatrixType> LinearSolverType;

    auto solver = new g2o::OptimizationAlgorithmLevenberg(
        g2o::make_unique<BlockSolverType>(
            g2o::make_unique<LinearSolverType>()));

    g2o::SparseOptimizer optimizer;
    optimizer.setAlgorithm(solver);

    // 添加位姿顶点
    for (int i = 0; i < poses.size(); i++) {
        auto v = new VertexPose();
        v->setId(i);
        v->setEstimate(poses[i]);
        // 固定第一帧位姿，作为坐标系原点
        // 如果不固定任何顶点，系统有规范自由度（gauge freedom），优化无法收敛
        if (i == 0) v->setFixed(true);
        optimizer.addVertex(v);
    }

    // 添加路标点顶点
    for (int i = 0; i < points.size(); i++) {
        auto v = new VertexPoint();
        v->setId(poses.size() + i);
        v->setEstimate(points[i]);
        v->setMarginalized(true);  // 边缘化路标点，利用稀疏结构加速
        optimizer.addVertex(v);
    }

    // 添加重投影误差边
    for (auto& obs : observations) {
        auto e = new EdgeProjection(K);
        e->setVertex(0, optimizer.vertex(obs.pose_id));
        e->setVertex(1, optimizer.vertex(poses.size() + obs.point_id));
        e->setMeasurement(obs.pixel);
        e->setInformation(Eigen::Matrix2d::Identity());  // 信息矩阵，暂时用单位阵
        optimizer.addEdge(e);
    }

    // 运行优化
    optimizer.initializeOptimization();
    optimizer.optimize(50);  // 最多迭代 50 次

    return 0;
}
```

这里有一件事值得你仔细思考。为什么固定第一帧位姿是必要的？如果不固定，整个地图可以在空间中任意平移和旋转而不改变任何重投影误差——因为重投影误差只关心相对位置关系，不关心绝对位置。这种不确定性叫做**规范自由度（gauge freedom）**，它会让正规方程的系数矩阵 H 变成奇异矩阵，无法求解。固定一个节点相当于确定了坐标系，消除了这种不确定性。

### 这一章的核心收获

学完这一章，你应该建立的最重要的直觉是：SLAM 的后端优化本质上是一个非线性最小二乘问题，高斯-牛顿法把它反复线性化来求解，雅可比矩阵是连接误差函数和优化变量的桥梁，而李代数是让旋转矩阵能被优化的关键工具。这四个概念串在一起，就是整个 SLAM 后端的数学骨架。

代码跑通之后，下一章是**第七章：视觉里程计进阶**，我们会学习直接法——一种完全不依赖特征点、直接用像素灰度值来估计相机运动的方法。直接法在纹理缺乏的场景下比特征点法更鲁棒，也是很多现代 SLAM 系统（比如 DSO）的核心思路。

## 第七章：直接法——不用特征点的视觉里程计

上一章我们用特征点法完成了 Bundle Adjustment。特征点法有一个隐含的假设：图像里存在足够多的、可以被可靠提取和匹配的角点。但现实场景里这个假设经常被打破——走廊、暗室、雾天、运动模糊，这些情况下特征点要么找不到，要么匹配错误率极高。这一章我们学习一种根本上不同的思路：**直接法（Direct Method）**。

---

### 核心思想：像素灰度应该保持不变

直接法的出发点是一个物理直觉，叫做**光度一致性假设（Photometric Consistency）**：同一个三维点，在相机运动前后拍到的两张图像里，对应像素的灰度值应该相同（或者至少非常接近）。

用数学语言写出来就是，设第一帧图像里像素 p1 处的灰度值是 I1(p1)，同一个三维点 P 在第二帧里投影到像素 p2，那么：

I1(p1)≈I2(p2)

如果相机的位姿估计是准确的，这个等式应该成立。如果位姿估计有误差，p2 就会偏离真实位置，两边的灰度值就会不相等。因此，**灰度差就是误差信号**，我们要优化位姿使灰度差最小。

这和特征点法的根本区别在于：特征点法的误差是"特征点应该在哪个像素位置"，直接法的误差是"这个像素应该是什么灰度值"。前者需要先提取特征再匹配，后者直接在像素灰度上做优化，跳过了整个特征提取和匹配的环节。

---

### 直接法的误差函数

设相机从第一帧到第二帧的变换矩阵是 T（待优化的量），第一帧里的像素 p1 对应的三维点 P（通过深度图获得），则 P 在第二帧里的投影位置是：

p2=π(K,T⋅P)

其中 π(⋅) 是上一章和第三节都用过的投影函数。直接法的误差函数（叫做**光度误差**）是：

e(T)=I1(p1)−I2(π(K,T⋅P))

我们对所有参与计算的像素点求误差的平方和，然后对 T 做优化：

T∗=argminT∑i∥I1(p1(i))−I2(π(K,T⋅P(i)))∥2T∗=argTmini∑∥I1(p1(i))−I2(π(K,T⋅P(i)))∥2

这个形式和上一章的 Bundle Adjustment 几乎一模一样，只是把"像素坐标误差"换成了"灰度值误差"。因此优化方法完全相同——高斯-牛顿迭代，需要计算误差对 T 的雅可比矩阵。

---

### 雅可比矩阵：链式法则的完整展示

直接法的雅可比推导是一个非常好的练习，因为它完整地展示了整个感知链条上的链式法则，把图像、投影、李代数三层全部串在一起。

误差 e 对李代数 δξ 的导数，用链式法则展开：

∂e∂δξ=∂I2∂p2⋅∂p2∂Pc⋅∂Pc∂δξ∂δξ∂e=∂p2∂I2⋅∂Pc∂p2⋅∂δξ∂Pc

这三个因子分别对应三层不同的物理含义，值得逐一理解清楚。

**第一项** ∂I2∂p2∂p2∂I2 是图像在像素 p2 处的**图像梯度**，是一个 1×2 的行向量，表示图像灰度值沿水平和垂直方向的变化率。这正是图像处理里常说的梯度图，可以用 Sobel 算子来近似计算。图像梯度越大的地方（边缘、角点附近），这一项越大，说明这个像素对位姿变化越敏感，是更好的优化信息来源。这也解释了一个反直觉的现象：直接法虽然不显式地提取特征点，但它实际上隐式地依赖图像梯度，在纹理丰富的区域效果更好。

**第二项** ∂p2∂Pc∂Pc∂p2 是投影函数对三维点坐标的导数，是一个 2×3 的矩阵，这正是上一章在 `linearizeOplus` 里计算过的那个投影雅可比，数值上是：

∂p2∂Pc=[fxZ0−fxXZ20fyZ−fyYZ2]∂Pc∂p2=[Zfx00Zfy−Z2fxX−Z2fyY]

**第三项** ∂Pc∂δξ∂δξ∂Pc 是三维点坐标对位姿李代数的导数，用第二章的左扰动模型得到，是一个 3×6 的矩阵：

∂Pc∂δξ=[I−Pc∧]∂δξ∂Pc=[I−Pc∧]

三项相乘，最终雅可比是一个 1×6 的行向量。每个参与计算的像素贡献一行，所有像素堆叠起来就是完整的雅可比矩阵 J，代入正规方程就能求解更新量。

### 稀疏直接法、半稠密法、稠密法

直接法根据参与计算的像素数量，分为三种变体，各有适用场景，理解它们的区别很重要。

**稀疏直接法**只选取少量像素参与计算，通常选图像梯度较大的像素（边缘附近），但不做完整的描述子计算，只用灰度值做误差。计算量小，速度快，是实时系统的首选。SVO（Semi-direct Visual Odometry）就是这种思路，它在选点上用了类似特征点的方法，但在优化时用直接法。

**半稠密法**选取所有图像梯度不为零的像素参与计算，通常对应图像中所有边缘和纹理区域，大约是总像素数的 20% 到 40%。能构建半稠密的深度地图，视觉效果好，DSO（Direct Sparse Odometry）是这个路线的代表作，精度非常高。

**稠密法**用所有像素参与计算，能构建完整的稠密地图，但计算量极大，通常需要 GPU 加速。KinectFusion（第六节讲过）是稠密法的代表。

---

### 直接法的两个关键问题

在动手写代码之前，有两个实现细节值得提前想清楚，否则写出来的代码结果会很差。

**第一个问题是图像插值**。投影得到的像素坐标 p2 几乎不可能正好落在整数像素位置上，比如可能是 (127.3,84.7)。但图像是离散的，只有整数坐标处有灰度值。解决方法是**双线性插值**：用周围四个整数像素的灰度值，按距离加权平均来得到非整数坐标处的灰度估计。这个操作必须是可微的（因为优化需要求导），双线性插值恰好满足这一点，所以是标准选择。

**第二个问题是图像金字塔**。直接法对初始位姿估计非常敏感，因为光度误差函数在大位移时高度非线性，容易陷入局部最优。标准的解决方案是**由粗到精（coarse-to-fine）**：先把图像缩小到很低的分辨率（比如原图的 1/8），在这个分辨率下做优化，得到一个粗略的位姿估计；然后把图像放大一倍（1/4），用粗估计作为初始值继续优化；最后在原始分辨率上做最终优化。低分辨率图像的运动看起来很小，误差函数更接近线性，优化更容易收敛，然后逐层精化。


核心代码逻辑如下，理解每一步和理论的对应关系：

```cpp
// 直接法优化的核心：一次高斯-牛顿迭代
void DirectPoseEstimationSingleLayer(
    const cv::Mat& img1,       // 第一帧图像
    const cv::Mat& img2,       // 第二帧图像
    const VecV2d& px_ref,      // 第一帧中参与计算的像素坐标
    const VecV3d& pts_ref,     // 对应的三维点坐标（从深度图获得）
    Sophus::SE3d& T21)         // 待优化的位姿（从第一帧到第二帧）
{
    const double fx = 718.856, fy = 718.856, cx = 607.193, cy = 185.216;

    // 迭代优化，最多 iterations 次
    int iterations = 10;
    double cost = 0, lastCost = 0;

    for (int iter = 0; iter < iterations; iter++) {
        // 每次迭代构建 H 矩阵和 b 向量（对应正规方程 H*dx = b）
        Eigen::Matrix<double, 6, 6> H = Eigen::Matrix<double, 6, 6>::Zero();
        Eigen::Matrix<double, 6, 1> b = Eigen::Matrix<double, 6, 1>::Zero();
        cost = 0;

        for (int i = 0; i < px_ref.size(); i++) {
            // 1. 把三维点投影到第二帧
            Eigen::Vector3d Pc = T21 * pts_ref[i];  // 变换到第二帧相机坐标系
            double X = Pc[0], Y = Pc[1], Z = Pc[2];
            if (Z < 0) continue;  // 点在相机后面，跳过

            double u = fx * X / Z + cx;  // 投影到像素坐标
            double v = fy * Y / Z + cy;

            // 检查投影点是否在图像边界内（留出 1 像素边距，为了插值）
            if (u < 1 || u > img2.cols - 1 || v < 1 || v > img2.rows - 1)
                continue;

            // 2. 计算光度误差（灰度差）
            // GetPixelValue 内部做双线性插值，处理非整数坐标
            double error = GetPixelValue(img1, px_ref[i][0], px_ref[i][1])
                         - GetPixelValue(img2, u, v);
            cost += error * error;

            // 3. 计算雅可比（链式法则三项相乘）
            // 第三项：投影雅可比 (2x3 部分，这里只取对旋转的部分)
            Eigen::Matrix<double, 2, 6> J_pixel_xi;
            J_pixel_xi
                fx/Z,   0,    -fx*X/(Z*Z),  -fx*X*Y/(Z*Z),    fx+fx*X*X/(Z*Z),  -fx*Y/Z,
                0,    fy/Z,  -fy*Y/(Z*Z),  -fy-fy*Y*Y/(Z*Z),  fy*X*Y/(Z*Z),     fy*X/Z;

            // 第一项：图像梯度（用相邻像素近似，这是 Sobel 梯度的简化版本）
            Eigen::Matrix<double, 1, 2> J_img_pixel;
            J_img_pixel
                0.5 * (GetPixelValue(img2, u+1, v) - GetPixelValue(img2, u-1, v)),
                0.5 * (GetPixelValue(img2, u, v+1) - GetPixelValue(img2, u, v-1));
            // 注意：梯度是在第二帧图像上计算的，因为误差关于 p2 的导数
            // 这里用相邻像素差来近似梯度，是标准的数值微分方法

            // 链式法则：J = -J_img * J_pixel_xi（负号来自误差定义）
            Eigen::Matrix<double, 6, 1> J = -(J_img_pixel * J_pixel_xi).transpose();

            // 4. 累积到 H 和 b（这正是高斯-牛顿正规方程的构建过程）
            H += J * J.transpose();  // H ≈ J^T * J
            b += -error * J;         // b = -J^T * f(x)
        }

        // 5. 求解线性方程组 H * dx = b
        Eigen::Matrix<double, 6, 1> dx = H.ldlt().solve(b);
        // ldlt() 是 Cholesky 分解，比直接求逆稳定且高效

        if (isnan(dx[0])) {
            // H 可能是奇异矩阵（比如所有像素都投影到图像外面），停止迭代
            std::cout << "结果包含 NaN，停止迭代" << std::endl;
            break;
        }

        // 6. 更新位姿：在李代数空间加上更新量，然后通过指数映射回 SE(3)
        // 这正是第二章李代数的直接应用：oplusImpl 的手动实现版本
        T21 = Sophus::SE3d::exp(dx) * T21;

        // 收敛判断：如果代价函数不再下降，停止迭代
        if (iter > 0 && cost >= lastCost) break;
        lastCost = cost;

        std::cout << "迭代 " << iter << " 代价: " << cost << std::endl;
    }
```

看完这段代码，你会发现它和上一章 g2o 的 `linearizeOplus` 函数做的是完全相同的事情，只是这里是手动构建 H 和 b，而 g2o 帮我们做了这些封装。手动实现一次反而能让你对高斯-牛顿迭代的每一步都了然于心。

### 直接法 vs 特征点法：该选哪个？

学完这两种方法，你可能会问：实际系统里该用哪种？答案取决于场景，理解这个权衡对你以后选择或设计系统非常重要。

特征点法的优势是对光照变化鲁棒（描述子有一定的光照不变性），对大位移和快速运动更鲁棒（因为匹配不依赖初始估计的精度），而且误匹配可以用 RANSAC 显式过滤。劣势是在纹理缺乏的场景下完全失效，特征提取本身有计算开销，而且只利用了图像中少数几百个特征点，丢弃了大量图像信息。

直接法的优势是在纹理缺乏的场景下仍然能工作（只要有些许梯度），充分利用了图像里的全部信息（半稠密或稠密），没有特征提取和匹配的开销。劣势是对光照变化非常敏感（光度一致性假设在光照变化时被打破），对初始估计的精度要求高（需要图像金字塔缓解），在快速运动时容易失败。

正因为各有所长，现代系统越来越多地采用**混合方法**——SVO 在选点时用特征检测的思路（FAST 角点），但优化时用直接法（光度误差）；LSD-SLAM 用直接法做跟踪，但用特征点法做回环检测。理解了这两种方法的本质，你就能读懂这些混合系统的设计思路。

## 第九章：滑动窗口优化与边缘化——让后端能实时运行

上一章我们实现了完整的 Bundle Adjustment，但你可能已经注意到一个现实问题：随着机器人不断运动，位姿节点和路标点节点会无限增加，优化问题会越来越大，最终无法实时运行。这一章解决的正是这个工程核心问题。

---

### 先想清楚问题所在

回忆第六章的 BA：我们把所有位姿 {T1,T2,…,Tn} 和所有路标点 {P1,…,Pm} 全部放进优化问题。如果机器人跑了 10 分钟，以每秒 30 帧计算，就有 18000 个位姿节点，加上几十万个路标点，正规方程的系数矩阵 H 会变成一个几十万维的巨型矩阵。就算利用稀疏性，求解这个方程组也会越来越慢，直到无法实时。

最直觉的解决思路是：只保留最近的 N 帧做优化，旧帧直接丢掉。这就是**滑动窗口（Sliding Window）**的基本想法。但"直接丢掉旧帧"会带来一个严重的问题——旧帧观测到的那些路标点，和窗口内的新帧之间可能有共视关系，直接丢弃旧帧相当于扔掉了这些宝贵的约束信息。

**边缘化（Marginalization）**就是解决这个问题的数学工具。它不是粗暴地丢掉旧帧，而是把旧帧携带的信息**压缩成一个先验约束**，传递给窗口内剩余的帧。丢掉的是节点，但信息被保留下来了。

---

### 边缘化的数学本质：Schur 补

边缘化的核心操作来自线性代数里的一个经典技巧，叫做 **Schur 补（Schur Complement）**。理解它的最好方式是从一个具体的线性方程组开始想。

假设我们的优化变量分成两组：要保留的变量 xb（窗口内的新帧）和要丢弃的变量 xm（即将离开窗口的旧帧）。正规方程 HΔx=g 按这两组变量分块写出来就是：

[HbbHbmHmbHmm][ΔxbΔxm]=[gbgm][HbbHmbHbmHmm][ΔxbΔxm]=[gbgm]

其中 Hbb 是保留变量之间的信息矩阵，Hmm 是被边缘化变量的信息矩阵，Hbm 描述两组变量之间的耦合关系。

从第二个方程解出 Δxm：

Δxm=Hmm−1(gm−HmbΔxb)

把这个代入第一个方程，消去 Δxm，得到一个只含 Δxb 的方程：

(Hbb−HbmHmm−1Hmb)⏟H~bΔxb=gb−HbmHmm−1gm⏟g~bH~b(Hbb−HbmHmm−1Hmb)Δxb=g~bgb−HbmHmm−1gm

其中 H~b=Hbb−HbmHmm−1HmbH~b=Hbb−HbmHmm−1Hmb 就是 Schur 补，也叫**先验信息矩阵**。它的含义是：把 xm 的信息"积分"进了对 xb 的约束里。以后我们只需要对 H~bΔxb=g~bH~bΔxb=g~b 求解，xm 这个节点就可以彻底从图里删掉了，但它的信息通过 H~bbH~b 永久地保留在系统里。

---

### 一个直观类比

如果上面的矩阵操作让你感到抽象，可以用这个类比来建立直觉。想象你有三个人 A、B、C，A 和 B 之间有债务关系，B 和 C 之间有债务关系。现在 B 要离开这个系统，你不能简单地把 B 的账目清零（那样信息就丢了），而是先结算 B 和 A、B 和 C 之间的债务，把净结果转换成 A 和 C 之间的直接债务关系。B 离开之后，A 和 C 之间新增的这条约束，就保留了 B 曾经存在过的信息。

边缘化做的正是这件事：把旧帧（B）和它连接的所有节点之间的关系，转化成那些节点（A 和 C）之间的直接约束，然后把旧帧从图里移除。

---

### FEJ：边缘化的一个重要细节

边缘化在实际工程实现里有一个容易忽视但非常重要的问题，叫做**First Estimate Jacobian（FEJ，首次估计雅可比）**。

问题是这样的：边缘化时我们对被丢弃变量 xm 的雅可比，是在当前估计点处线性化得到的。之后每次迭代更新 xb 时，xb 的值会改变，但先验项 H~bbH~b 里"冻结"的那个线性化点没有更新。如果 xb 更新后我们重新在新的点处线性化先验项，会引入额外的不一致性，破坏系统的**可观性（Observability）**——在某些运动模式下，系统会"凭空"获得本来无法观测的信息（比如绝对姿态），导致估计值出现漂移。

FEJ 的解决方案很简单：先验项的雅可比**永远使用第一次边缘化时的线性化点**，不随后续迭代而更新。这确保了整个优化过程的线性化点保持一致，避免引入虚假的可观测性。VINS-Mono 的代码里有非常清晰的 FEJ 实现，是值得精读的工程范本。

---

### 路标点的边缘化：Schur 技巧

SLAM 里最常见的边缘化操作其实不是对位姿，而是对路标点。路标点的数量远多于位姿（通常多一到两个数量级），如果直接解整个正规方程会非常慢。但注意到路标点之间没有直接约束（每个路标点只和观测到它的那几帧位姿有边，路标点和路标点之间没有边），所以 Hmm（路标点块）是**分块对角矩阵**，求逆极其高效。

把所有路标点都边缘化掉，只保留位姿节点，得到的正规方程规模从"位姿+路标点"缩减到"只有位姿"，计算量大幅下降。这个技巧就是 BA 里经典的 **Schur 消元**，几乎所有实用的 BA 实现都用这个方法。g2o 里的 `setMarginalized(true)` 调用（你在上一章的代码里见过）正是触发了这个机制。

```cpp
// backend.cpp 核心逻辑（简化版，帮助你理解结构）

void Backend::Optimize(Map::KeyframesType& keyframes,
                       Map::LandmarksType& landmarks) {
    // 构建 g2o 优化问题（和第六章一样的套路）
    typedef g2o::BlockSolver_6_3 BlockSolverType;
    typedef g2o::LinearSolverCSparse<BlockSolverType::PoseMatrixType>
        LinearSolverType;
    // 注意这里用的是 CSparse 而不是 Dense
    // CSparse 专门利用稀疏矩阵结构，处理大规模问题时比 Dense 快几个数量级
    // 这正是前面说的"稀疏性让 BA 可以实时运行"的工程体现

    auto solver = new g2o::OptimizationAlgorithmLevenberg(
        g2o::make_unique<BlockSolverType>(
            g2o::make_unique<LinearSolverType>()));
    g2o::SparseOptimizer optimizer;
    optimizer.setAlgorithm(solver);

    // 只把滑动窗口内的关键帧加入优化
    // 注意：不是所有帧，而是最近的 N 个关键帧（N 通常是 7 到 10）
    std::map<unsigned long, VertexPose*> vertices;
    unsigned long max_kf_id = 0;
    for (auto& keyframe : keyframes) {
        auto kf = keyframe.second;
        auto vertex = new VertexPose();
        vertex->setId(kf->keyframe_id_);
        vertex->setEstimate(kf->Pose());
        optimizer.addVertex(vertex);
        max_kf_id = std::max(max_kf_id, kf->keyframe_id_);
        vertices.insert({kf->keyframe_id_, vertex});
    }

    // 遍历所有在窗口内被观测到的路标点
    std::map<unsigned long, VertexXYZ*> vertices_landmarks;
    for (auto& landmark : landmarks) {
        auto lm = landmark.second;
        // 检查这个路标点是否被窗口内至少一个关键帧观测到
        // 如果只被窗口外的旧帧看到，它对当前优化没有贡献，跳过
        bool has_active_obs = false;
        for (auto& obs : lm->GetObs()) {
            if (obs.lock()->keyframe_.lock()->IsActive()) {
                has_active_obs = true;
                break;
            }
        if (!has_active_obs) continue;

        auto vertex = new VertexXYZ();
        vertex->setEstimate(lm->Pos());
        vertex->setId(lm->id_ + max_kf_id + 1);
        vertex->setMarginalized(true);  // 触发 Schur 消元，路标点被边缘化
        optimizer.addVertex(vertex);
        vertices_landmarks.insert({lm->id_, vertex});

        // 为这个路标点的每个观测添加重投影误差边
        for (auto& obs : lm->GetObs()) {
            auto feat = obs.lock();
            if (feat->is_outlier_) continue;  // 跳过已被标记为外点的观测
            auto kf = feat->keyframe_.lock();
            if (!kf || !kf->IsActive()) continue;

            auto edge = new EdgeProjection(kf->camera_->K(),
                                           kf->camera_->Pose());
            edge->setVertex(0, vertices.at(kf->keyframe_id_));
            edge->setVertex(1, vertices_landmarks.at(lm->id_));
            edge->setMeasurement(feat->position_.pt.cast<double>());
            edge->setInformation(Eigen::Matrix2d::Identity());

            // 鲁棒核函数：Huber 损失
            // 对残差小的观测用普通最小二乘，对残差大的观测（可能是误匹配）
            // 自动降低其权重，避免少数外点主导优化结果
            // 这比上一章用的普通最小二乘更鲁棒
            auto rk = new g2o::RobustKernelHuber();
            rk->setDelta(chi2_th);  // chi2_th 是判断是否为外点的阈值
            edge->setRobustKernel(rk);

            optimizer.addEdge(edge);
        }

    // 运行优化
    optimizer.initializeOptimization();
    optimizer.optimize(10);

    // 把优化结果写回关键帧和路标点
    for (auto& v : vertices) {
        keyframes.at(v.first)->SetPose(v.second->estimate());
    }
    for (auto& v : vertices_landmarks) {
        landmarks.at(v.first)->SetPos(v.second->estimate().cast<double>());
    }
```

这段代码里有一个细节值得专门说一下：`g2o::RobustKernelHuber`。在第六章我们用的是普通最小二乘，对所有观测一视同仁。但现实里特征匹配不可避免地有残余误匹配，这些误匹配对应的重投影误差非常大，在普通最小二乘里它们会对 H 矩阵贡献极大的权重，把整个优化结果拉偏。Huber 核函数是一个鲁棒的损失函数，当残差小于阈值时等同于普通最小二乘，当残差超过阈值时自动切换为线性增长，大幅削弱大残差点的影响。这是让 BA 在真实数据上稳定工作的关键工程细节之一。

### 这一章最值得思考的问题

学完边缘化之后，有一个值得停下来想一想的深层问题：为什么不把所有历史帧都保留下来，用完整的全局 BA 给出最精确的结果？

答案不只是"计算量太大"这么简单。更深的原因是：SLAM 系统运行在一个**在线（online）**的环境里，机器人必须以实时的速度响应新的传感器数据。如果后端优化用了 5 秒，前端的图像已经积压了 150 帧没有处理，系统就完全失去了实时性。滑动窗口和边缘化是在"优化精度"和"计算实时性"之间找到平衡点的工程手段，而这种取舍贯穿了所有工业级 SLAM 系统的设计。
