## 第十章：回环检测——闭合漂移的最后一环

前九章我们建立了一个能实时运行的视觉里程计系统，但它有一个无法回避的缺陷：误差会随时间单向积累。机器人绕一圈回到起点，轨迹的终点和起点之间会有一个明显的缺口。回环检测就是识别出"我回来了"这个事件，然后触发全局优化把这个缺口闭合掉。这一章我们把这个机制从原理到代码完整走一遍。

---

### 问题的本质：图像检索

回环检测在数学上是一个**图像检索（Image Retrieval）**问题：给定当前帧图像，在历史所有帧构成的数据库里，找到视觉上最相似的那一帧，并判断相似程度是否足以确认"这是同一个地方"。

最直觉的做法是把当前帧的所有特征描述子，和历史每一帧的描述子逐一比较，找相似度最高的。这个方法绝对准确，但代价是灾难性的——如果历史帧有一万帧，每帧有五百个描述子，每次检索就需要做五百万次描述子比较，根本无法实时运行。

我们需要一种能在毫秒级完成检索的方法。这正是**词袋模型（Bag of Words，BoW）**的动机。

---

### 词袋模型：把图像变成向量

词袋模型的核心思想来自自然语言处理。想象你要比较两篇文章的内容相似度，最简单的方法不是逐字比较，而是统计每篇文章里各个词出现的频率，得到一个词频向量，然后比较两个向量的相似度。两篇都大量提到"机器人"、"传感器"、"算法"的文章，词频向量很接近，内容大概率相关。

BoW 把同样的思路搬到图像上。"词"对应**视觉单词（Visual Word）**——把大量图像的特征描述子用 K-means 聚类，每个聚类中心就是一个视觉单词，所有视觉单词构成**视觉词典（Visual Vocabulary）**。对一张新图像，先提取特征描述子，然后把每个描述子"量化"到最近的视觉单词，统计每个单词出现的次数，得到一个词频向量。比较两张图像，就变成了比较两个词频向量的相似度，这个操作极其高效。

但有一个细节值得认真想：不是所有视觉单词都同等重要。一个在几乎所有图像里都出现的单词（比如某种常见的纹理），对区分不同图像没有贡献；一个只在少数图像里出现的单词，区分度极高。这个直觉催生了 **TF-IDF 权重**：某个单词在当前图像里出现越频繁（TF，词频），权重越高；它在整个数据库里越罕见（IDF，逆文档频率），权重也越高。词频向量里每个维度的值，是这个单词的 TF-IDF 加权词频，而不是原始的计数。

---

### 词汇树：让检索更快

实际系统里视觉词典通常有几万到几十万个视觉单词。把一个描述子量化到最近的视觉单词，需要和所有单词比距离，如果词典有十万个单词，每帧五百个描述子，每次量化就要做五千万次距离计算，仍然太慢。

解决方案是用**词汇树（Vocabulary Tree）**代替平铺的词典。词汇树是一棵 K 叉树：根节点代表所有描述子，每个节点用 K-means 聚成 K 个子节点，递归地分裂到叶子节点，每个叶子就是一个视觉单词。量化一个描述子时，从根节点出发，每层只需要和 K 个子节点比距离，选最近的那个往下走，总共只需要 O(K⋅L) 次比较（L 是树的深度），而不是 O(N)（N 是单词总数）。对于 K=10、L=6 的词汇树，总单词数是 106=100 万，但量化一个描述子只需要约 60 次距离比较，速度提升几万倍。

DBoW2 就是基于词汇树的 BoW 实现，ORB-SLAM3 里用的词典 `ORBvoc.txt` 就是一个预训练好的 DBoW2 词汇树，用海量真实图像的 ORB 描述子训练得到，下载下来直接用不需要自己训练。

---

### 回环检测的完整流程

理解了 BoW 之后，整个回环检测的流程就很清晰了，分四个步骤。

第一步是**图像转化为 BoW 向量**。每来一个新的关键帧，提取 ORB 特征，用词汇树把每个描述子量化到视觉单词，得到 TF-IDF 加权的词频向量，存入数据库。

第二步是**候选帧检索**。查询数据库，找出词频向量相似度最高的若干历史帧作为候选。相似度通常用 L1 范数或余弦相似度度量。DBoW2 还做了一个重要的工程优化：它用倒排索引（inverted index），对每个视觉单词维护一个"包含该单词的所有图像"列表，查询时只需要对当前帧的单词列表取并集，大幅加速候选帧筛选。

第三步是**几何验证**。BoW 相似度高不代表真的是同一个地方，光照变化、动态物体都可能造成误报。几何验证是对候选帧做完整的特征匹配和位姿估计（用 RANSAC + 本质矩阵或 PnP），如果能找到足够多的内点，才真正确认为回环。几何验证的计算量比 BoW 检索大很多，但只对少数候选帧执行，所以整体代价可以接受。

第四步是**全局位姿图优化**。确认回环后，把这条长程约束加入位姿图，触发一次全局优化，把漂移沿整条轨迹平摊掉。这个过程和第九章的 BA 用的是同样的 g2o 框架，区别在于这次优化的是整条历史轨迹而不只是滑动窗口。

---

### 一个容易忽视的陷阱：时间一致性检验

BoW 检索有一个著名的问题：在机器人还没走远的时候，相邻帧的图像内容和当前帧非常相似（因为场景几乎没变），会出现大量的"伪回环"——系统以为自己回到了某个历史位置，其实只是几秒前刚刚经过的地方。

解决这个问题的标准方法是**时间一致性检验**：要求在连续若干帧里都能检测到同一个历史位置，才确认为真正的回环。单帧的相似性匹配很容易误报，但如果连续 5 帧都指向同一个历史帧作为最近邻，误报的概率就极低了。ORB-SLAM3 把这个连续性要求设为 3 帧，VINS-Mono 设为更严格的 10 帧，可以根据场景调整。

### 动手：用 DBoW2 做图像检索

进入书的第十一章目录（书里回环检测的代码在第十一章），先安装 DBoW2：

```bash
# DBoW2 是 ORB-SLAM3 的子模块，也可以单独编译
cd ~ && git clone https://github.com/dorian3d/DBoW2.git
cd DBoW2 && mkdir build && cd build
cmake ..
make -j$(nproc)
sudo make install
```

然后看书里的核心实验，它展示了词袋检索的完整流程：

```cpp
#include <DBoW2/DBoW2.h>
#include <opencv2/opencv.hpp>

// DBoW2 的模板参数指定了描述子类型
// OrbVocabulary 是 DBoW2 为 ORB 描述子预定义的词汇树类型
typedef DBoW2::TemplatedVocabulary<DBoW2::FORB::TDescriptor,
                                    DBoW2::FORB> OrbVocabulary;
typedef DBoW2::TemplatedDatabase<DBoW2::FORB::TDescriptor,
                                  DBoW2::FORB> OrbDatabase;

int main() {
    // 加载预训练词典，这个文件是 ORB-SLAM3 附带的
    // 加载时间较长（约 10 秒），因为词典有几十万个节点
    OrbVocabulary voc;
    voc.loadFromTextFile("ORBvoc.txt");
    std::cout << "词典加载完成，单词数量: " << voc.size() << std::endl;

    // 创建图像数据库
    // 第二个参数 true 表示使用直接索引（用于后续几何验证时快速找对应特征点）
    // 第三个参数 4 是直接索引的层级（词汇树的第几层）
    OrbDatabase db(voc, true, 4);

    // 读取一系列图像，提取 ORB 特征，加入数据库
    cv::Ptr<cv::ORB> orb = cv::ORB::create(500);
    std::vector<std::string> image_paths = {
        "1.png", "2.png", "3.png", /* ... */
    };

    for (size_t i = 0; i < image_paths.size(); i++) {
        cv::Mat img = cv::imread(image_paths[i], cv::IMREAD_GRAYSCALE);
        std::vector<cv::KeyPoint> kps;
        cv::Mat desc;
        orb->detectAndCompute(img, nullptr, kps, desc);

        // 把描述子转成 DBoW2 需要的格式（每行一个描述子的 vector）
        std::vector<cv::Mat> descriptors;
        for (int j = 0; j < desc.rows; j++)
            descriptors.push_back(desc.row(j));

        // 加入数据库，返回这张图像在数据库里的 ID
        db.add(descriptors);
        std::cout << "图像 " << i << " 已加入数据库" << std::endl;
    }

    // 用最后一张图像做查询，模拟"当前帧检索历史帧"
    cv::Mat query_img = cv::imread(image_paths.back(), cv::IMREAD_GRAYSCALE);
    std::vector<cv::KeyPoint> kps;
    cv::Mat desc;
    orb->detectAndCompute(query_img, nullptr, kps, desc);

    std::vector<cv::Mat> query_desc;
    for (int j = 0; j < desc.rows; j++)
        query_desc.push_back(desc.row(j));

    // 查询数据库，返回相似度最高的若干帧
    DBoW2::QueryResults results;
    db.query(query_desc, results, 4);  // 返回最相似的 4 个结果

    // 输出检索结果
    // results[0] 是相似度最高的帧（通常是自身，如果查询图像也在数据库里）
    // results[1] 才是第二相似的，真正的回环候选
    for (auto& r : results) {
        std::cout << "图像 ID: " << r.Id
                  << "  相似度得分: " << r.Score << std::endl;
    }

    return 0;
}
```

运行这段代码，观察相似度得分的分布。你会发现一个有趣的现象：相邻帧之间的相似度通常在 0.05 到 0.1 之间，而真正的回环帧（场景相同的两帧）相似度会跳到 0.3 甚至更高。这个得分的跳变就是回环检测的信号，阈值的设置需要根据具体场景调整。

### 把回环检测接入完整系统

书的第十二章把回环检测接入了第九章的完整 SLAM 系统。核心逻辑在 `loop_closing.cpp` 里，结构是这样的：

```cpp
// loop_closing.cpp 核心逻辑（简化版）

void LoopClosing::Run() {
    while (running_) {
        // 等待前端送来新的关键帧
        // 回环检测线程和前端、后端是并行运行的
        // 前端负责实时跟踪，后端做局部 BA，回环检测在另一个线程慢慢检索
        if (HasNewKeyframe()) {
            auto kf = GetNewKeyframe();

            // 第一步：把当前关键帧转成 BoW 向量并查询数据库
            DetectLoop(kf);
        }

bool LoopClosing::DetectLoop(KeyFrame::Ptr kf) {
    // 计算当前帧的 BoW 向量
    kf->ComputeBoW(voc_);

    // 查询数据库
    DBoW2::QueryResults results;
    db_->query(kf->bow_vec_, results, 4);

    if (results.empty()) {
        db_->add(kf->bow_vec_);
        return false;
    }

    // 时间一致性检验：跳过太近的帧（可能是相邻帧而非真正的回环）
    // 只考虑至少 20 个关键帧之前的候选（确保机器人真的"走了一圈"）
    auto best_candidate = results[0];
    if (best_candidate.Id >= (int)kf->keyframe_id_ - 20) {
        db_->add(kf->bow_vec_);
        return false;
    }

    // 得分阈值检验
    if (best_candidate.Score < score_threshold_) {
        db_->add(kf->bow_vec_);
        return false;
    }

    // 通过初步筛选，进入几何验证
    auto loop_kf = map_->keyframes_.at(best_candidate.Id);
    return VerifyLoop(kf, loop_kf);
}

bool LoopClosing::VerifyLoop(KeyFrame::Ptr current_kf,
                              KeyFrame::Ptr loop_kf) {
    // 几何验证：在当前帧和候选回环帧之间做特征匹配
    // 用 BoW 的直接索引加速特征匹配（只匹配属于同一视觉单词的描述子对）
    std::vector<cv::DMatch> matches;
    MatchByBoW(current_kf, loop_kf, matches);

    // 如果匹配数太少，几何验证失败
    if (matches.size() < min_inliers_) return false;

    // 用 PnP + RANSAC 估计两帧之间的相对位姿
    // 内点数量是几何验证的关键指标
    Sophus::SE3d T_loop;
    int inliers = EstimatePose(current_kf, loop_kf, matches, T_loop);

    if (inliers < min_inliers_) return false;

    // 几何验证通过！触发全局位姿图优化
    CorrectLoop(current_kf, loop_kf, T_loop);
    return true;
}

void LoopClosing::CorrectLoop(KeyFrame::Ptr current_kf,
                               KeyFrame::Ptr loop_kf,
                               const Sophus::SE3d& T_loop) {
    // 把回环约束加入位姿图，触发全局 BA
    // 这个优化和第六章的 BA 用同样的 g2o 框架
    // 区别是这次优化所有历史关键帧，而不只是滑动窗口内的
    std::cout << "检测到回环！关键帧 "
              << current_kf->keyframe_id_ << " <-> "
              << loop_kf->keyframe_id_ << std::endl;

    // 全局位姿图优化...

    // 对应的路标点坐标也会跟着调整
```

### 这一章最值得深思的问题

回环检测有一个根本性的假设：同一个地方的图像应该相似。但这个假设在几种情况下会被打破，值得你提前想清楚。

**视角变化过大**是最常见的失败原因。如果机器人第一次经过某个地方是朝北走，第二次是朝南走，同一个场景的图像会截然不同，BoW 相似度会很低，回环检测失败。对这个问题，一种解决方案是存储多个视角下的描述子；另一种是用语义信息（比如"这里有一扇门"这样的抽象描述）来替代低级的视觉特征，语义信息对视角变化更鲁棒。

**场景动态变化**是另一个挑战。如果机器人一小时前路过某个地方，一小时后回来，场景里的人、车、光线都变了，BoW 相似度会大幅下降，但这确实是同一个地方。对这个问题，目前没有完美的解决方案，工程上通常靠增加词典规模和调低得分阈值来缓解。

这两个挑战指向了 SLAM 研究里一个重要的开放方向：**长期地图维护（Long-term Map Maintenance）**，也就是让地图在日夜交替、季节变换、动态场景中保持可用。这是目前学术界非常活跃的研究领域，也是自动驾驶落地面临的核心工程挑战之一。

### 第四层：你缺的部分

ORB此前已经很熟悉了，但第四层里还有几个重要内容你没有接触过。

**SIFT（Scale-Invariant Feature Transform）**是ORB的"前辈"，理解SIFT的设计思路比ORB更有教育意义，因为它把尺度不变性、旋转不变性的实现原理解释得最清楚。ORB很多设计决策都是在SIFT的基础上做的工程简化，知道SIFT你才能真正理解ORB"简化了什么、牺牲了什么"。

**光流（Optical Flow）**是你明显缺失的一块。光流估计的是图像中每个像素在相邻帧之间的运动向量场，是直接法视觉里程计的近亲，也是很多目标追踪算法的基础。Lucas-Kanade光流和直接法共享同一个光度一致性假设，理解光流能让你对直接法的理解更深一层。

**立体视觉（Stereo Vision）**我们在第六节简单提过视差公式，但没有深入讲半全局匹配（SGM）这类实用的稠密立体匹配算法，也没有讲极线约束在代码层面是怎么实现的。

### 第五层：你基本是空白的

深度学习视觉这一层你目前几乎没有接触，但它对现代机器人视觉越来越重要，尤其是语义理解和端到端的感知方案。这一层主要包含三个方向。

**目标检测**是最成熟的方向。YOLO系列（现在已经到YOLOv8）代表实时检测路线，Faster R-CNN代表精度优先路线。理解这两者的区别，本质上是理解"两阶段检测（先提候选区域再分类）"和"单阶段检测（一步到位）"这两种设计哲学的权衡。

**语义分割**是比目标检测更细粒度的感知，它给图像里每个像素打上类别标签（"这个像素属于地面"、"这个像素属于行人"）。对机器人导航来说，语义分割能让占据栅格地图不只知道"这里有障碍物"，还能知道"这个障碍物是一个人，可能会移动"。DeepLab和SegFormer是这个方向的代表。

**姿态估计**和SLAM的关系最直接。6D物体姿态估计（估计物体的三维位置和三维朝向）是机器人抓取的核心，PVNet和FoundPose是当前代表性方法。人体姿态估计（检测人体关键点）则是人机交互的基础。

---

### 一个你可能没意识到的空缺：点云处理

你在第六层学了SLAM，但点云处理我们只是浅浅提了一下Open3D和PCL的名字，没有真正深入。点云处理是一个独立的技能树，包括点云配准（ICP算法，让两片点云对齐）、点云分割（从点云里分离出不同物体）、法向量估计、体素降采样等。这些在机械臂抓取、三维重建、激光雷达SLAM里都是基本功。

### 建议的补全顺序

考虑到你的SLAM方向，我建议按这个优先级补全。首先补**光流和SIFT**，因为它们和此前已经学的内容关系最紧密，补完之后你对第四层会有完整的认识，而且理解光流能让你重新审视直接法，会有"原来如此"的顿悟感。其次补**深度学习视觉的基础**，至少把目标检测和语义分割的核心思路搞清楚，因为现代SLAM越来越多地融合语义信息（语义SLAM），这是你以后进阶必须跨过的门槛。最后补**点云处理**，这部分和你SLAM的知识结合得最自然，可以边做项目边学。
