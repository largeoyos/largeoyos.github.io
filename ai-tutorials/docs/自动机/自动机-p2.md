# 自动机学 · 第四节：正则语言的全貌——正则表达式与泵引理

## 一、先解答上节的练习题

上一节的 NFA，转移规则是：在 `q0` 读到 `b` 可以跳到 `q1`，在 `q1` 读到 `a` 跳到接受状态 `q2`。也就是说，机器在任意时刻读到 `b`，都可以"猜测"这个 `b` 是倒数第二个字符，然后期待下一个字符是 `a`，从而接受。

所以这个 NFA 识别的是：**所有倒数第二个字符是 `b` 的字符串**，比如 `"ba"`、`"aba"`、`"bbba"` 都被接受，而 `"ab"`、`"a"`、`"bb"` 被拒绝。这和上一节"倒数第二个字符是 `a`"的例子是完全对称的镜像，只是把角色换了一下。

## 二、正则表达式：你早就认识的老朋友

你可能在写代码时用过正则表达式——比如用 `\d+` 匹配数字，用 `[a-z]*` 匹配小写字母序列。但你也许不知道，正则表达式背后有一套严密的数学理论，而它与有限自动机有着深刻的联系。

在数学上，正则表达式（Regular Expression）是用来**描述语言**的一种符号系统。它由以下几种基本构件组成，通过递归地组合，可以描述各种复杂的语言。

最基础的构件有三种。第一是**单个符号**：正则表达式 `a` 描述只包含一个字符串 `"a"` 的语言。第二是**空串** `ε`：描述只包含空字符串的语言 `{ε}`。第三是**空语言** `∅`：描述不包含任何字符串的语言。

在基础构件之上，有三种组合操作。**并（Union）**：如果 R 和 S 是正则表达式，`R∪S`（有时写作 `R|S`）描述"属于 R 或属于 S"的所有字符串。**连接（Concatenation）**：`RS` 描述"先取 R 中的一个字符串，再连接 S 中的一个字符串"所得到的所有字符串。**克莱尼星（Kleene Star）**：`R*` 描述"把 R 中的字符串重复零次或任意多次"所得到的所有字符串，包括空串 `ε`。

举个例子，正则表达式 `(a∪b)*ab` 描述的就是"所有以 `ab` 结尾的字符串"——`(a∪b)*` 匹配任意长度的前缀，`ab` 匹配结尾。这正是我们在第二节构造过的那个 DFA 所识别的语言。

## 三、Kleene 定理：正则表达式与有限自动机是同一件事

现在来到这一节最核心的结论，它由数学家 Stephen Kleene 在 1950 年代证明，被称为 **Kleene 定理**：

> **一个语言是正则语言（即可被某个 DFA/NFA 识别），当且仅当它可以被某个正则表达式描述。**

这是一个双向的等价，意味着正则表达式和有限自动机**描述的是同一类语言**，只是两种不同的表达形式而已。正则表达式是**声明式**的——它描述语言"长什么样"；有限自动机是**过程式**的——它描述如何一步步识别语言。

这个定理的证明分两个方向。从正则表达式到 NFA 的方向，思路是对正则表达式的结构做归纳：基础构件（单个符号、ε、∅）各自对应一个简单的 NFA，而并、连接、Kleene 星三种操作，也各自有对应的 NFA 构造方式。比如两个 NFA 的"并"，就是加一个新的初始状态，用 ε-转移连接两个旧的初始状态，就像按下了一个"同时启动两台机器"的开关。

从 DFA 到正则表达式的方向则更有趣，思路是逐步"消除"DFA 中的状态，每次消除一个状态就把经过它的路径用正则表达式来替代，最终把整个自动机"压缩"成一个正则表达式。这个过程就像是在简化一张地图：每次把一个中转城市消掉，把经过它的路线直接合并成一条路。

Kleene 定理的实践意义非常直接：你在代码里写的每一个正则表达式，背后都对应一个有限自动机，正则引擎在匹配时，实际上就是在模拟这台自动机的运行。理解了这一点，你就能更好地预测正则表达式的性能，甚至解释为什么某些正则表达式会导致所谓的"灾难性回溯"问题。

## 四、正则语言的封闭性

在继续之前，有一个重要的性质值得一提：**正则语言在多种运算下是封闭的**。

所谓"在某种运算下封闭"，意思是：对正则语言做这种运算，结果仍然是正则语言。正则语言在以下运算下都是封闭的：并（两个正则语言的并集还是正则）、连接（两个正则语言的连接还是正则）、Kleene 星（一个正则语言的星还是正则）、补集（一个正则语言的补集还是正则）、交集（两个正则语言的交集还是正则）。

补集的封闭性特别值得说明一下：要构造语言 L 的补集对应的 DFA，只需要把原来 DFA 的接受状态和非接受状态互换即可。这是因为 DFA 对任意字符串都会给出明确的"接受"或"拒绝"，互换之后，原来被拒绝的都变成接受，原来被接受的都变成拒绝，恰好就是补集。这个操作对 NFA 不能直接使用（原因值得你思考一下）。

## 五、泵引理：正则语言的边界

我们已经知道正则语言能做什么，现在来研究它**不能做什么**。

有一类语言是有限自动机天生无法识别的。最直觉的例子就是上一节提到的 `{ aⁿbⁿ | n ≥ 0 }`，即 n 个 a 后跟 n 个 b 的语言。要识别这个语言，机器必须"数清楚"a 的个数，然后验证 b 的个数与之相等。但 n 可以是任意大的数，而有限自动机的状态数是固定的——它没有足够的"记忆空间"来记住任意大的 n。

为了把这个直觉变成严格的数学证明，我们需要**泵引理（Pumping Lemma）**。

泵引理的内容如下：如果语言 L 是正则语言，那么存在一个正整数 p（称为**泵长度**），使得 L 中任意长度不小于 p 的字符串 w，都可以被分成三段 `w = xyz`，满足以下三个条件：第一，`|xy| ≤ p`（前两段合起来不超过 p 个字符）；第二，`|y| ≥ 1`（中间那段 y 不为空）；第三，对所有 `k ≥ 0`，字符串 `xy^kz` 都属于 L（把 y 重复 k 次，结果仍然在 L 中）。

第三个条件就是"泵"的含义——y 这一段可以被任意"抽吸"（重复），而结果仍然合法。

**为什么这是对的？** 直觉非常清晰。假设 DFA 有 p 个状态，那么它在读入一个长度为 p 的字符串时，要经过 p+1 个状态（包括初始状态）。由鸽巢原理，p+1 个状态中必然有两个是相同的，也就是说，DFA 在读这段字符串的过程中必然经历了一个**循环**。这个循环对应的就是 y 那一段——循环走零次、一次或任意多次，DFA 最终都会到达相同的状态，因此结论是否定相同的。

---

## 六、用泵引理证明语言不是正则的

泵引理的使用方式是**反证法**：假设 L 是正则语言，那么泵引理的条件必然成立；然后我们找到一个具体的字符串，证明无论怎么分成 xyz，都无法同时满足三个条件，从而推出矛盾，得出 L 不是正则语言的结论。

我们来完整地证明 `L = { aⁿbⁿ | n ≥ 0 }` 不是正则语言。

假设 L 是正则语言，设泵长度为 p。我们选取字符串 `w = aᵖbᵖ`，它的长度是 `2p ≥ p`，所以满足泵引理的前提条件。根据泵引理，w 可以被分成 `xyz`，且 `|xy| ≤ p`，`|y| ≥ 1`。

由于 `|xy| ≤ p`，而 w 的前 p 个字符全是 a，所以 xy 这一段完全落在 a 区域里，因此 y 必然是若干个连续的 a，设 y = `aᵐ`，其中 `m ≥ 1`。

现在根据泵引理，`xy²z`（把 y 重复两次）应该仍然属于 L。但 `xy²z` 包含了 `p + m` 个 a，以及 p 个 b，而 `m ≥ 1`，所以 a 的数量严格大于 b 的数量，这个字符串**不属于** L。矛盾！

所以 L 不是正则语言，有限自动机无法识别它。证明完毕。

这个证明的精妙之处在于：泵引理的条件 `|xy| ≤ p` 强制 y 只能落在 a 区域里，而"泵"这段 a 之后，a 和 b 的数量就失去了平衡。这正是语言本质的体现——有限自动机无法同时追踪两个任意大的计数。

---

## 七、正则语言的全貌

到这里，我们可以为正则语言画出一幅完整的画像了。正则语言是由正则表达式描述的、由有限自动机（DFA 或 NFA）识别的一类语言，它在并、交、补、连接、Kleene 星等运算下封闭，但它无法描述任何需要"无界计数"或"配对匹配"的语言。

这类语言足够强大，可以描述词法结构（标识符、数字、关键字），这正是为什么所有编译器的词法分析阶段都使用正则表达式和有限自动机。但它又足够有限，无法描述语法结构（括号嵌套、函数调用的配对），这正是为什么语法分析需要更强的工具。

这个边界不是工程上的限制，而是数学上的必然。有限的状态，就意味着有限的记忆，而有些问题天生需要无界的记忆。
