论文讲解全文整理提示词

当我听完一篇论文的讲解后，只要我说“整理它”“整理他”“整理这篇论文”“把刚才的讲解整理成文件”，请执行本提示词，将你围绕当前论文已经给出的讲解全文整理为本地文件。

整理的对象是已经实际讲过的全部内容。必须保留讲解全文，不能用摘要、提纲或重新撰写的简短报告代替。

一 触发与论文识别

  1. 根据当前聊天、论文文件和阅读记录确定整理对象。当前论文明确时，直接执行，不再询问是否需要整理。
  2. 本指令适用于略读、精读，以及同一篇论文在两种模式之间切换后的全部讲解。
  3. 包括最初讲解、后续追问的补充解释、重新推导、例子、纠错和最终讨论；不能只整理最近一轮回复。
  4. 用户明确指定某篇论文或某个章节时，以指定范围为准。确有多篇论文且无法判断指代时，只询问需要整理哪一篇，并先核对现有材料。
  5. 用户是在讨论、修改或创建本提示词，或要求“整理项目文档”时，不触发论文讲解导出。

二 收集已经讲解的全部内容

优先检查当前聊天的相关历史、该论文的阅读记录、已保存的逐轮讲解与章节文件。必要时，通过可用的聊天历史工具或当前聊天对应的本地会话记录找回原始讲解；仅查阅与指定论文有关的材料。

日常阅读时使用项目内的 paper-reading 技能，每轮讲解及实质性答疑都保存完整正文，并在阅读记录的“完整讲解文件清单”中登记。整理时先核对这份清单，再补查相关历史；不能只根据进度摘要重写正文。本整理流程由项目内的 paper-lecture-export 技能执行。

按实际讲解顺序建立来源清单，记录每轮或每份文件的可核实定位、讨论范围及是否已收录。短回复、公式补充、图表解释和答疑也要收集，不得用字符长度、某个关键词或图示文件名作为筛选全部讲解的唯一条件。

同一回复的不同存储副本可以去重，并注明对应关系；不同轮次中的重复解释仍应保留，不能因为主题相同就删去其中一轮。

如果历史上下文不完整，先尝试从现有文件与可访问记录中恢复。仍无法恢复时，保存能够核实的内容，在文件中明确标注“已获取讲解汇编，历史内容存在缺口”，列出缺失范围与待补材料；交付时说明该缺口。不得凭记忆或重新推演补写缺失内容后声称是原来的讲解全文。

三 全文保留要求

凡已实际讲解且属于本篇论文的内容，均应收录，包括：

  • 论文基本信息、研究背景、研究动机、研究问题和核心 Idea。
  • 已展示的英文原文、对应中文翻译，以及逐段深入讲解。
  • 关键术语、前置知识、教材与课程建议，以及相关论文说明。
  • 公式、符号定义、成立假设、逐步推导、数学直觉与数值例子。
  • 模型结构、技术流程、伪代码、算法步骤与实现细节。
  • 图片、表格、算法及其逐项解释。
  • 实验目的、设置、Baseline、指标、结果、消融与证据评价。
  • 创新点、技术权衡、局限性、复现建议与后续研究方向。
  • 用户围绕论文提出的问题所引出的答疑、类比、补充推导与纠错。
  • 各小节总结、理解检查、全文总结及阅读进度。

忠实保留原有表述、推理层次与例子，不以“篇幅太长”“前面已经解释过”或“只保留重点”为由压缩。不得把推导改成只列最后公式，不得把图表分析改成一句结论，不得把多个不同解释合并后丢失细节。

只删除与论文无关的工具执行日志、操作等待通知和纯操作性文字。需要用户问题才能理解的回答，应保留相关问题或准确的问题背景；不混入无关私人信息。

四 内容组织与勘误

主文按照实际讲解顺序排列，给每一轮或每个独立讲解单元设置清晰标题与来源定位。前面增加按论文主题或章节组织的导航目录，让同一章节的主讲与后续答疑可以相互跳转，避免为重新排序而打乱推导前提。

精读段落继续采用“英文原文 → 中文翻译 → 必要讲解”的结构；略读内容保留其原有分析结构。模式切换、局部精读和后续专题答疑应标明范围。

允许统一标题层级、字体样式、公式排版、图表编号引用及目录链接。聊天中的“你下一条回答”之类交互措辞原则上保留在相应练习或答疑背景中；确需改为独立讲义表达时，仅调整交互措辞，并在整理说明中注明，不改变知识内容与问题本身。

已有纠错必须保留原问题与纠正内容的对应关系。在已知错误处加醒目的勘误提示，链接到正确解释；不能将已被纠正的表述继续当作有效结论，也不能静默改写而丢失纠错过程。整理时新发现的问题标为“整理时核对发现”，与当时的讲解区分。

“论文事实”“作者主张”“独立分析”“合理推测”“待验证问题”的界限必须保留。自行构造的例子、补充推导和改进设想不能被整理成作者报告的实验或结论。

五 公式 图表与来源

  1. Markdown 保留可编辑的 LaTeX 公式；核对变量、上下标、条件、公式编号和推导顺序。
  2. HTML 正确渲染公式，优先将渲染结果或所需资源保存在本地，避免断网后出现空白公式。
  3. 已讲解的原论文图表应嵌入对应位置，标明原始编号、图注和所在页码；补充示意图标明是讲解辅助内容。
  4. 交互图示保留可用的交互；打印时提供能够覆盖重要状态的静态内容。无法保留时，明确说明缺失状态，不能只留下失效占位符。
  5. 本地图像与资源放在输出文件旁的资源子目录，使用相对路径，确保整组文件复制后仍能阅读；不改动论文原文件。
  6. 保留已有引用编号、来源链接与学习资源。聊天专有引用标记应转换为可核实的论文页码、章节、公式、图表或来源链接，不能笼统替换为论文名称而丢失定位。
  7. 找不到的图表、资源和出处明确列为缺失或待核实，不生成貌似原始内容的替代品。

六 输出文件

默认在当前论文所在目录创建：

<论文标识>_讲解全文.md
<论文标识>_讲解全文.html
<论文标识>_讲解资源/

资源目录仅在确有资源时创建。Markdown 是可编辑的正文，HTML 根据同一份正文生成，提供目录、章节锚点、便于长文阅读的排版与打印样式。两份文件的实质内容必须一致。

用户明确指定其他格式或输出位置时，遵循其要求。内容很长时，通过文件写入完成，不受单次聊天回复篇幅限制；默认仍保留一份包含全文的主文件。若另外提供逐章节文件，主文件或总入口必须完整覆盖所有章节，并保证链接有效。

已有同名整理结果时，先读取并核对来源，再合并后续新增讲解。保留旧版本或生成清晰标识的新版本，不覆盖手工批注，不重复收录同一来源。核对完成后再更新主要阅读入口。

七 文件结构

按以下结构组织，正文部分必须包含实际讲解全文：

  1. 论文与整理范围：论文身份、材料版本、实际讲解范围、整理时间，以及是否存在历史缺口。
  2. 导航目录：按论文章节或主题链接到对应主讲、补充解释与答疑。
  3. 讲解全文：按照实际讲解顺序完整收录各轮内容。
  4. 答疑与勘误索引：链接到正文中已经收录的相关问题和纠正内容，不用索引替代正文。
  5. 术语与公式索引：根据已有讲解建立定位，不能用简短索引替代已有解释或推导。
  6. 来源与收录核对表：逐项记录收集到的讲解来源、正文位置、收录状态，以及任何缺口或编辑调整。

索引和整理说明属于辅助内容，不能挤占、取代或缩减讲解全文。

八 完整性核对与交付

交付前逐项核对：

  • 来源清单中的每一轮讲解与补充答疑均能对应到输出位置；短回复同样纳入核对。
  • 对照原始讲解检查正文、列表、公式、例子、表格、图注与引用，不仅比较段落 ID、文件大小或总字数。
  • 对排版转换后可比较的文本进行内容核对；对公式、图表和交互内容单独核对。去重、勘误与交互措辞调整均有记录。
  • Markdown 与 HTML 的实质内容一致，图像可访问，章节链接与目录锚点有效，公式无明显渲染错误。
  • 整理范围与实际阅读进度一致。“已讲解内容全部收录”不等于“整篇论文已经读完”，不得把未读章节自动标为完成。

整理过程中如需读取原论文，可用于核对已有讲解的定位与内容；不要自动补讲尚未读过的章节来凑成全文。新补充内容确有必要时，应单独标为整理时新增，不能混充历史讲解。

完成后直接给出可点击的文件链接，简要说明覆盖范围、核对情况，以及是否仍有缺口。聊天中的交付说明保持简短，详细讲解全部放入文件。

最终要求：当我说“整理它”或“整理他”时，我要拿到的是你此前围绕这篇论文讲过的完整内容，能够离开聊天记录独立阅读，并保留原来的推理深度与细节。
