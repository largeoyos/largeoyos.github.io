DCVC-FM：质量范围与参考传播为何要一起处理

依据：本地 reference/papers/DCVC-FM.pdf，重点为 §3.2、§3.3、Fig.3/5 和 §4.3；源码为固定提交 cbdae87a 中的 DCVC-family/DCVC-FM/src/models/video_model.py。这是方法与消融精读，不冒称已经重现全部训练或论文数据集结果。

量化控制的本质是让整个表示适应质量

单纯把同一潜变量除以不同步长，虽然能改变码率，却不保证网络在整个质量范围内都适用。FM 同时考虑按用户质量参数控制的全局增益，以及由熵模型给出的空间、通道相关局部控制。

把论文的指数插值写成几何插值更直观：当 α=q/63，s(q)=s_min^(1−α) × s_max^α。它让线性变化的质量参数对应乘法尺度上的平滑变化。训练损失的 λ 也按同类公式从端点插值，并均匀采样整数 q；均匀的是 q，也就是 log λ 轴上的位置，不是在线性 λ 轴均匀抽样。

这意味着不同质量等级不仅在推理时被“试一下”，而是在训练时都参与表示与增益的共同学习。编码端和解码端的全局参数分别学习；在非线性潜变量网络中，它们没有必须互为倒数的约束。判断代码中的量化方向，要沿着乘法、除法和最终取整位置追踪，不能直接套传统 QP 数字越大步长越大的习惯。

局部控制与全局控制回答不同问题：前者分配当前内容中各处的表示精度，后者切换整套网络的质量工作范围。它们都依赖双方可获得的信息，不能把原图上独有的统计偷偷送给解码器。

刷新处理的是传播状态，不是强制插入新 I 帧

FM 的参考分支通常从上一帧传播特征提取上下文。刷新时改从上一帧的重建图像提取，使网络重新建立较受约束的参考状态。它仍使用重建图，所以之前的像素误差不会被神奇清零，也不会产生独立随机访问点。

长序列训练与刷新互补：前者让模型见过较长的状态链，后者在推理中改变状态链的组织方式。若只训练很短的片段，再在几百帧序列上递归使用，分布失配和传播误差可能被放大。

本轮在 RT 上做的刷新实验，与这里的机制动机相通，但不是 FM 的直接复现。要声称复现 FM，还要使用其模型、权重、训练/推理结构与对应配置。

消融表应怎样解释

论文逐步加入结构调整、宽质量范围、通用色彩支持、长序列训练和刷新。某些实用功能会先付出压缩效率代价，后续训练与参考机制再带来收益；不能把最终提升全部归到题目中的一个词。

所有相对同一 anchor 的百分数，需要保留其评价区间和协议。两个 BD-rate 数字相差若干“百分点”，不等于后一模块相对前一个模型恰好节省同样百分比；严谨的模块收益要在共同质量区间重新比较。

论文还显示，较低 MACs 不一定带来较短实际 FP32 时间。卷积类型、计算密度和实现都会影响耗时。其低精度结果也依赖特定优化，不能只把 dtype 改为 half 就保证相同压缩性能。

由此产生的实验问题

RT 的 Life 四档刷新 RD 已完成。在该片段的共同质量范围中，reset64 相对关闭刷新节省码率；reset32 相对 reset64 反而需要更多码率。同 q 的总码率也不是始终增加：q63 的 reset64 比关闭刷新略低。详见 第二轮实测。随后已完成 自然视频四档对照 与 七点加密检查：Ducks/Station2 的七点 PSNR-Y reset32/64 BD-rate 为 +0.85%/+9.36%，相对四点变化 −0.14/+0.35 个百分点，当前排序未翻转。这些是 RT 的测量，不能直接解释成 FM 的同模块收益。

2026-10-17 补读附录：作者以关闭刷新为基准，测试周期 8/16/32/64/96，平均结果以 32 最好，并明确指出不同内容的最佳周期可能不同。这个作者平均结论与当前 RT 单段 Life 中 64 优于 32 并不矛盾：模型、内容和评价区间都不同。

固定源码的 parser 已核查：FM 使用 --q_indexes_i/--q_indexes_p，默认刷新周期 32、--float16 false；真实码流需要编译 MLCodec_rans，半精度还涉及自定义 warp。后续用独立源码/环境，先以 FP32 跑 12 帧、四个质量索引，检查实际写流、独立解码和评分，再扩大范围。不能直接沿用 RT 的 --qp_i/--qp_p 参数。

附录的码率控制器根据缓冲偏差调整质量索引，且只在相应的隔帧位置更新；码率超额时降低索引。它说明宽质量范围能承接码控，但不证明任意网络条件下都能严格达到目标码率。具体检查点质量端点与完整实测仍待复现。

FM 传播了哪些状态

固定代码中的 DPB 保存上一帧的重建图 ref_frame、重建特征 ref_feature、运动特征 ref_mv_feature、内容潜变量 ref_y 和运动潜变量 ref_mv_y。这些状态分别参与光流估计、上下文生成和概率预测，不能把“参考”理解为一张图。

周期刷新只把 ref_feature 设为 None。下一次上下文提取因此调用 feature_adaptor_I(ref_frame)，运动特征和两个潜变量参考继续传播。ref_y 仍进入内容概率参数融合，ref_mv_y 仍进入运动概率参数融合。由此可知，特征刷新仍依赖预测链；它不会把全部误差和历史状态清空。状态读取与上下文生成源码

真实码流的刷新 P 帧用 SPS 中的 fa_idx=3 通知解码端清理同一特征；普通 P 帧用 0/1/2 选择特征适配器。SPS 还带尺寸与六位质量索引。这个信令使接收方从共享信息恢复相同分支，编码器不能单方面改变参考策略。写流与读流源码

FM 与 RT 的分层质量也不能按参数名类推。FM 真实流中的 SPS q 保持基本索引，0/1/2 的变化体现在特征适配器；本次 RT 实测则按帧把基本索引加 0/8/4。跨模型“相同 q”不等于相同质量、码率或同一套分层控制，仍应比较 RD 曲线。

最小复现的判断条件

FM 官方 README 的示例显式采用 --force_intra_period 9999。该快照的逐帧判断直接计算 frame_idx % intra_period；把 RT 的 −1 原样搬过来，会令所有帧进入 I 帧分支。12 帧冒烟实验必须从实际码流检查 1I11P，不能只看程序正常结束。

默认真实写流路径对每帧重置熵编码器并写一个 I/P 包；读流循环重新建立 SPS 表和参考状态，逐帧比较编码、解码重建的加权 PSNR。这个检查可以发现解码分歧，但 PSNR 相等本身不是逐像素相等的证明。独立检查还需覆盖文件总字节、帧数、q 和特征适配器信号。默认写流路径

仓库 README 明确说明论文用估计熵计码率，真实文件另有开销。因此本项目首先跑实际码流，之后若对照论文数值，还需分别保留熵估计与实际字节口径。格式工具也支持多个 P 帧共用一个包；默认逐帧写流并未采用该分支，不能把格式能力当作默认执行行为。

FP32 作为初次复现基准。该快照的运动补偿在没有自定义 CUDA 模块时可回退到 grid_sample；回退函数也会把半精度输入临时转为 FP32。自定义 warp 影响实际速度与执行路径，并不是“缺少它就完全无法运行半精度”的充分依据。运动补偿回退代码
