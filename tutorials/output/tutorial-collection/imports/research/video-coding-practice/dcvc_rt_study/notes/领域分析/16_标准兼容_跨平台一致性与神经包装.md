# 16｜标准兼容、跨平台一致性与神经包装

2026-10-19。依据 Neural Wrapping 的选定正文、INTNET 的官方摘要及 NVC360 固定源码。INTNET 的全文下载受 403/验证页阻碍，**只讨论摘要明确支持的问题，不把它记为已读全文**。

## 1. 三种兼容需要分别验证

| 兼容性质 | 实际问题 | 不充分的证据 |
|---|---|---|
| 语法兼容 | 既有解码器能否解析这个字节流 | 网络结构长得类似、解码器权重固定 |
| 数值一致 | 不同设备是否生成相同离散概率和参考状态 | 相同随机种子、单机器 deterministic 标志 |
| 服务兼容 | 原有接收器能否达到预期画面和延迟 | 码流解析成功或能显示一幅图 |

一个标准 codec 外加神经后处理，可以保留标准流语法，却要求新接收器计算后处理才能达到优化质量。一个纯神经 codec 在同一 GPU 上闭环成功，也不说明不同硬件一定一致。

## 2. 为什么概率的微小差别可能比像素差别更危险

熵解码通过离散累积概率区间确定符号。若两端的整数 CDF 边界相差一个单位，某些码值就可能落入不同符号区间；此后上下文更新又会放大差异。不能用“浮点差只有很小误差”直接证明码流仍可解。

本轮构造的单区间例子：总频数 65536，编码端 A/B 边界为 32768，解码端为 32767，码值为 32767.5/65536。同一码值在编码端对应 A，在解码端对应 B。它只演示区间归属，不是完整算术编码器或实际 RT 跨设备失败测试。见[机制小实验](../../experiments/scope_expansion_20261019/机制小实验.md)。

INTNET 官方摘要明确讨论了浮点推理不一致对基于潜变量熵编码的影响，并提出整数网络路线。其官方出版页为 ICLR 2019；本轮没有获得论文全文，不进一步声称其整数范围、舍入、溢出和实现开销细节。[Google Research 官方摘要](https://research.google/pubs/integer-networks-for-data-compression-with-latent-variable-models/)

**工程推导：**真正的协议需要说明权重版本、输入颜色和尺寸、量化舍入、概率到整数 CDF 的映射、状态初始化、熵流分段及字节序。整数化也必须定义饱和、位宽和运算顺序，不能只把张量类型改成整数就称为标准化。

## 3. 固定源码观察：NVC360 如何携带上下文

本轮审读固定提交 `d5591e2c9ad67e30a0c80fe89749a4aa1450fc96` 的 10 份文件。流头写入帧数、宽高、位深、投影、质量、GOP、模型 ID 和模型文件的截断 SHA256 标识。解码器按流头寻找本地对应权重；**头中是标识，不是完整权重本身**。这降低误用不同模型的风险，但仍依赖接收端已持有可用模型。

编码控制器实际调用匹配解码，得到后续参考。该观察比仅看模型 `compress` 返回值更完整：不能发现返回图像某处未截断，就不看控制器而断言真正参考链不一致。确定性标志和种子设置也只是实现措施，不构成跨设备通过证明。[固定源码与行号记录](../../experiments/scope_expansion_20261019/NVC360_固定源码审读.md)

如果未来做跨设备实验，应区分：符号完全一致、熵解码成功、参考逐位一致、最终像素一致四级结果。还要交换码流方向（A 编码/B 解码和 B 编码/A 解码），避免只测各设备自行闭环。

## 4. Neural Wrapping：把神经网络放到传统 codec 两侧

作者使用神经预处理 P、标准编解码器 C 和神经后处理 O，形成 `x→P(x)→C→O→x̂`。标准 codec 提供成熟流语法，神经网络试图把内容变成更有利于给定感知目标和编码器的输入，再改善重建。它与直接替换熵编码、运动或变换的全神经路线具有不同部署约束。[Neural Wrapping，第 4–5 页](https://openaccess.thecvf.com/content/CVPR2025/papers/Khan_Perceptual_Video_Compression_with_Neural_Wrapping_CVPR_2025_paper.pdf)

难点是 C 通常不可直接反向传播。论文训练可微代理 M 来模仿真实 codec 的输出及码率，并随预处理分布变化继续更新。其一处关键形式可写成 `I_O=stopgrad(I_C−I_M)+I_M`：前向数值采用真实 codec 的结果，梯度则来自代理。这样减少“训练前向看到假重建”的问题，却不会自动使代理梯度准确。

**为什么输出接近还不够？**令 `C(x)=x`、`M(x)=x+0.001 sin(1000x)`，输出误差始终不超过 0.001，但导数误差可达 1。这个平滑函数反例证明两种准确性不等价；实际标准 codec 常为离散、分段行为，更不能凭输出误差直接给出梯度一致性保证。示例不代表论文代理实际达到或未达到这种误差。[数学例子及数值](../../experiments/scope_expansion_20261019/机制小实验.md)

## 5. 训练代理要和真实编码条件相连

论文分阶段拟合解码输出、建立概率/码率代理，并对码率做校准。预处理网络变化后，代理需要追踪新输入分布，否则优化可能利用代理的漏洞：预测上很省，实际编码却不省。可靠验证是定期使用真实 codec 编解码并计实际字节，同时比较代理预测误差，尤其检查被预处理改变最多的片段。

选读设置中，训练含小 GOP、低延迟的代理配置，而最终标准 codec 测试不统一限于低延迟，使用 96 帧、1080p、YUV420 8-bit 等条件，并比较 SVT-AV1/VVenC。不能把它与严格因果 DCVC 的所有差值都解释为网络结构优势；未来帧和标准编码器搜索预算需要另列。[Neural Wrapping，第 5–6、8 页](https://openaccess.thecvf.com/content/CVPR2025/papers/Khan_Perceptual_Video_Compression_with_Neural_Wrapping_CVPR_2025_paper.pdf)

其优化关注感知指标，并承认 PSNR 可能退步。因此应联合报告原始像素保真、感知、时间稳定和总计算，不用感知 RD 的一个改进数字概括所有质量维度。视频后处理还需检查时间不一致；逐帧更自然不必然减少闪烁。

## 6. 哪些问题值得实际验证

| 问题 | 小规模验证方式 | 成功标准 |
|---|---|---|
| 现有 RT 的跨执行路径一致性 | 固定短流，核对符号/CDF/参考/像素，各级分列 | 精确说明通过哪一级，不用 PSNR 相近代替符号一致 |
| 头信息是否足以发现错模型 | 独立解析、缺失模型/错误标识的明确失败 | 不悄悄用另一权重继续解码 |
| 包装代理是否可信 | 留出片段上比较实际 codec 和代理的率/重建误差 | 不用训练内误差证明部署泛化 |
| 包装方案是否值得部署 | 同标准配置与等待下比较 P+C+O 总时间和真实 RD | 后处理成本与新增模型一起报告 |

现有 RT 的精度诊断已经提供部分同机执行路径证据；它不是跨设备兼容实验。本轮仅完成源码与理论分析，不将新数学例子写进真实码流结果表。
