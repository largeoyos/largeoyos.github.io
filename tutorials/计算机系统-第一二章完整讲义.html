第1章 · 讲解单元 01—01

第一章的主线：信息怎样成为计算机可处理的对象

掌握要求：能把“信息—编码—程序—硬件”连成一句话。

为什么讲到这里：先建立整体位置；这里是理解框架，不是计算公式。

1 / 01先建立整章最重要的一句话

计算机用二进制编码保存信息，按照程序中的指令，控制硬件处理这些信息。

这句话里有四件事：

  • 信息：数字、文字、图像、声音等。
  • 编码：规定一串 0、1 代表什么。
  • 程序：规定先做什么、后做什么。
  • 硬件：真正执行存储、运算、输入输出的电路和设备。

第一章其实就在回答：

计算机从哪里来？有哪些部件？怎样用 0 和 1 表示信息？把计算机装进设备里，又是什么样子？

先抓住这条线，后面的名词就有地方放了。

1.1 计算机发展简史

掌握要求：会解释存储程序思想、摩尔定律，能按用途区分计算机类型。

为什么讲到这里：历史帮助解释今天的结构；器件代际、代表事件要认识，旧设备的重量、价格和市场数字不必逐项背。

1 / 02计算机发展简史：为什么要讲这一段？

这一段主要帮助你理解：今天计算机的组织方式，是围绕“怎样更方便地自动计算”逐渐形成的。

对本章计算题，它的直接作用很小；对理解“程序为什么也要放在存储器里”，有作用。

讲义前面的历史可以压缩为：

阶段或人物 做了什么 你需要记住什么
算筹、算盘 帮人计数和计算 计算工具早于电子计算机
帕斯卡、莱布尼茨 用机械装置实现计算 计算可以交给机器完成
巴贝奇 提出差分机、分析机等设计 开始探索更通用、可按步骤工作的计算机器
图灵 研究可计算性，提出图灵机模型 从理论上研究“什么能够按机械步骤计算”
ENIAC 早期具有代表性的通用电子数字计算机 电子电路显著提高计算速度
EDVAC 方案 系统阐述存储程序等思想 程序可以像数据一样放进存储器
EDSAC、LEO、UNIVAC 推动存储程序计算机走向实际使用和商业应用 计算机从实验装置发展为实际工具

图灵机是一个理论模型，这一章不需要你推演它的状态转移。它的意义是帮助人们严格研究计算过程，不能理解成“计算机能解决任何问题”。

讲义把 EDSAC 直接称为第一台存储程序式电子计算机，表述过于绝对。曼彻斯特大学的 Baby 已在 1948 年 6 月 21 日运行电子存储的程序；EDSAC 是随后非常重要的早期实用系统。这里知道发展关系即可。曼彻斯特大学历史资料

ENIAC 有多重、多少电子管、占多少平方米，这些数字用于说明早期计算机庞大、耗电。按本章习题，不需要把这些数字当计算公式背下来。

1 / 03“存储程序”到底解决了什么问题？【重点】

假设你要机器算：

(2+3)×4

机器需要知道：

  1. 先取出 2 和 3。
  2. 把它们相加。
  3. 再把结果乘以 4。
  4. 保存或者输出结果。

这些步骤就是程序的一部分。

如果每换一道题，都要重新接线、重新改机器内部连接，使用起来就很麻烦。

存储程序的办法是：

把表示操作步骤的指令也编码，和数据一起预先放进存储器。机器运行时，自动取出指令并执行。

因此，存储器里不只有“要算的数”，还有“告诉机器怎样算的指令”。

习题 1.1 可以这样回答：

冯·诺依曼型计算机主要由运算器、控制器、存储器、输入设备、输出设备五部分组成。其主要思想包括：

  • 使用二进制表示指令和数据。
  • 采用存储程序方式，将程序和数据存放在存储器中。
  • 控制器自动取出、解释并执行指令。
  • 指令通常按顺序执行，也可以通过转移指令改变执行顺序。

这里的“顺序执行”不等于永远从第一条直走到底。条件判断、循环都需要改变执行顺序。

1 / 04计算机为什么越来越小？五个发展阶段看什么？

讲义按主要器件把发展过程分成五个阶段：

讲义中的阶段 主要器件或技术 带来的变化
第一阶段 电子管 体积大、耗电多、可靠性较低
第二阶段 晶体管 更小、更省电、更可靠
第三阶段 中小规模集成电路 把多个电路功能集成起来
第四阶段 大规模、超大规模集成电路 微处理器和个人计算机快速发展
第五阶段 更高集成度及系统集成 功能丰富的单片机、嵌入式系统大量出现

需要理解的是“集成度提高”这件事：原先需要很多独立器件实现的功能，可以集中到更少的芯片里。

具体分代年份、LSI/VLSI/ULSI/GSI 的历史界限，先认识即可，不必把它们看成全世界统一的严格分界线。

讲义还提到几个指标：

  • MTBF：平均故障间隔时间，用于描述可靠性，通常越长越好。
  • 性能价格比：花相同的钱能获得多少性能。
  • MIPS：这里指每秒百万条指令，是一种指令执行速率单位。
  • SPEC：通过一组基准程序评测性能。

这里的 MIPS 是性能单位；本章后面还有一种叫 MIPS 的处理器架构，同名但含义不同。性能如何比较，第二章再展开。

1 / 05摩尔定律：一定分清“晶体管数量”和“运行速度”【习题 1.2】

比较稳妥的表述是：

在一定历史时期内，集成电路上的晶体管数量呈现大约每两年翻一番的发展趋势。

摩尔在 1965 年最初预测的是每年翻倍，1975 年将预测调整为大约每两年翻倍。它属于产业发展中的经验观察与目标，不是自然科学中永远成立的定律。Intel 关于摩尔定律的说明

它不能直接写成：“计算机运行速度每两年必然翻倍。”

因为晶体管更多，可以拿来增加：

  • 处理器核心。
  • 缓存。
  • 图形、人工智能等专用运算单元。
  • 安全和控制功能。

这些增加不一定都能让某一个普通程序按同样比例加速。

讲义的性能增长曲线，是想说明：**单纯依靠传统方式，持续取得性能增长越来越困难。**不能仅凭曲线的某个拐点，就断言摩尔定律在某一年统一“失效”。

习题问发展受限的原因，可以抓住四点：

原因 直观解释
器件微缩越来越困难 尺寸很小时，漏电、量子隧穿等问题更突出
功耗与散热约束 更多器件、更高频率，可能带来难以处理的热量
互连成为限制 晶体管之间的导线也存在电阻、电容和延迟
制造成本与复杂度上升 工艺、设备、设计和验证都越来越昂贵

物理限制、散热和互连问题在相关研究中都有讨论。关于微缩极限的研究

学到什么程度：能解释含义，能说明以上原因。暂时不需要推导半导体器件公式。

计算机系统包含硬件和软件。先看硬件：

五大部件的职责，可以用一个“输入两个数并相加”的过程理解：

1 / 08存储器、寄存器、内存、外存，分别是什么？【习题 1.3】

先按用途分：

名称 主要作用 典型特点
寄存器 暂存 CPU 正在使用的数据、地址或状态 位于 CPU 内部，数量有限，访问很快
内存／主存 保存正在运行的程序和当前需要处理的数据 CPU 运行时频繁访问
外存／辅助存储器 长期保存较大量的程序和文件 容量通常较大，适合持久保存

“外存”的“外”，不是说它必须装在机箱外面。

装在电脑里面的 SSD，也属于外存。

讲义介绍的内存类型：

  • RAM：可读可写。普通计算机常见的主存 RAM 掉电后不能保留内容。
  • ROM 类存储器：用于保存相对固定的程序和数据；其中有些类型可以按规定方式重新编程。
  • Flash：非易失性存储器，在 SSD、嵌入式程序存储等场合都能见到。

“RAM”这个名字首先强调随机访问特性；入门时讨论掉电丢失，通常指常见的 SRAM、DRAM。

外存的例子，讲义包括磁盘、磁带、光盘和闪存设备。这里需要认识它们的用途，具体存储原理不必在第一章展开。

这部分就是我们第三章存储器系统的入口：为什么要用多种速度、容量、价格不同的存储部件。

1 / 09运算器和控制器里面那些缩写，学到哪里？

运算器中的核心部件是 ALU：算术逻辑单元。

它可以完成的操作包括：

  • 算术操作：加、减等。
  • 逻辑操作：与、或、非等。
  • 移位、比较等处理。

寄存器用于保存操作数、临时结果等。

控制器中，讲义提到：

名称 作用
IR，指令寄存器 保存当前正在处理的指令
指令译码器 分析指令要求做什么
操作控制部件 发出完成该指令所需的控制信号

你现在需要理解：

指令进入控制器，控制器安排数据如何流动、ALU做什么、结果写到哪里。

暂时不需要在第一章背完整的控制信号时序，那是第二章的内容。

时钟电路则为许多同步操作提供时间节拍。一个时钟周期也不一定刚好完成一条指令，后面会讲。

1 / 10输入输出接口和总线：为什么不能把外设随便接到 CPU 上？

不同外设差别很大：

  • 键盘发送信息慢。
  • 存储设备可以连续传输大量数据。
  • 传感器输出的信号形式可能与 CPU 所需形式不同。
  • 设备之间的电气特性、通信规则也可能不同。

因此需要 I/O 接口，负责桥接与匹配，例如：

  • 缓冲数据。
  • 转换信息形式。
  • 配合通信时序。
  • 提供状态和控制功能。

**设备与接口要区分。**例如键盘是设备，处理器通过接口电路与它交换信息。

总线是部件之间传输信息的通道，入门模型中分为：

总线 主要传什么 可以怎样记
地址总线 AB 地址 找谁、找哪个位置
数据总线 DB 数据或指令内容 传什么
控制总线 CB 读写命令、状态等 做什么、是否准备好

以 CPU 为主设备的简单模型里，地址通常由 CPU 发出。到了 DMA、多主设备系统，其他主设备也可以发出地址，不能把“永远只有 CPU 能发地址”当成普遍规律。

习题 1.3 的四个名词，到这里就都能回答了：

CPU 负责执行指令和处理数据；内存服务于当前程序运行；外存保存大量持久信息；I/O 接口负责主机与外设之间的信息交换和匹配。

1 / 11软件分三类：系统软件、应用软件、中间件

类型 主要解决什么问题 例子
系统软件 管理资源，支持程序开发与运行 操作系统、编译器、调试器等
应用软件 完成具体用户任务 浏览器、办公软件、游戏、CAD
中间件 为应用之间的通信、集成、协作提供公共服务 消息中间件、应用服务器等

操作系统 OS 是系统软件的核心。

它管理：

  • 处理器时间：谁先运行、运行多久。
  • 内存：各程序使用哪些空间。
  • 设备：输入输出如何进行。
  • 文件：信息如何命名、组织和保存。
  • 其他资源以及程序之间的协调。

1 / 19原码：最高位表正负，其余位表绝对值

以 8 位为例：

  • 最高位 0：正。
  • 最高位 1：负。
  • 后面 7 位：绝对值。

因为：

76=01001100B

所以：

+76 的原码：0100 1100
−76 的原码：1100 1100

原码直观，但直接拿它做普通二进制加法，会出问题。

例如：

+1 原码：0000 0001
−1 原码：1000 0001
直接相加：1000 0010

按原码解释，结果是 −2，而数学结果应该是 0。

这说明原码的运算需要额外处理符号和绝对值，不能直接照搬普通二进制加法。

1 / 22为什么补码能把减法变成加法？

关键是：固定 n 位，只保留结果的低 n 位，相当于对 2n 取模。

8 位的模是：

28=256

例如：

256−76=180

180 的二进制就是：

1011 0100

因此，8 位补码用这个位串表示 −76。

在只保留低 8 位的前提下：

49−76

可以转成：

49+(256−76)=229

而 229 对应：

1110 0101

作为 8 位补码解释，它表示：

229−256=−27

这正是：

49−76=−27

所以，补码使加法器可以参与完成减法，简化硬件实现。

1 / 23补码怎样读回真值？两种方法都要认识

已知 8 位补码：

1011 0100

最高位为 1，表示负数。

方法一：先按无符号数读，再减去 256。

10110100B=180
x=180−256=−76

方法二：全部取反，再加 1，得到绝对值。

原位串： 1011 0100
全部取反：0100 1011
加 1：   0100 1100 = 76

原位串代表负数，所以真值为 −76。

还有一个非常重要的直接理解：

x=−b7×128+b6×64+⋯+b0

在 8 位补码中，最高位的权值是 −128。

因此：

10110100B=−128+32+16+4=−76

这解释了为什么不能把补码简单理解成“一个负号＋后面七位的绝对值”。

1 / 28溢出是什么？别看见第九位就喊“溢出”【核心】

对于 8 位有符号补码：

−128≤x≤127

若数学上的正确结果超出这个范围，就发生有符号溢出。

例如：

94+55=149

149 超过 127，发生溢出。

但二进制相加结果是：

   0101 1110
 + 0011 0111
 -----------
   1001 0101

这里没有第九位进位，仍然发生有符号溢出。

因为保留下来的 1001 0101 按 8 位补码解释是 −107，不能表示数学结果 149。

反过来：

   1111 1111    −1
 + 0000 0001    +1
 -----------
 1 0000 0000

舍弃第九位，结果为 0。

数学上：

−1+1=0

完全正确，没有有符号溢出。

因此：

最高位向外进位≠有符号溢出

1 / 29判断有符号溢出，先学最省力的符号法

加法：

情况 是否可能有符号溢出
正数＋正数，结果变成负数 有
负数＋负数，结果变成非负数 有
一正一负相加 不会

记成：

同号相加，结果异号，发生溢出。

例如：

  • 100+50：可能超出上界。
  • −100+(−50)：可能超出下界。
  • 100+(−50)：一正一负相加，不会超出两端边界。

减法：

两个操作数异号，且结果符号与被减数不同，发生溢出。

例如：

100−(−50)=150

正数减负数，本来应该更大；保留下来的结果若成了负数，就出现了溢出。

初学做题时，最好再用真值范围检查一遍。这样不容易被符号口诀绕进去。

1 / 30讲义的进位判定法：进入符号位与移出符号位比较

以 8 位加法为例：

  • c7：从第 6 位进入第 7 位，即进入最高符号位的进位。
  • c8：从第 7 位向外，即移出最高符号位的进位。

有符号溢出标志：

V=c7⊕c8

异或的意思是：

  • 两个相同，结果为 0。
  • 两个不同，结果为 1。

所以：

c7 c8 V 结论
0 0 0 无有符号溢出
0 1 1 有
1 0 1 有
1 1 0 无

**注意讲义的记号：它把移出最高位记为 CP，把进入符号位记为 CF。这里的 CF 不是通常 x86 资料中 Carry Flag 的同一命名用法。**为了减少混淆，我们用 c7,c8。

切换下面四道习题，重点观察：有进位时可能不溢出，没有进位时也可能溢出。

CPU 可以根据这些运算信号更新状态标志，例如 x86 的 OF。程序再根据标志决定后续处理。

1.3.4 定点与浮点表示

1 / 32定点数：小数点的位置事先约定

定点的意思是：

小数点位置固定，而且通常不需要把小数点本身存进去。

最简单的是整数：

0001 1000

按无符号整数解释，它是：

24

如果约定最低四位是小数部分，相当于除以 24，同一个位串就表示：

24/16=1.5

所以：

定点数不一定没有小数，它只是小数点位置固定。

若用 f 位表示小数，最小步长通常是：

2−f

这帮助你理解一个取舍：固定位宽下，给小数部分的位越多，分辨率越细，整数范围通常就越小。

本章先理解这个思想，不需要立刻学习各种定点数格式的完整运算规则。

1 / 33浮点数：把有效数字和数量级分开保存

6500000=6.5×106

二进制也可以这样表示：

6.510=110.12=1.1012×22

所以可以分别保存：

  • 正负号。
  • 指数。
  • 有效数字相关部分。

讲义用“尾数”和“阶码”说明这个思想。

指数主要决定可表示的数量级范围；有效数字位数主要决定精度。

IEEE 754 常见两种格式：

格式 总位数 符号位 S 阶码字段 E 小数字段 F

x=(−1)S×(1.F)2×2E−127

双精度规格化数则使用偏置 1023。

  • 阶码字段存的是偏置后的编码，不是直接把实际指数写成补码。
  • 单精度规格化数有一个隐含的前导 1，所以有效精度是 24 个二进制位，虽然 F 只存了 23 位。Oracle 的 IEEE 浮点格式说明

S = 0
E = 2 + 127 = 129 = 1000 0001
F = 101 后面补 0，直到共 23 位

1 / 34BCD：逐个十进制数字编码【重点】

BCD 是 Binary Coded Decimal，二进制编码的十进制数。

本章使用 8421 BCD，每个十进制数字各占四位：

0 → 0000
1 → 0001
……
9 → 1001

例如十进制 59：

5 → 0101
9 → 1001

BCD：0101 1001

但普通二进制的 59 是：

0011 1011

因为：

59=32+16+8+2+1

因此：

59 的普通二进制≠59 的 BCD 编码

两者表示同一个数值，但采用不同编码规则。

再看讲义例子：

135

BCD 是：

0001 0011 0101

即逐位编码 1、3、5。

小数也可以逐位编码，但小数点的位置需要另行约定或记录，并不是凭空多出一个二进制“小数点字符”。

1 / 35压缩 BCD、非压缩 BCD、ASCII 数字，怎么区分？

对于 59：

表示方式 存储内容 占用
普通二进制，按 8 位容器存 0011 1011 1 字节
压缩 BCD 0101 1001 1 字节
非压缩 BCD 0000 0101、0000 1001 2 字节
ASCII 字符串 "59" 0011 0101、0011 1001 2 字节

按本章约定：

  • 压缩 BCD：一个字节装两个十进制数字。
  • 非压缩 BCD：一个字节装一个十进制数字，高四位为 0000。
  • ASCII 数字字符：使用字符编码，例如 '5' 是 35H。

BCD 的代价是，一组四位本来有 16 种状态，只使用其中 10 种。1010～1111 不是合法的单个 8421 BCD 数字。

为什么还要使用它？因为它与十进制逐位对应，便于处理、显示某些十进制数据。不是所有信息表示方式都只追求最省位数。

BCD 运算还需要调整。例如：

  0111    7
+ 0101    5
------
  1100

1100 不是一个合法 BCD 数字。正确的十二应是：

0001 0010

对这种单个十进制位的加法，结果大于 9 或发生相应进位时，需要做十进制调整，常见办法涉及加 6。

你需要知道为什么要调整。本章没有要求你掌握各种处理器的完整 BCD 调整指令。

1 / 36习题 1.9：四位十进制数为什么只需十四位二进制？

这里“四位十进制数”指十进制位数，例如 0～9999，不是“四个二进制位”。

要覆盖 0～9999，需要至少 10000 种状态。

找最小的 n，使：

2n≥10000

因为：

213=8192<10000
214=16384≥10000

所以普通无符号二进制最少需要：

14 位

非压缩 BCD 中，一个十进制位占一个字节：

4×8=32 位

顺便比较：

  • 压缩 BCD：4×4=16 位。
  • ASCII 保存四个数字字符：32 位，不含额外结束标记。

1 / 47嵌入式软件分两层，也可以没有操作系统

复杂系统常见：

嵌入式应用软件
       ↓
嵌入式操作系统
       ↓
硬件

嵌入式操作系统负责：

  • 任务调度。
  • 内存分配和管理。
  • 中断及定时相关管理。
  • 任务之间的通信与同步等。

1 / 48嵌入式操作系统的三个特点【习题 1.14】

按讲义回答：

特点 含义
实时性 对有实时要求的任务，在规定时间内完成响应和处理
可靠性 能长期稳定工作，并按需要具备诊断、恢复、告警等能力
可裁剪性 根据应用选择功能模块，减少不需要的资源开销

“可裁剪”例如：

  • 不需要文件系统，就不配置该模块。
  • 不需要图形界面，就不加入图形相关功能。
  • 不需要网络，就不加入完整网络功能。

这样可以减少内存占用和系统复杂度。

不过，功能更少不自动证明系统更可靠，可靠性仍需要设计和验证。这里要理解的是：去除不必要功能，有助于控制复杂度。

1 / 49RTOS：“实时”最重要的是能否按时完成【习题 1.15】

RTOS 是实时操作系统。

假设某项控制任务要求：

事件发生后，必须在 10 ms 内完成响应。

两个系统：

系统 平时响应 最坏情况 是否满足这个要求
A 1 ms 偶尔 100 ms 不满足
B 5 ms 可保证不超过 8 ms 满足

因此：

实时性强调时间约束和确定性

平均速度很快，但偶尔严重拖延，仍可能不满足实时要求。

需要实时处理的典型场景：

  • 汽车制动和部分车辆控制。
  • 工业运动控制、电机控制。
  • 无人机飞行控制。
  • 某些医疗设备的控制任务。
  • 需要规定时序的通信和采集任务。

这些场景可能采用 RTOS，也可能用经过设计与验证的裸机方案。装了 RTOS 也不等于整个系统自动保证期限，还要看任务、驱动、硬件及调度等。

补充认识两个词：

  • 硬实时：错过期限不可接受。
  • 软实时：偶尔错过期限会降低体验或服务质量，但后果通常不同。

这两个词有助于理解应用差别，本章先能举例即可。

这属于程序员能够看到的规则。

但处理器内部可以用不同方式完成：

  • 一个加法器分多步处理。
  • 多个部件配合处理。
  • 使用不同流水线。
  • 使用不同控制器。

再往下，还要决定使用什么电路工艺、怎样布线、怎样供电散热。

层次 主要研究 例子
体系结构 机器向程序员提供什么功能和规则 指令集、寄存器、寻址方式
计算机组成 内部部件怎样组织起来实现这些功能 数据通道、控制器、流水线、Cache
计算机实现 怎样把设计做成具体电路与产品 工艺、布局布线、电源、封装、散热

三者关系：

体系结构规定功能，组成安排实现这些功能的部件与联系，实现技术把它们做成实际硬件。

同一指令集，可以有不同的内部组织，因此可以出现软件指令层面相近、性能却不同的处理器。

2 / 03层次模型：为什么需要分层？

因为直接从高级语言一路研究到晶体管，问题太复杂。

讲义的层次，可以整理为：

从上到下 主要内容
用户程序层 用户需要完成的任务
语言处理层 编译、解释等
操作系统层 资源管理及系统服务
指令系统层 机器指令及其规则
微体系结构层 控制器、数据通道，以及某些实现中的微程序等
数字逻辑层 门电路、寄存器等实际逻辑部件

分层是观察和设计的方法，不表示每条机器指令运行时都必须“再经过一次编译器和操作系统”。

程序编译之后，CPU 可以直接执行其中的机器指令；需要系统服务时，再按照约定请求操作系统。

讲义说“软硬件在逻辑上等价”，主要想表达：

某些计算功能既可以由专用硬件完成，也可以由软件组合较基础的操作完成。

但两者在速度、能耗、成本和开发方式上可能差别很大。

本节学到能解释这种分工即可，不需要推导完整的分层理论。

2 / 04模型机与冯·诺依曼瓶颈【习题 2.2】

讲义模型机包含：

  • CPU。
  • 存储器。
  • I/O 接口。
  • 连接它们的地址、数据、控制总线。

指令和数据放在同一存储系统中，通过共用通路访问。

问题在于：

CPU 想取下一条指令时，前一条指令也可能正在访问数据。两种需求争用同一通路。

再加上 CPU 运算速度与主存访问速度存在差距，处理器可能花时间等待信息。

这就是本章强调的技术瓶颈：

  1. 处理器与存储系统之间的速度和带宽差距。
  2. 取指令与访问数据竞争共享资源。

后面介绍的 Cache、多总线、分离指令数据通路、流水线等，都与这些问题有关。

注意：简单模型里的共享通路是一种组织方式，不能据此认为所有现代处理器内部都只有一条总线。

2.2 存储器与总线

2 / 05开机时，程序是从哪里来的？

普通 RAM 掉电后不能保存有效内容。

但这不等于重新上电后每个位置自动为 0。初始化之前，不能随便把其中内容当有效数据使用。

系统需要某种非易失存储保存启动代码，例如 ROM 或 Flash。启动后大致经历：

复位入口
→ 执行启动代码
→ 初始化必要硬件和内存
→ 建立运行环境
→ 执行后续程序

具体系统可能把程序从外存调入 RAM，也可能直接从 Flash 执行，不能把某一种启动方式看成所有计算机的唯一方式。

这里要理解：

  • 非易失存储负责保留必要代码和数据。
  • RAM 用于程序运行时的数据和工作空间。
  • 需要长期保存的信息，要按系统约定保存到非易失存储中。

2 / 06地址位数、数据总线位数、机器字长，不能混用【重点】

这三个参数回答不同问题：

参数 回答的问题
地址位数 可以区分多少个地址
数据总线位数 一次数据传输可以并行传多少位
机器字长 本课程模型中，处理器主要整数处理宽度是多少

例如：

数据总线 16 位，地址总线 24 位，按字节编址。

可以有：

224 个字节地址

所以地址空间为：

224 B=16 MiB

地址范围：

000000H~FFFFFFH

不能因为数据总线是 16 位，就说只能访问 216 字节。

同样，一次传 16 位，不表示每个地址对应 16 位。题目明确按字节编址，每个地址仍对应一个字节。

讲义常把这些二进制容量写作 MB、GB；这里用 MiB、GiB 把含义写得更明确。

2 / 07习题 2.6：怎样既传一个字，又能只传其中一个字节？

采用两个 8 位字节存储体并行连接。

总空间为 16 MiB，平均分成：

每个存储体 8 MiB

每体有：

223 个 8 位单元

连接方式：

部分 连接
低字节存储体数据口 D7～D0
高字节存储体数据口 D15～D8
两体内部行地址 共用 A23～A1
读写控制 送往两个存储体
字节选通信号 分别控制低、高字节存储体是否参与

以类似 8086 的小端字节组织方式为例：

  • 偶地址字节放低字节存储体。
  • 奇地址字节放高字节存储体。
  • 偶地址开始的一个 16 位字，两个存储体同时输出即可。

若仿照 8086，用 A0 和低有效的高字节使能 BHE― 控制：

A0 BHE― 参与传输的部分
0 1 低字节
1 0 高字节
0 0 两个字节
1 1 两者均不选

这是一个可采用的接口设计，不是说任何 16 位处理器都必须使用同名引脚。

讲义还用 8086 举例：20 位地址、16 位数据，其总空间为 1 MiB，两个字节存储体各为 512 KiB，原理相同。

2 / 08对齐存放：为什么四字节数据最好从 4 的倍数地址开始？【习题 2.5】

本章 32 位字占 4 字节。

自然对齐要求：

起始地址mod4=0

因此：

0、4、8、12……

都是对齐地址。

假设一次能访问的对齐块是：

第 0 块：地址 0、1、2、3
第 1 块：地址 4、5、6、7

一个四字节数据：

  • 从地址 0 开始：全部位于第 0 块。
  • 从地址 1 开始：占地址 1、2、3、4，跨越两块。

在这种简化总线模型下，第二种情况要分次访问，再拼出完整数据。

下面同时展示对齐与大小端。起始位置和字节序是两个独立问题。

习题 2.5 可以这样答：

32 位数据若未按四字节边界对齐，可能跨越两个对齐存储块，需要多次访问及数据组合，降低访问效率。例如从地址 1 存放一个四字节字，会占用地址 1～4。

2 / 10读、写、块传送：地址、数据、命令分别从哪里走？

读操作：

  1. CPU 提供目标地址，送到地址总线。
  2. 控制器发读命令。
  3. 存储器把所选内容送到数据总线。
  4. CPU 接收数据。

普通内存读完后，原内容不因这次读取而改变。

写操作：

  1. CPU 提供目标地址。
  2. CPU 把要写的内容送到数据总线。
  3. 控制器发写命令。
  4. 存储器在规定时序下保存数据，覆盖目标位置原内容。

要分清：

  • 地址总线上是“去哪里”。
  • 数据总线上是“传什么”。
  • 控制线上是“读还是写”等控制信息。

讲义还介绍连续块传送：协议若允许根据首地址、传输宽度、方向和长度推导后续地址，就能减少重复地址开销。

这需要双方支持相应协议，不是 CPU 随便发一次地址，任何存储器都会自动继续传输。这与第四章讲过的突发传输相联系。

2 / 11习题 2.14：同一总线上的 A→B，能否一个总线周期完成？

按本章“CPU 发起一次读或一次写”的普通存储器模型：

不能，通常至少需要一次读和一次写

过程：

A 单元 → CPU 内部暂存位置
CPU 暂存位置 → B 单元

第一步访问 A 的地址并读取，第二步访问 B 的地址并写入。

总线够宽，只能说明一份数据不需要拆成多个数据片段，不能把读 A 和写 B 自动合并成同一次访问。

一条复杂机器指令可以包含这两个过程，但“一条指令”不等于“一个总线周期”。

2 / 12存储器分级：这一节与第三章怎样接上？

讲义这一节建立基本关系：

层级 主要角色 典型取舍
寄存器 CPU 直接使用的少量工作数据 快、少
Cache 保存近期或可能需要的指令和数据 较快、容量有限
主存 程序运行的主要工作空间 较大，访问慢于寄存器等
外存 大量持久信息 容量大，访问延迟通常更高

Cache 常用 SRAM，主存常用 DRAM。

分级的目的，是综合容量、速度、成本，而非找到一个各方面都最好的单一存储器。

第三章已经进一步讲过 Cache、局部性和虚拟存储，这里无需再背一遍具体电路，但要知道它们在整个系统中的位置。

2.3 CPU 的内部结构

掌握要求：认识 ALU、寄存器、PSW、PC、IR、控制器与数据通道，区分三个“微”概念。

为什么讲到这里：知道两类控制器的取舍即可；本章不要求编写真实 CPU 的微程序。

2 / 13CPU 内部部件，先按“保存、计算、控制、连接”分类

类别 部件 作用
保存 通用寄存器、PC、IR、状态寄存器等 保存数据、地址、指令或状态
计算 ALU、移位器、乘法器、FPU 等 处理数据或计算地址
控制 指令译码器、操作控制器等 产生完成指令所需的控制信号
连接 内部总线、地址和数据缓冲器等 在部件间传送信息

看到 CPU 结构图时，不要先试图背所有箭头。

2 / 14运算器：ALU、累加器、暂存器、FPU，各做什么？

  • ALU：完成算术、逻辑、移位等操作。
  • ACC 累加器：在某些模型或指令中，保存操作数或运算结果。
  • 暂存器：保存内部处理中需要的中间值，可能不对程序员直接可见。
  • FPU：专门处理浮点运算。

没有 FPU，也能用软件组合整数操作实现浮点算法，只是实现方式和效率不同。

讲义提到的加法器、先行进位、移位器，是在说明运算电路的基础。先行进位主要用于减少等待进位逐级传播的延迟。

累加锁存器、暂存器等，则帮助分隔不同时间阶段的数据，避免当前运算所需的输入被结果更新干扰。

本章需要知道它们为什么存在，不要求你现在画出完整门电路。

另外，不能把累加器理解成“所有处理器做任何加法都必须经过一个叫 ACC 的寄存器”。具体使用哪些寄存器，由指令集和内部组织决定。

2 / 15PSW 是什么？【习题 2.7，联系第一章】

**程序状态字 PSW，是描述处理器当前状态的一组位。**保存它的部件可称状态寄存器、标志寄存器等，具体名字随架构不同。

本章分两类：

类型 内容
状态标志 运算结果的特征
控制标志 对处理器行为的控制状态

常见状态位：

标志 主要含义
Z 保留的运算结果是否为零
N／S 保留结果的最高位等符号相关信息
C／CF 进位等无符号运算信息，具体规则看架构
V／OF 有符号溢出

第一章已经学过：

进位与有符号溢出不是一回事

例如，8 位计算：

127 + 1 → 1000 0000

保留结果最高位为 1，但数学结果是正的 128。此时必须结合溢出标志理解，不能只凭 N 判断数学结果。

还有一个讲义需要修正的地方：

**Arm 减法中，C＝1 通常表示没有借位；C＝0 表示发生借位。**不能简单背成“C＝1 就是有借位”。Arm 的 Carry flag 说明

控制位方面，讲义用 8086 举例：

  • D／DF：串操作中的地址变化方向。
  • I／IF：是否允许响应可屏蔽外部中断。
  • T／TF：单步调试相关控制。

不同架构不能混记。例如 8086 的 IF＝1 表示允许可屏蔽中断，而传统 Arm CPSR 的 I＝1 表示屏蔽 IRQ。

  • 通用寄存器：保存数据、地址或结果等。
  • 专用寄存器：具有特定职责，例如 PC、IR、状态寄存器。

本章还出现 SP，栈指针。

栈按后进先出方式使用：

先压入 A，再压入 B
先弹出 B，再弹出 A

SP 用来跟踪栈顶位置。SP 本身保存的是相关位置，不是把整个栈都装在这个寄存器里。

2 / 17控制器各部分做什么？【习题 2.9】

部件 作用
PC，程序计数器 提供指令地址，跟踪执行位置
IR，指令寄存器 保存当前取得、需要处理的指令
ID，指令译码器 分析操作码，识别指令要求
OC，操作控制器 结合时序、状态等产生控制信号
地址生成部件 根据指令信息和寄存器等计算有效地址

最重要的区别：

PC 保存地址，IR 保存指令内容

不是都存“下一条指令”。

例如：

PC = 20000004H
内存 20000004H 中保存 LDR 的机器码

取指后：

IR ← 这条 LDR 的机器码

PC 则按约定更新为后续指令位置。

在真实流水线处理器中，取指位置、正在执行位置以及程序员读到的 PC 值可能不同。本章先按模型机的明确约定分析。

2 / 18PC 到底加 1、加 2，还是加 4？

取决于：

  1. 地址的计量单位。
  2. 当前指令长度。
  3. 是否发生控制转移。

本章模型机：

  • 按字节编址。
  • 一条指令固定 32 位＝4 字节。

顺序执行时：

PCnext=PC+4

如果某模型按字计数，一个指令占一个字，可以表现为 PC＋1。

如果采用变长指令，按当前指令的字节长度更新。

遇到跳转时，则按转移规则确定目标地址。

因此，不要背成“CPU 每执行一条指令，PC 一定加 1”。

2 / 19微操作、微指令、微程序：分清三个层次【习题 2.10】

考虑：

ADD R1, R2, R3

它的功能是：

R1←R2+R3

内部需要若干更细的动作，例如：

  • 读取 R2。
  • 读取 R3。
  • 选择 ALU 加法功能。
  • 将结果写入 R1。
  • 按指令规定更新状态。

这些细化动作叫微操作。

在微程序控制器中：

  • 微指令：编码控制信息和后续微指令顺序等。
  • 微程序：为实现某项机器指令功能而安排的一段微指令序列。
  • 控制存储器／控制 ROM：保存微程序。

一条微指令可以控制一个或多个可同时进行的微操作，不能把两者硬性看成一一对应。

控制 ROM 与保存应用程序的主存不同。

程序员写的机器程序是一层；CPU 内部可能用来实现机器指令的微程序，是另一层。

2 / 20微程序控制与硬连线控制，怎样比较？

比较 微程序控制 硬连线控制
产生控制信号的主要办法 读取并解释控制存储器中的微指令 由逻辑电路结合操作码、状态、时序产生
传统优势 结构规整，较便于实现和调整复杂操作 控制路径可以较直接，适合高速实现
传统代价 读取和解释微指令有开销 复杂功能的设计、修改和验证可能更困难

这里比较的是设计思路，不是给所有处理器贴“永远快”“永远慢”的标签。

现代实现可以结合不同办法。指令集风格，也不强制内部只能采用某一种控制器。

这一节要能回答概念题，不需要现在独立设计控制 ROM 编码表。

2 / 21数据通道是什么？地址与数据缓冲器有什么用？【习题 2.11】

数据通道是数据被传送、保存和处理的部件及连接路径。

本章模型中包括：

  • 寄存器。
  • ALU 等运算部件。
  • 内部总线及相应连接。
  • 与系统总线交互的接口等。

控制器决定“现在做什么”，数据通道完成具体传送和处理。

例如：

R2、R3 → ALU → R1

就是一条运算数据路径。

内存 → 数据总线 → 缓冲器 → 内部通路 → R1

是一条加载路径。

地址和数据缓冲器负责 CPU 内部与系统总线之间的缓冲、传送配合及相关驱动作用。

数据通道不是仅指某一根数据线，也不只包含 ALU。

先记三个约定：

  • Rd：目的寄存器。
  • Rs：源寄存器。
  • #数值：立即数，即指令本身给出的数值。

还有方括号：

[R3]表示按 R3 保存的地址访问内存

2 / 24定长指令为什么限制立即数和地址？【习题 2.12】

一条指令不仅要保存“数”，还要保存：

  • 做什么操作。
  • 使用哪些寄存器。
  • 寻址方式等信息。

假设一个示意编码总长 32 位：

操作码 8 位 | Rd 4 位 | Rs 4 位 | 立即数 16 位

那么立即数只剩 16 位。

处理器能处理 32 位数据，不代表每条 32 位指令都能直接塞进任意 32 位立即数。

同理，若指令还要包含操作码、寄存器编号，就无法再无条件放入完整的 32 位绝对地址。

所以会使用：

  • 寄存器保存地址。
  • 基址加偏移。
  • PC 相对寻址。
  • 组合多条指令等办法。

定长编码的优点：

  • 指令边界容易确定。
  • 取指、译码较规则。
  • 有利于流水线组织。

代价：

  • 编码空间有限。
  • 立即数、偏移量或可直接表示的地址受限制。
  • 简单操作也可能占用整个指令长度，影响代码密度。

定长不保证一次总线传输一定取完整条指令，还要看总线宽度和存储接口。

2 / 28习题 2.13：逐步写出 `LDR R1, [R3]` 的执行过程【必须会】

题目称它为“数据存储指令”，但 LDR 是数据加载指令。

仍假设：

PC = 20000004H
R3 = 00001000H
[00001000H] = 7

它包含两次不同目的的读取：

先读指令本身，再读指令要求的操作数。

完整答题过程可以写为：

  1. PC 的内容送入地址生成及地址缓冲部件，再通过地址总线选中指令所在内存。
  2. 控制器发出读命令。
  3. 指令机器码经数据总线、数据缓冲器等送入 IR。
  4. 按本模型的顺序取指约定，PC 加 4，变为 20000008H。
  5. 指令译码器识别 LDR，确定目的寄存器为 R1，地址来自 R3。
  6. 读取 R3 的内容，将 00001000H 经地址通路送往地址总线。
  7. 控制器再次发读命令，读取该地址处的操作数。
  8. 操作数经数据总线、缓冲器及 CPU 内部通路写入 R1。

结束后：

R1 = 7
R3 仍然是 1000H
内存 [1000H] 仍然是 7

加载会改变目的寄存器，不会因为“取出了数据”就把普通内存原内容清空。

2.5 体系结构的改进与并行技术

掌握要求：比较 CISC/RISC，分析流水线和相关，区分多发射、SMT、多核，并会算理想加速比。

2 / 29CISC 和 RISC，关键在设计取向【习题 2.3、2.4】

先看典型风格：

比较 传统 CISC 风格 传统 RISC 风格
指令功能 可以较复杂 强调较规则的基础操作
指令长度 常为变长 常强调固定或规则编码
访存运算 某些算术指令可以直接使用内存操作数 常用 Load/Store 模型
寻址方式 较丰富 较规则
通用寄存器 传统设计中往往较受限制 强调较充足的寄存器
控制实现 传统上常借助微程序 传统上强调较直接的控制逻辑
优化重点 丰富指令表达能力、代码密度等 简化常用操作，利于流水与编译优化

这些是典型设计特征，不是永无例外的判定清单。

尤其不能背成：

  • RISC 的所有指令永远一样快。
  • RISC 永远只有几十条指令。
  • CISC 不能做流水线。
  • RISC 一定比 CISC 快。

性能必须结合具体实现、程序和编译结果分析。

2 / 30为什么一条 CISC 指令能对应三条 RISC 指令？

要做：

M[A]←M[A]+R2

一种 CISC 风格可以写：

ADD [A], R2

Load/Store 风格则通常分成：

LDR R1, [A]
ADD R1, R1, R2
STR R1, [A]

它们都要完成：

读内存 → 运算 → 写内存

区别是这些动作怎样组织成机器指令。

一条指令功能复杂，不代表内部不用做那些动作。

CISC 的典型优点：

  • 指令表达能力强。
  • 某些任务所需机器指令较少。
  • 可能具有较好的代码密度。

典型代价：

  • 译码、控制和调度可能更复杂。
  • 指令边界、执行延迟等更不规则。

RISC 的核心思想：

  • 让常用操作规则、高效。
  • 用较简单指令组合复杂功能。
  • 强调寄存器运算、加载存储及编译优化。
  • 便于组织流水线和并行执行。

讲义的历史人物及 IBM 801、RISC-I、SPARC、MIPS、PowerPC、Alpha、PA-RISC、Itanium/EPIC 等，是介绍这些思路的发展与相互影响。知道它们是代表性路线即可，不必背每款芯片的晶体管数量。

“二八定律”在这里也是说明：应关注实际高频使用的操作，不是每个程序都严格符合 80% 和 20%。

2 / 31流水线：让不同指令的不同阶段重叠【核心】

本章示例把指令过程分成：

F：取指
D：译码
R：读源寄存器
E：执行
W：写回

串行执行时：

I1 全部做完 → I2 才开始 → I3……

流水执行时：

I1 进入 D 时，I2 可以进入 F
I1 进入 R 时，I2 进入 D，I3 进入 F

各阶段之间加入流水线寄存器，保存上一阶段产生、下一阶段需要的信息。

流水线主要提高吞吐率：单位时间完成更多指令。

它不保证单条指令从开始到结束更快。流水线寄存器等还有额外开销。

稳定运行时每拍完成一条，也不意味着那条指令只经历了一拍。

2 / 32流水线的基本计算：先声明理想条件

假设：

  • 每条指令有 k 个阶段。
  • 每阶段时间均为 t。
  • 指令之间无冲突。
  • 暂不计额外寄存器开销。

执行 n 条指令：

串行：

T串行=nkt

流水：

T流水=(k+n−1)t

因为第一条要先经过 k 拍，之后每拍完成一条。

例如 k=5,n=4：

T串行=20t
T流水=8t

加速比：

S=208=2.5

不是用了五级流水线，四条指令就直接快五倍。

只有当指令数量足够多、其他条件理想时，加速比才趋近 k。

如果各阶段耗时不相同，流水时钟还会受到最慢阶段和寄存器开销的限制，不能任意缩短。

2 / 33流水线为什么会停？三类冒险先分清

类型 问题
结构冒险／资源相关 同时想用同一个不能同时服务的资源
数据冒险 数据读写先后关系受到破坏
控制冒险 还没确定下一条该从哪里取

“有相关”描述指令之间的关系；“冒险”强调具体执行时序可能因此出现问题。

不是发现某两条指令相关，处理器就一定算错。正确实现必须通过等待、旁路、调度等保持程序语义。

2 / 34结构冒险与哈佛结构：取指和读数据撞在一起

假设：

  • 前一条 LDR 要访问数据内存。
  • 后一条指令同拍需要取指。
  • 系统只有一套无法同时服务两者的访存接口。

就发生资源冲突。

解决办法之一是等待，即插入停顿或气泡。

另一种办法是分离指令与数据通路：

哈佛结构强调指令与数据具有分离的存储或访问通路。

现代处理器还可能在靠近 CPU 的位置分设 I-Cache、D-Cache，而后面连接统一的主存系统。

分离通路可以缓解对应的取指与数据访问冲突，不能消除所有结构冲突。例如两个操作仍可能争用同一个乘法器。

2 / 35RAW：后一条要读前一条尚未产生的结果

例子：

SUB R1, R2, R3
AND R4, R1, R5

第一条写 R1，第二条读 R1。

程序本意：

先产生新的 R1
→ 再把这个新 R1 用于 AND

但在流水线上，第二条可能在第一条写回之前就进入读寄存器阶段。

这叫：

RAW：Read After Write，写后读

它是真实的数据依赖。

解决思路：

  • 后一条等待。
  • 把前一条已算出的结果直接旁路给后一条。
  • 在保持语义的前提下，安排其他独立指令填补等待。

**旁路不一定能消除所有等待。**例如加载数据尚未返回时，依赖它的指令仍可能需要停顿。

具体等待几拍，取决于阶段划分、结果何时产生、寄存器读写时序和旁路路径，不能脱离模型只背一个固定数字。

2 / 36WAR 与 WAW：习题 2.15 要会自己举例

WAR：Write After Read，读后写。

I1: ADD R4, R1, R2
I2: SUB R1, R5, R6

程序要求：

I1 先读取旧 R1
I2 再写入新 R1

若某种乱序执行让 I2 先写 R1，I1 再读取，就读错了。

WAW：Write After Write，写后写。

I1: MUL R1, R2, R3
I2: ADD R1, R4, R5

程序最后应保留 I2 写入的 R1。

若 I1 较慢，I2 先完成写入，而 I1 随后又覆盖 R1，最终结果就错了。

区别可以记为：

类型 必须维护的顺序
RAW 前一条写 → 后一条读
WAR 前一条读 → 后一条写
WAW 前一条写 → 后一条写

**在简单、顺序读寄存器、顺序写回的五级流水线中，WAR 和 WAW 通常不会出现。**它们在更复杂的乱序或不同延迟执行结构中才成为实际风险。马里兰大学流水线课程资料

这里讲它们，是为理解后续更复杂并行执行；不应把三种风险都硬套到所有简单流水线。

2 / 37旁路、调度、乱序、寄存器重命名，各解决什么？

方法 主要作用
停顿／插入气泡 等条件满足后再继续

2 / 38控制冒险：下一条究竟取顺序地址，还是跳转目标？【习题 2.16】

例如：

  4. 指令实际执行后检查预测。
  5. 预测错误时取消错误路径操作，恢复正确执行。
  6. 根据实际结果更新预测状态。

2 / 40BTB 与“转不转”的预测表，不必一定是同一张表

讲义把信息放在一个简化表中：

分支指令地址
预测状态
转移目标地址

这样方便理解。

更一般地：

  • 方向预测信息回答：转不转？
  • BTB 主要帮助回答：转到哪里？

实际实现可能将这些信息分开组织。

BTB 容量有限，需要匹配和替换。讲义的 1024 项只是示例，不是所有处理器的固定容量。

这一节要掌握工作过程，不需要记住某一张表必须有多少项。

2 / 41转移延迟槽：讲义这一段必须单独澄清【习题 2.16】

在某些采用延迟转移的指令集中：

分支后面规定位置的指令，按架构规则仍会执行，然后才发生转移效果。

这个位置称为分支延迟槽。

例如简化表示：

BRANCH Target
某条延迟槽指令

编译器可能安排一条合适且安全的指令放进去，否则可能使用 NOP。具体规则及取消执行等变体由指令集决定。Oracle 对分支延迟槽的说明

必须分清：

  • 被预测路径上的指令取入了流水线，不代表它一定应当完成。
  • 架构规定的延迟槽指令，是程序语义的一部分。
  • 分支预测与延迟槽，是不同机制。

**不是所有流水线处理器都有延迟槽。**本章介绍 Arm 时，也不能把这种延迟槽规则随意套进去。

这里值得讲清楚，因为讲义把“分支后的时间片”“预测取指”和“延迟槽”写得过于接近，很容易造成概念混淆。

2 / 42超标量与多发射：一拍可以送出多条指令【习题 2.18】

普通单发射流水线，理想情况下每拍进入一条指令。

超标量设计增加执行能力，可以在满足条件时，每拍发射多条指令到相应执行资源。

但发射前必须检查：

  • 操作数是否准备好。
  • 指令之间有无数据关系。
  • 需要的执行单元是否可用。
  • 其他执行限制是否满足。

例如：

ADD R1, R2, R3
SUB R4, R5, R6

若资源支持，两条互不依赖，适合并行安排。

但：

ADD R1, R2, R3
SUB R4, R1, R5

第二条依赖第一条的新结果，就不能简单当作彼此无关的两条指令同时执行。

即使没有寄存器依赖，两条指令都需要同一个、不能同时服务两者的功能单元，也会受限制。

“配对检查”的目的，是保证并行安排正确且资源允许。

编译器可以帮助优化排列，运行时是否发射及相关检查也通常由处理器硬件参与，不能把责任全归给编译器。

2 / 43超流水线、超标量、向量/SIMD，分别增加什么？

技术 主要办法
更深流水线／超级流水线 把处理过程分成更多阶段
超标量 在同一核心中增加并行发射和执行能力
向量／SIMD 一条指令对多个数据元素做相应操作

例如四组数相加：

a0+b0，a1+b1，a2+b2，a3+b3

SIMD 可以让一条指令处理多个元素。

超标量则可能同时安排多条不同指令。

更深流水线也不是级数越多越好，因为：

  • 寄存器及控制开销增加。
  • 分支失败恢复可能更贵。
  • 功耗、时序和设计复杂度增加。
  • 其他瓶颈仍然存在。

讲义列举某些旧处理器有多少流水级，是历史实例，理解取舍即可，不必把数字当普遍最优值。

2 / 44进程、线程、时间片：为什么这里要讲操作系统名词？

因为后面的“超线程”需要区分软件执行任务与硬件资源。

  • 程序：静态代码和相关内容。
  • 进程：程序运行中的实例，具有地址空间、状态和资源。
  • 线程：进程内可以被调度执行的一条执行流。

同一进程的线程通常共享代码、全局数据、堆等资源，但各自有：

  • PC。
  • 寄存器执行状态。
  • 栈等线程相关状态。

所以不能把“共享进程资源”理解成“所有线程的运行状态都相同”。

时间片调度，让处理器轮流运行不同线程。切换时需要保存和恢复现场等。

讲义说进程每次切换都回收并重新分配全部资源，表述过重。普通上下文切换不是把整个进程的内存等全部销毁后重建。

这部分用于理解调度和硬件线程，不要求现在学完操作系统课程。

2 / 45超线程 SMT：两个线程共享一个核心，也可以真正重叠执行

SMT 是同时多线程。Intel 的 Hyper-Threading 是其相关技术实现和名称。

典型的双线程 SMT 核心：

  • 为两个硬件线程保持相应的架构执行状态。
  • 共享核心中的执行单元、部分缓存和其他资源。
  • 可以利用一个线程未用上的资源，安排另一个线程的指令。

**共享资源不等于完全不能并行。**不同线程的指令可以重叠执行，但也会竞争资源，不能当成两套完全独立核心。Intel 关于超线程执行上下文的说明

讲义中：

  • “不是真正意义的并行处理”不够准确。
  • “固定提升约 30%”不能当保证。
  • “单线程应用一定下降”也不是普遍结论。

实际收益取决于任务与资源竞争情况。

把三种思路放在一起看：

它们也可以同时存在：一个多核处理器，每个核心内部又支持超标量和 SMT。

  • SMP：处理器地位对称，参与相应任务执行及资源共享。

  2. 分布式协作可以通过操作系统、中间件或应用软件完成，并不都要求一个统一的“分布式操作系统”。

2 / 47多处理器与多核有什么区别？【习题 2.19、2.20】

按本章比较：

  • 多处理器系统通常强调多个独立处理器。
  • 多核强调一个处理器中集成多个执行核心。
  • 二者可以共存：一台机器安装多个多核处理器。

核心通常有自己的执行与寄存器等资源，但仍可能共享末级缓存、内存接口等，不能理解成每个核心拥有一整台完全独立电脑。

同构多核：核心的主要结构和能力相近。

异构多核：采用不同类型、性能或功耗特性的核心。

异构的目的：

让不同任务使用更合适的硬件，在性能、能耗和成本之间取得更好的配合。

例子：

  • 高性能 CPU 核处理计算压力较大的任务。
  • 低功耗 CPU 核处理较轻任务。
  • GPU 处理适合大规模数据并行的工作。
  • NPU 等加速特定计算。

讲义的麒麟 980、990 是历史实例，借它认识大核、小核、GPU、NPU 的分工即可，不必背频率和晶体管数量。

2 / 48安达尔定律：为什么增加核心不能无限加速？【重要补充计算】

假设原任务：

  • 20% 的执行时间必须串行。
  • 80% 可以理想并行。
  • 使用 n 个同等并行节点。
  • 暂不考虑通信、调度等额外开销。

则：

S=1(1−a)+a/n

其中 a 是原执行时间中可并行部分的比例，不是代码行数比例。

当 a=0.8：

使用 4 个节点：

S=10.2+0.8/4=10.4=2.5

使用 8 个节点：

S=10.2+0.1=3.33

节点无限多时：

Smax=10.2=5

这里讲它，是为了让你能定量解释“核心翻倍，程序不一定快一倍”。

实际还有并行开销，通常比这个理想模型更复杂。

2 / 5016 位寄存器怎样产生 20 位地址？【习题 2.21】

8086 的典型物理地址计算：

物理地址=(段值≪4)+偏移

左移四位，就是乘以 16，也是在十六进制末尾加一个 0。

例如：

段值：1234H
偏移：5678H

则：

  12340H
+ 05678H
--------
  179B8H

不是把两个 16 位数直接拼成 32 位地址。

不同的段值和偏移组合，也可能指向相同物理位置。

对于原始 8086，最终地址受 20 根地址线限制，超出的高位不会输出。本章先会做正常的段值加偏移计算即可。

2 / 51Pentium：用它把前面的技术串起来

  • 32 位主要整数寄存器。
  • 32 位物理地址总线，对应 4 GiB 地址空间。
  • 64 位外部数据总线。
  • 分离的 8 KiB 指令 Cache 和 8 KiB 数据 Cache。
  • U、V 两条整数流水线。
  • 浮点流水线。
  • 分支目标等预测机制。
  • 硬连线与微程序等控制思想结合。

外部数据总线 64 位，不会因此把它变成 64 位整数架构处理器。

讲义计算：

66 MHz×64/8=528 MB/s

这个结果是按每个数据拍传 8 字节得到的理想数据通路上限。实际持续传输还受到访问时序、地址和等待等开销影响。

这里介绍 Pentium，是为了让你看到：CISC 指令集同样可以通过内部组织改进，使用流水线、超标量和缓存等技术。

2 / 52习题 2.22：“Pentium 不能同时执行整数和浮点”怎样理解？

按讲义想考查的点：

整数与浮点处理共用部分前级流水和发射资源，不是两条完全独立、可任意配对的通路。

这不应该扩大成“整数与浮点指令在任何阶段都绝不可能重叠执行”。手册还规定了某些浮点指令与 FXCH 的特殊配对。

另外，讲义写共享前四级；原始手册在对应流水阶段说明中写的是前五级共享。答这题抓住共享资源与配对发射限制，不背讲义的绝对化结论。

2 / 59VA、PA、MMU、MPU、CP15、JTAG，分别是什么？

名称 本章需要知道的作用
VA，虚拟地址 程序使用的地址
PA，物理地址 翻译后用于访问物理存储系统的地址
MMU 按配置完成地址翻译、权限检查等
MPU，存储保护单元 主要提供区域访问保护等功能，通常不承担完整虚拟内存翻译
CP15 传统相应 Arm 系统中的系统控制接口
JTAG 测试、调试相关标准接口
ICE／ETM 等 调试或跟踪执行的支持
回写物理地址标记 帮助记录需要回写的 Cache 数据对应的物理位置

注意 MPU 在这里是 Memory Protection Unit，存储保护单元；第一章 MPU 表示微处理器，是另一种缩写含义。

操作系统负责内存分配及建立映射等管理工作，MMU 按配置执行翻译和保护。不能理解成 MMU 自己决定给哪个进程分配多少内存。

2.8 计算机性能评测

2 / 60性能评测，先看“完成什么任务”

讲义列了多个维度：

指标 能说明什么 不能直接推出什么
机器字长 某些数据处理和地址等能力 64 位机器执行任何程序都比 32 位快
Cache、内存容量与速度 数据供应条件 容量越大，每个程序都按比例变快
总线宽度、频率、吞吐 数据传送能力 理论带宽必然等于实际吞吐
功耗、能量 运行与续航成本 只看瞬时功率就能知道完成任务的能耗
核心数、并行能力 潜在的并行资源 核心翻倍，所有任务时间减半

EPI 是每条指令消耗的能量。不过跨不同指令集、不同任务比较时，还应关注完成同一任务的总能量。

讲义提到噪声、有害物质和废弃物处理等，是补充系统评价维度。它们对本章指令执行题没有直接作用，认识这些也是工程设计要考虑的因素即可。

2 / 61RASIS：性能好，也要可靠、可用、可维护

讲义用 RASIS 概括：

特性 含义
Reliability 可靠性 在规定条件和时间内持续正确运行的能力
Availability 可用性 系统在需要时能够提供服务的程度
Serviceability 可维护性 故障是否容易定位、修复
Integrity 完整性 信息或处理结果不被不当破坏、改变等
Security 安全性 防止未经授权的访问和操作等

相关指标：

  • MTTF：平均失效前时间。
  • MTBF：平均故障间隔时间。
  • MTTR：平均修复时间。

一般希望正常工作时间长、修复时间短。

例如 99.9% 可用性，按一年 365 天计算：

365×24×(1−0.999)=8.76 小时

意思是一年不可用时间约 8.76 小时的量级。

这里不是让你现在做可靠性工程推导，而是理解：一台跑分很高但经常停机的机器，未必满足系统需求。

2 / 62MIPS、CPI、IPC 与真正完成任务的时间【习题 2.25】

几个量：

  • IC：实际执行的指令数。
  • CPI：平均每条指令消耗多少时钟。
  • IPC：平均每个时钟完成多少指令。
  • f：时钟频率。

对同一次测量：

TCPU=IC×CPIf

按真实机器指令计数的 MIPS：

MIPS=ICT×106=fCPI×106

因此，频率、平均周期和指令数量都会影响任务完成时间。

为什么不能只看 MIPS？

假设完成同一任务：

机器 需要指令 执行速率 完成时间
A 100 万条 100 MIPS 0.01 秒
B 300 万条 200 MIPS 0.015 秒

B 的 MIPS 更高，却更晚完成。

因为不同指令集和编译结果，完成同一任务所需的指令数量和单条功能可能不同。

习题 2.25 的结论：MIPS 不能单独、普遍地客观代表计算机完成任务的速度。

2 / 63习题 2.24：300 MHz 的 ARM920T，答案为什么是 330，又为什么要说明单位？

按讲义给出的系数：

1.1MIPSMHz

乘以：

300 MHz

得到：

330

但原始 Arm 资料中的 0.9、1.1，指的是 Dhrystone VAX MIPS/MHz，即 DMIPS/MHz。

因此更准确地说：

300×1.1=330 DMIPS

这是一种基准性能分数，不能直接断言它每秒真实执行 3.3 亿条 Arm 指令。

Arm 自己的应用笔记明确区分：

  • Dhrystone VAX MIPS。
  • 根据实际指令数和平均 CPI 计算的真实指令吞吐。

真实指令吞吐仍应使用：

指令/秒=fCPI

Arm《Benchmarking with ARMulator》

做这道讲义题可以写“按给定指标为 330 MIPS”，同时理解其历史基准含义。这样既完成题目的乘法，也不会把它和 IPC 混起来。

2 / 65为什么还要介绍 JMeter、LoadRunner 等系统测试工具？

因为一个信息系统除了 CPU，还包括：

  • 网络。
  • 数据库。
  • 存储。
  • 软件架构。
  • 并发请求。
  • 业务处理流程等。

用户关心的可能是：

  • 一次请求多久返回。
  • 同时能服务多少人。
  • 每秒完成多少业务。
  • 高负载下是否稳定。

讲义列举 WebLoad、NeoLoad、JMeter、LoadRunner，以及 Katalon、WinRunner 等不同侧重点的测试工具，是为了说明系统还需要功能自动化、负载及性能等多类测试。

这里学习的必要性在于：以后你不能看到某个 CPU 参数高，就直接推断整个网站或业务系统一定快。

目标指令是转移后应执行的目标位置指令；转移代价是因确定方向、目标或冲刷等带来的额外开销；延迟槽是某些指令集规定的、分支之后具有特定执行语义的指令位置；BTB 缓存分支目标等信息。延迟槽不等于处理器碰巧取到的顺序指令。

习题 2.23 / ARM9TDMI 相对 ARM7TDMI 的改进
