第六章 · 第 01 节

这一章学什么：把指令读成状态变化

6.1，第 2—3 页；习题 6.1、6.2、6.4—6.6、6.25

掌握要求：能区分指令、指令系统、指令字、汇编表示；读代码时写出数据、地址、标志和 PC 的变化。

背景为什么要讲：第五章给出处理器有哪些状态，本章说明一条条指令怎样改变它们；第七章再组织完整程序。

机器指令是处理器能解释并执行的编码；指令字是表示这条指令的二进制位串；指令系统是某处理器支持的指令集合。汇编语言用助记符、寄存器名、常量、标号等表示操作，由汇编器生成机器码。宏和伪指令可能展开成不同条数的机器指令，不能把所有源代码行都看成一行对应一条硬件操作。

一条指令需要表达操作及必要的操作数/地址信息，有些信息是隐含的，例如 PUSH 隐含使用当前 SP，顺序执行时下一条地址由 PC 与指令长度确定。不是每条指令都显式拥有 Rd、Rn、立即数等全部字段。

本章聚焦 Armv7-M/Armv7E-M 的 Cortex-M3/M4 与 T32。A32、A64 都采用 32 位定长指令编码，T32 使用 16/32 位编码；A64 的“64”主要关联其寄存器和执行架构，不表示每条编码 64 位。M3/M4 不执行 A32/A64。原书第 6.1 节的架构/扩展表是历史定位：A 侧常见虚拟内存 VMSA，R/M 常见保护模型 PMSA，具体产品和扩展仍要核对。

原书列出的 M0/M0+/M1、M3/M4/M7、M23/M33 在基本 Thumb、IT、除法、DSP、FPU、TrustZone 等方面支持不同；Y/N/P/O 分别表示支持、不支持、部分支持、可选。表中指令总数、2019 年版本与扩展清单以查表为主，不用硬背，也不能由“都叫 T32”推断任意指令都兼容。

在本章的 32 位 M profile 语境，字节=8 位，半字=16 位，字=32 位，双字=64 位。双字传输常用一对 32 位寄存器；不意味着整数寄存器突然变成 64 位。

读任何指令，都做四个检查

  1. 操作数是数值，还是地址？是否真正访问内存？
  2. 写了哪个寄存器或内存单元？基址会不会写回？
  3. 哪些标志更新，哪些保留？后面的条件判断读哪一次结果？
  4. PC 顺序前进还是跳转？这条语法在目标内核上是否合法？

下面所有算例均假定相应代码和 RAM 已实现、权限允许；涉及未对齐或不支持的写法会单独指出。重点不是背完所有指令，而是能把这些问题答对。

第六章 · 第 02 节

从第一个半字判断长度，再看编码字段

6.2.1—6.2.2，第 3—5 页；习题 6.3、6.5、6.6

掌握要求：会判断 T32 的 16/32 位长度，知道分类前缀不等于完整合法指令。

背景为什么要讲：原书两张二进制分类表供查读；理解译码入口即可，不必默写每个操作类别的所有位。

T32 指令从半字边界开始。检查当前指令的第一个半字的 bit[15:11]：为 11101、11110、11111 时，表示一条 32 位指令的前半；其他前缀属于 16 位长度的译码入口。识别为 32 位后，还要再取一个半字，不能把第二半字又当新指令起点。

例如 0xE001 的前五位为 11100，按 16 位译码；0xF04F 的前五位为 11110，需要第二半字。判出长度并不证明全部编码合法：其中还有未分配、保留或该内核不支持的组合。

原书 16 位分类入口可以归纳为：00xxxx 常含移位/加减/比较/移动；010000 常规数据处理；010001 特殊数据处理；01001x 为 PC 相对加载；0101xx、011xxx、100xxx 涉及单数据访存；10100x/10101x 生成 PC/SP 相对地址；1011xx 为杂类；11000x/11001x 多存储/多加载；1101xx 条件分支等；11100x 为窄无条件分支。“高六位分类”不是说每条指令都只有固定的六位操作码。还要继续看子字段及特殊保留组合。

32 位分类会结合第一个半字的 op1、op2 及第二半字中的相关位：多寄存器、双字/独占、移位寄存器数据处理、立即数数据处理、分支/杂类、各宽度加载存储、乘法及协处理器类等。原书表 6.5 的作用是展示分层译码，不是要求你靠肉眼完整反汇编所有机器码。

注意字节序：若两个半字按编码顺序为 EA4F、0001，小端内存字节是 4F EA 01 00。不能先把这四字节当一个普通小端 32 位数读成 0x0001EA4F，再去看那个数的最高五位判断第一半字。

第六章 · 第 03 节

汇编语法：逗号、方括号、后缀分别表达什么

6.2.3、6.2.5，第 5—10 页

掌握要求：能识别操作码、操作数、条件、S、.N/.W，区分语法说明符号与真正要输入的符号。

背景为什么要讲：UAL 统一写法便于同一源文件选用不同长度编码；它不让任意参数组合都变合法。

UAL 是 Unified Assembly Language，统一汇编语言。典型写法可读作“助记符及适用后缀 + 操作数列表”，如 ADDS.W R0,R1,R2：加法、更新相应标志、选择宽编码，结果写 R0。

符号/名字 作用 例子
Rd / Rt 目标或传输寄存器占位名 LDR R8,[R1,#4] 中 R8 为加载目标
Rn / Rm 源或基址/偏移寄存器占位名 含义由指令定义决定
# 立即数前缀 #10、#0x10 分别是十进制 10、十六进制 16
[...] 在实际访存语句中表示地址表达式 [R1,#4] 是计算地址去访存
! 相应寻址形式中的基址写回 [R1,#4]!
{R1-R4} 实际代码中的寄存器列表 包含 R1、R2、R3、R4
; 本讲义采用的 Arm 风格注释 GNU 工具需按其注释语法转换

手册中的 <Rd>、{S}、[cond] 等是占位或可选语法说明，不全部照字面输入。尤其不能把手册的“方括号表示可选”与实际 LDR 的“方括号表示地址”混淆。

S 表示按该条指令规则更新标志，不是“所有 APSR 位都重写”。.N/.W 选择窄/宽指令编码，不改变访问的数据宽度；LDR.W 仍可取一个 32 位字，LDRB.W 仍只取一个字节。MOVW 的 W 则是助记符的一部分，和 MOV.W 是两件事。

不是所有指令都能任意加 S、.N、.W 或条件后缀。没有对应编码时汇编器应拒绝，不能靠后缀强迫硬件提供能力。不同工具还会选择不同别名或省略形式，本讲义优先给清楚、可核对的写法。GNU 汇编器的 Arm 语法与操作码说明

第六章 · 第 04 节

MOV、MOVS、MOV.W：看懂同一种操作的不同编码

6.2.5，第 7—10 页

掌握要求：能解释功能、长度与标志三个维度，能把两个半字顺序与小端字节写对。

背景为什么要讲：T1/T2/T3 是某条指令说明里的编码编号，不是整个架构通用的三个指令等级。

以不在 IT 块内的 R1→R0 复制为例：

汇编 编码半字（按取指顺序） 字节数 标志行为
MOV R0,R1 4608 2 不更新算术标志
MOVS R0,R1 0008 2 更新 N/Z；此复制形式保留 C/V
MOV.W R0,R1 EA4F 0001 4 不更新算术标志
MOVS.W R0,R1 EA5F 0001 4 此复制形式更新 N/Z，保留 C/V

16 位 MOV 的寄存器字段和支持的寄存器范围与窄 MOVS 不同；MOVS 的窄复制可看作移位量为 0 的相应移位别名。宽 MOV 留出更多编码空间表达寄存器及 S 等选择。同一数据结果可以有不同编码长度和标志副作用。

原书脚注说 MOV 不可能产生某些宽编码，与同页 MOV.W 示例相矛盾，不应照背。T1/T2/T3 要连同具体指令页读取；不能推出“所有 T1 都不改标志，所有 T2 都改标志”。IT 块中的部分窄指令还存在上下文相关的标志行为，因此要看实际编码与上下文。

做编码题先把字段填入相应模板，再拼成半字，最后按需要写内存字节。读程序结果题则先问有没有 S、它究竟更新哪几位，通常不需要背全部机器码。

第六章 · 第 05 节

N、Z、C、V、Q：特别把减法的 C 讲清楚

6.2.4，第 6—7 页；习题 6.8

掌握要求：会算 32 位加减的 N/Z/C/V，解释有无符号是解释方式而非不同加法电路。

背景为什么要讲：后面比较、分支、多字长运算都依赖这里；标志不能靠“结果看起来像负数”猜。

N=结果 bit31，Z=结果全零，C 由相应算术/移位规则决定，V 表示有符号范围溢出。32 位加法结果保留低 32 位，C 记录无符号加法是否产生第 33 位；减法通常按加补码实现，C=1 表示没有借位，即无符号被减数不小于减数。

运算 低 32 位结果 N Z C V 为什么
0xFFFFFFFF+1 0x00000000 0 1 1 0 无符号进位；有符号 −1+1 不溢出
0x7FFFFFFF+1 0x80000000 1 0 0 1 无无符号进位；正数相加越过有符号上限
0−1 0xFFFFFFFF 1 0 0 0 无符号需要借位，有符号结果 −1 合法
0x80000000−1 0x7FFFFFFF 0 0 1 1 无符号没有借位；有符号越过下限

Q 不是普通的“上一条指令是否溢出”：它是相关指令可能置位的黏性饱和/溢出状态，未发生新事件时往往保留旧值；需要按规定清除。M4 的 GE[3:0] 则由部分 SIMD 指令提供逐通道信息，不是普通有符号分支条件 GE 的四位编码。

要读懂“最后一次更新该标志的操作”。LDR/MOV 或无 S 的算术不一定更新；SSAT 常只涉及 Q；MULS 常更新 N/Z 而保留 C/V。不能把所有标志都归给刚执行的最后一条指令。

第六章 · 第 06 节

CMP 后怎样选条件：有符号和无符号不能混

6.2.4、6.4.8—6.4.9；习题 6.7

掌握要求：会用 EQ/NE、HI/LS、CS/CC、GT/LE、GE/LT，能解释 N 与 V 为什么要结合。

背景为什么要讲：条件表要全见过；常用条件必须会选，冷门条件可按标志查表。

CMP R0,R1 按 R0−R1 计算标志，不把差写回 R0。之后比较同样的位串，如果你要按无符号解释，就用 HI/LS、HS/LO 等；如果按补码有符号解释，就用 GT/LE、GE/LT。EQ/NE 仅判断是否相等，两种解释都适用。

条件 判断式 主要意义
EQ / NE Z=1 / Z=0 等于 / 不等于
CS（HS） / CC（LO） C=1 / C=0 无符号 ≥ / <；也用于相应进位条件
MI / PL N=1 / N=0 结果最高位为 1 / 0，非完整有符号大小比较
VS / VC V=1 / V=0 有符号溢出 / 未溢出
HI / LS C=1 且 Z=0 / C=0 或 Z=1 无符号 > / ≤
GE / LT N=V / N≠V 有符号 ≥ / <
GT / LE Z=0 且 N=V / Z=1 或 N≠V 有符号 > / ≤
AL 恒真 无条件；一般省略

例：R0=0xFFFFFFFF，R1=1，CMP 后 N=1、Z=0、C=1、V=0。无符号是 4294967295>1，HI 成立；有符号是 −1<1，LT 成立。两者都正确，只是在回答不同问题。

为什么不只看 N？0x80000000−1 得 0x7FFFFFFF，N=0，但原来的有符号 −2147483648 明明小于 1。这是减法发生 V=1，需用 N≠V 判断。原书表 6.6 将 LE 的中文写成无符号，是笔误；LE 是有符号 ≤。

第六章 · 第 07 节

IT 块：直线执行中的条件选择

6.2.5、6.4.9 的条件执行，第 9—10、30—31 页；习题 6.7、6.41

掌握要求：会写 IT、ITT、ITE、ITTE/ITTEE 等，并按 T/E 对照条件；分清条件执行与条件跳转。

背景为什么要讲：用于短小分支，未必比跳转总更快；性能要看路径与实现。

M3/M4 的普通条件数据处理通常须放在 IT 块中。IT{x{y{z}}} cond 最多控制后面四条指令，第一条隐含 T，额外字母依次描述第二、三、四条。T 表示与首条件一致，E 表示取相反条件；不是 E 就永远不执行。

CMP R0, #0
ITE EQ
MOVEQ R1, #10
MOVNE R1, #20

若 R0=0，只执行第一条赋值；否则只执行第二条。源代码中的 EQ/NE 要与 IT 模式匹配。不要在不了解上下文时直接单写 MOVEQ 并假设所有汇编器都自动补 IT；自动插入属于工具选项，不是机器保证。

ITTEE EQ 控制四条，条件依次是 EQ、EQ、NE、NE；ITETT NE 则是 NE、EQ、NE、NE。字母数算不清时，把“第一 T + 后缀字母”逐项展开。

IT 块不能随意嵌套；改变 PC 的分支等须遵守只能位于块末等限制，某些指令不允许在块内。中途更新标志会影响后续条件，且部分编码有专门限制。入门例子应避免在块内修改条件依赖的 APSR，而不是背成“架构下绝无任何能更新标志的块内情况”。

BEQ 用标志决定改不改 PC，MOVEQ 用条件决定改不改数据寄存器。前者跳转后从另一处取指；后者保持直线位置前进。IT 不需要把每条普通指令都扩出四位条件字段，这正是它与本章编码格式的联系。

第六章 · 第 08 节

立即数：先问是哪条指令的哪一种编码

6.3.1，第 11—12 页；习题 6.10—6.12

掌握要求：能解释字段有限，区分 imm8、imm12、MOVW/MOVT 与修饰立即数，不把一套规则推广给所有指令。

背景为什么要讲：修饰立即数算法用于读编码，日常可借汇编器判断；常见合法/非法例子必须知道原因。

立即数包含在指令自身，MOVS R0,#66 不去 RAM 取 66。32 位编码还要容纳操作码和寄存器等，不可能让每条指令同时直接携带任意 32 位常量，但不同指令有不同表示办法。

形式 典型限制/用途
窄 MOVS 的立即数 8 位，目标通常为低寄存器
MOVW / MOVT 各提供 16 位常量，组合构造 32 位值
ADDW / SUBW 对相应寄存器加减未移位 imm12，即 0—4095 等编码约束
某些宽数据处理指令 采用 Thumb 修饰立即数（modified immediate）
LDR/STR 的地址偏移 按该访问的编码、缩放和写回形式限制，不能套数据运算立即数表

修饰立即数包含一个字节、字节重复（00ab00ab、ab00ab00、abababab）和特定旋转的位图等。精确算法是在旋转分支构造带最高有效 1 的 8 位模式再进行相应 32 位旋转；并非“任意 8 位数在任意 16 位寄存器里转几圈”。零重复组合等还受编码规则限制。

编码查读补充：若 imm12[11:10]=00，由 [9:8] 选择低 imm8 的直接零扩展或上述三种重复（重复分支的 imm8 不能为 0）；否则先构造 0x80 | imm12[6:0]，再按 imm12[11:7] 给出的量做 32 位 ROR，该分支旋转量为 8—31。理解“有限字段经规则展开”即可，日常常量是否合法可交汇编器核对，不需穷举记忆全部值。

原书的 0x01FC 可由八位模式扩展旋转形成；0x07FC 的连续 1 超出该类位图的表示能力。但 0x07FC 仍可用于 MOVW 或相应 ADDW 等，不能称为所有指令的非法立即数。原书 ADDS R0,R0,#0x1234 也不能直接因为“十六进制不大”就认定合法，应先用 MOVW 装入另一个寄存器，再做寄存器加法。

任意 32 位常量可用 MOVW+MOVT，或 LDR Rd,=常量 伪指令交给工具选择合适序列。伪指令的加载常量不等于从那个数值表示的地址读数据，详见第 14—15 节。

第六章 · 第 09 节

数值与地址：寄存器直接、间接和移位操作数

6.3 概述、6.3.2—6.3.4，第 11—12 页；习题 6.10、6.12、6.13

掌握要求：会把操作数分为立即数、寄存器值、存储器内容；正确区分读内存与参与地址/算术计算。

背景为什么要讲：源文“ADD 直接带 [R2]”等例子跨了指令集边界，需要在这里纠正。

设 R1=0x20000100，那个地址的内存字为 7：MOV R0,R1 得到的是 0x20000100 这个数值；LDR R0,[R1] 才读出内存中的 7。前者为寄存器直接，后者为寄存器间接。存储器地址本身也是一个整数，区别由指令怎么使用它决定。

M3/M4 采用加载/存储分工，普通 ADD 不能写成 ADD R0,R1,[R2]。要先加载：

LDR R3, [R2]
ADD R0, R1, R3

数据处理的移位寄存器操作数，是把寄存器值先移位再参与运算，如 ADD R0,R1,R2,LSL #2 表示 R1+4×R2，没有内存访问，也不把移位结果写回 R2。这里所谓“寻址”是原书宽泛的操作数形成方式。

独立移位指令可用寄存器给移位量，例如 LSL R0,R2,R1；原书的 MOV R0,R2,LSL R1 在支持这种别名的工具中可转成相应寄存器移位指令，本讲义优先写显式 LSL 便于识别。不能由此推断普通 ADD 等也能任意附带寄存器指定移位量。立即数嵌入移位、寄存器控制的独立移位、访存地址中的缩放各有自己的编码限制，应以目标编码核对。

三种索引：先算本次地址，再单独算写回

掌握要求：能分别写出有效地址 EA 与执行后基址 Rn；遇到连续代码不擅自把基址重置。

背景为什么要讲：这是本章寻址题的核心；改变数据宽度不会改变偏移的字节单位。

设执行前基址 B=0x20000100，立即数偏移 d=8，分别独立执行下列指令：

写法 本次 EA 执行后的 R1 口诀
LDR R0,[R1,#8] B+8 B 加偏移访问，不写回
LDR R0,[R1,#8]! B+8 B+8 加偏移访问，且写回
LDR R0,[R1],#8 B B+8 用旧基址访问，之后写回

每次都先写两列，内存访问地址与执行后的基址是两个结果。! 不是“再读一遍内存”，逗号放在 ] 外也不是排版差异。偏移可以为负，依具体编码范围；如 −4 表示地址退 4 字节，而非退四个字。

原题 6.19 的 0xB 怎么看

如果三行分别从相同 B 开始：偏移形式 EA=B+0xB、不写回；前变址 EA=B+0xB、写回 B+0xB；后变址 EA=B、写回 B+0xB。若三行连续执行，第二行已改变 R1，第三行必须使用那个新值，最终 R1=B+0x16。

0xA/0xB 这类偏移还可能让字访问未对齐。本节先求逻辑 EA；实际是否成功，要结合 Normal/Device、指令和非对齐配置，不能仅凭地址计算正确就断言一定读成功。带写回的加载还要避开基址与目标寄存器重叠等受限组合。

第六章 · 第 11 节

缩放寄存器偏移：数组下标怎样变成字节地址

6.3.5、6.4.2 的寄存器移位模式，第 12—13、20 页；习题 6.14、6.17—6.18

掌握要求：会把元素下标乘元素字节数，用 LSL 形成偏移；基址和下标均不因普通偏移形式而写回。

背景为什么要讲：数组、结构体和查表都要用到；这是桶形移位器参与地址计算的具体用途。

若 R1 指向 32 位数组 a 的首元素，R2=i，则 a[i] 的地址为：

EA=B+i×4=B+(i≪2)
LDR R3, [R1,R2,LSL #2]   ; 读取 a[i] 的一个字

字节数组无需乘 4，半字数组常乘 2。下标本身不是字节偏移；题目若已经给 R2 为字节偏移，再左移 2 位就多乘了一遍。

LDM/STM：寄存器号越小，对应地址越低

6.3.8、6.4.2 的多加载/多存储，第 14—15、20—21 页；习题 6.20、6.21

掌握要求：能独立画 IA/IB/DA/DB 的地址表与写回，明确 M3/M4 支持 IA/DB 的边界。

背景为什么要讲：四模式是经典 Arm 的通用模型；原题同时包含本内核不支持的 IB/DA，也要讲清原理。

LDM=Load Multiple，连续内存字加载到多个寄存器；STM=Store Multiple，多个寄存器写到连续内存字。列表中的寄存器可以不连续，但实际映射遵循最低寄存器号对应最低传输地址，不由你书写列表的先后决定。

设 B 为原基址，n 为寄存器数，每字 4 字节：

模式 最低传输地址 最高传输地址 若写回，基址成为
IA B B+4n−4 B+4n
IB B+4 B+4n B+4n
DA B−4n+4 B B−4n
DB B−4n B−4 B−4n

例：B=0x20000100，列表 {R1-R4}，DB 模式对应 R1→0x200000F0、R2→F4、R3→F8、R4→FC。不是 R1 先去 B−4，然后 R2 再去 B−8。原书“每取一个再递减”的口头说明容易在这里导致逆序，应先算整个区间再按寄存器号填。

! 只决定是否把调整后的基址写回，不决定传输地址有没有递增/递减。原题 STMIA R9,{R1-R4} 无 !，传输照常覆盖四个连续字，但 R9 不变。

T32 的 M3/M4 对应多传输使用 IA、DB；STMIB/STMDA 不应当作它们能直接汇编的指令。原题 6.21 仍可按上表解释经典模型，并说明目标内核限制。寄存器列表大小、SP/PC/LR、基址是否也在列表里等均有编码约束，入门例子避免重叠。

第六章 · 第 13 节

PUSH/POP 与 FD 别名：批量压栈不是逐项反序写入

6.3.9、6.4.2 的压栈/出栈，第 15、21 页；习题 6.22—6.24

掌握要求：会写 FD 栈的存取对应关系，算 SP 与各寄存器地址；理解返回地址为何要保存。

背景为什么要讲：接上第五章的满递减栈，后续函数调用必须用得熟练。

M3/M4 的常用栈是满递减：压栈向低地址生长，弹出后 SP 增大。主要别名关系：

含义 常见写法 相应地址模式
压栈 PUSH {R1-R4} STMDB SP!,{R1-R4}；也写 STMFD
弹栈 POP {R1-R4} LDMIA SP!,{R1-R4}；也写 LDMFD

SP 原为 0x20001000，压四个字后 SP=0x20000FF0；从低到高分别保存 R1、R2、R3、R4。一次 PUSH {R1-R4} 与四条“先 R1、再 R2、再 R3、再 R4”的单独 PUSH 布局不同。POP 也按寄存器号与地址映射，不是任意从列表末尾开始。

原题 6.22 的 STMFD SP!,{R1-R8} 与 STMDB 为同一满递减存储含义，n=8、SP 减 32；6.23 的 LTMFD 是拼写错误，应为 LDMFD，与 LDMIA 相应，SP 加 32。

FD、EA 等是“栈的组织名称”，IA、DB 等是“具体多传输地址模式名称”。同样 FD 栈，存时用 DB，取时用 IA。原书 LDMEA/STMEA 作为其他组织的背景，应按“存与取互为恢复”理解，不能只见一个字母就把 LDMDB 当本章标准 POP。

PUSH/POP 的可用寄存器受窄/宽编码限制；涉及 R8 等可能需宽编码。浮点 VPUSH/VPOP 还能保存 S/D 寄存器，64 位 D 视图是传输单位，不因此获得双精度算术。栈区需真实可写、容量足够并维持相应对齐，不能为了少写一条指令破坏调用约定。

PC 相对：地址、该地址的内容和文字池要分三步

6.3.10、6.4.2 的 PC 相对模式，第 15—16、21—22 页；习题 6.24

掌握要求：会用当前指令地址 +4 与相应对齐计算 literal 地址，区分 ADR、LDR 地址形式和 LDR 伪指令。

背景为什么要讲：文字池解决大常量编码问题；下一章才系统学习数据定义和汇编控制。

Thumb 读取 PC 有架构规定的偏移，常见为当前指令地址 A+4；字面量加载和 ADR 等还会使用按字对齐的 PC 基址。不能把源码行号当字节地址，也不能一概把“PC+4”理解为跳过下一条源代码行。

以一条位于 A=0x08001002 的字面量 LDR 为例：可见 PC=A+4=0x08001006，按字对齐得 0x08001004。LDR R0,[PC,#0xC] 从 0x08001010 读字，而非从 A+0xC 读取。具体偏移范围和正负由编码决定。

写法 得到什么
ADR R0,label 生成附近标号地址，不读取该地址的数据
LDR R0,[R1] 读取 R1 指向的内存字
LDR R0,[PC,#offset] 读取 PC 相对位置的内存字
LDR R0,=0x12345678 伪指令：使 R0 得常量 0x12345678，由工具选择实现

第六章 · 第 15 节

内部传送：MOVW/MOVT、MVN、MRS/MSR

6.4.1，第 16—17 页；习题 6.9、6.35

掌握要求：会构造 32 位常量，知道 MOV 不代替 LDR，特殊 CPU 寄存器不用普通内存访存语法。

背景为什么要讲：指令表每一项都要认识；这几条是系统初始化与常量加载的基础。

MOV 复制寄存器值或装载可编码的立即数，不直接读取任意内存单元。内存到通用寄存器通常用 LDR 系列。因此 MOV R0,[R1] 不能取代 LDR R0,[R1]。

MOVW 写入一个 16 位立即数到目标低半并清零高半；MOVT 修改高 16 位，保留低半。构造 0x12345678：

MOVW R0, #0x5678      ; R0=0x00005678
MOVT R0, #0x1234      ; R0=0x12345678

顺序不能随意交换：先 MOVT 再 MOVW，后者会清掉之前的高半。MVN 则是按位取反，MVN R0,R1 得 ~R1，不等于数学取负 −R1；补码取负通常还要加 1，或用 RSB 从 0 减。

MRS 从特殊寄存器读到一般寄存器，MSR 反向写入，例如 MRS R0,PRIMASK、MSR CONTROL,R0；修改需满足权限与同步要求。SCB/NVIC 的内存映射寄存器则通过地址访问。第五章已区分 CPU 特殊寄存器与 MMIO，此处把对应指令接上。

第六章 · 第 16 节

LDR/STR 的宽度：加载扩展，存储截取

6.4.2、第 17—22 页；习题 6.26—6.28、6.34、6.51、6.52

掌握要求：会根据宽度和有无符号选指令，计算 8/16 位值进入 32 位寄存器后的结果。

背景为什么要讲：原书各寻址模式反复列不同大小，本节用一套规则解释它们，避免机械背重复表。

读取指令 读取多少 高位怎样填 相应写入
LDRB 8 位 零扩展到 32 位 STRB 只写源寄存器低 8 位

第六章 · 第 17 节

带 T 的非特权访存：内核替用户检查访问

6.4.2 的非特权等级加载/存储，第 22 页；习题 6.45

掌握要求：说明这些指令为什么存在，以及它们不会把调用者整体永久降权或给用户提权。

背景为什么要讲：属于系统编程背景，现阶段不必实现完整用户缓冲区 API，但要懂保护边界。

特权操作系统要替用户读写一段缓冲区，不能只凭自己“权限够大”就把用户本不该访问的数据传出去。LDRT/STRT 等允许特权代码按非特权数据访问规则完成该次访问，从而发现不合法的用户地址。

原书列出 LDRBT、LDRSBT、LDRHT、LDRSHT、LDRT，以及 STRBT、STRHT、STRT；B/H、SB/SH 的宽度与扩展含义和前节一致，T 在这里表示该类非特权访问语义。其立即数偏移等限制须查具体编码。

这不把 Handler 变成非特权模式，也不让用户绕过 MPU。数据曾由特权程序写过，不意味着它必然受保护；真正限制来自区域权限与核心系统规则。访问被拒绝可能产生相应 Fault，系统还需设计错误处理，不能把一条访存当完整、无竞争的安全检查协议。

    LDREX R1, [R0]

    CMP   R2, #0
    BNE   retry

第六章 · 第 19 节

加减、进位与借位：把 64 位运算接起来

6.4.3，第 23—24 页；习题 6.9、6.50

掌握要求：会写 ADD/ADC、SUB/SBC 的关系，理解 RSB，能追踪两字组成的 64 位加减。

背景为什么要讲：相同位宽加法通常共用电路；跨字运算必须正确传递低字的 C。

ADD 得 A+B；ADC 得 A+B+C。SUB 得 A−B；SBC 得 A−B−(1−C)，不能误写成 A−B−C。RSB（Reverse Subtract）交换相减方向，例如 RSB R0,R1,#0 得 −R1 的补码结果。ADDW/SUBW 主要提供相应直接立即数形式，W 不代表 64 位加法。

两对寄存器 {R1,R0}、{R3,R2} 分别为高字、低字，64 位加法：

ADDS R0, R0, R2       ; 先低字，产生 C
ADC  R1, R1, R3       ; 高字加上低字进位
0x00000001FFFFFFFF+0x0000000200000001=0x0000000400000000

64 位减法对应先 SUBS R0,R0,R2，再 SBC R1,R1,R3。例如 0x0000000200000000−0x0000000100000001：低字 0−1 得 FFFFFFFF、C=0；高字 2−1−1=0，结果为 0x00000000FFFFFFFF。

低字与高字之间不要插入会破坏 C 的指令。最终想得到完整 64 位的零/符号等状态，还需按需求组合；只看高字操作的 Z 不足以说明两个字全为零。

第六章 · 第 20 节

MUL、长乘法、MLA/MLS：先决定要留下多少位

6.4.3、6.4.12 的公共乘法表，第 24、36 页；习题 6.9、6.47、6.50

掌握要求：能区分 32 位低结果与 64 位完整结果，读懂 RdLo/RdHi 与累加关系。

背景为什么要讲：乘法是 DSP 的基础，结果位宽和符号解释会决定用哪条指令。

MUL 取 32×32 乘积的低 32 位。对同样的输入位串，有符号与无符号乘法的低 32 位相同，但完整 64 位的高部可能不同；因此不能简单把 MUL 叫成“只会无符号乘法”。有符号结果是否溢出，也不能靠 MUL 不更新 V 来证明没有。

指令 数学含义 结果
MUL Rn×Rm 的低部 32 位
MLA Ra+Rn×Rm 的低部 32 位
MLS Ra−Rn×Rm 的低部 32 位
UMULL / SMULL 无符号 / 有符号完整乘积 RdHi:RdLo 共 64 位

例：位串 FFFFFFFF 与 00000002。UMULL 得 00000001:FFFFFFFE；SMULL 把前者解释为 −1，得 FFFFFFFF:FFFFFFFE。低字一样，高字不同。64 位寄存器对的写法里 RdLo 通常先写在操作数列表，不要因数学显示“高:低”就倒填。

MAC（Multiply-Accumulate，乘并累加）对应点积 ∑xihi，常见于 FIR 滤波、相关、矩阵乘法。MLA 可减少乘后再加的指令，但要选择足够累加位宽。MULS 的某些窄形式可改 N/Z；这些长乘及 MAC 通常不提供普通 S 后缀，不能一概假定更新 NZCV。

除法与定点缩放：同一位串可以代表不同数

6.4.3 与扩展背景；习题 6.48—6.50

掌握要求：区分 SDIV/UDIV，理解整数与定点共用电路的条件，能做简单 Q15 乘法缩放。

背景为什么要讲：星号题仍然讲到，但不要求现在设计完整乘除法器。

UDIV 按无符号除法；SDIV 按有符号补码，商向零截断。例如 SDIV 的 −7/3=−2；若同样的 0xFFFFFFF9 当无符号，商就完全不同。整数低位乘积可以相同，不代表除法也能不分符号。

Q15 示例：0.5↔16384=0x4000
0x4000×0x4000=0x10000000(30 个小数位)
右移 15 位得 0x2000=8192⇒8192/32768=0.25

这解释了为什么 DSP 需要乘加、算术移位、饱和和符号扩展。浮点则还需处理指数、对阶、规格化与舍入，见第 37 节；不能把定点/浮点的差异说成只换一条注释。

指令 按位运算 常用目的
AND A & B 只保留掩码允许的位
ORR A | B 掩码为 1 的位置置 1
EOR A XOR B 掩码为 1 的位置取反

第六章 · 第 23 节

LSL、LSR、ASR、ROR、RRX：把移出的位画出来

6.3.4、6.4.5，第 12、25—26 页；习题 6.36—6.38

掌握要求：会算五种移位、移出位与 C，知道算术右移保符号，RRX 使用原 C。

背景为什么要讲：桶形移位器还可参与其他数据处理；零和超过字长的移位属于查规则层，不能忽略。

操作 空位/回填 右移一个位的例子，输入 0x80000001
LSL 低位补 0，高位丢弃 左移 1 得 0x00000002
LSR 高位补 0 0x40000000
ASR 高位复制原符号位 0xC0000000
ROR 移出的低位回到高端 0xC0000000
RRX 只右移 1 位，高端填原 C C=0 得 0x40000000；C=1 得 0xC0000000

这组数恰好使 ASR 与 ROR 的结果相同，不代表二者相同；改用 0x80000000，ASR #1 得 C0000000，ROR #1 得 40000000。RRX 把“原 C + 32 位寄存器”当扩展通道，输出的旧 bit0 可用于更新 C；ROR 不以原 C 作为回填位。

带 S 的对应指令按规则更新 N/Z/C，V 通常保留；不带 S 时 APSR 的 C 不因图中出现一个“移出位”就自动改变。RRX 即使不改标志，仍要读取原 C 来填高位。

移位量的边界别用一种规则包办

立即数编码常见 LSL #0—31、LSR/ASR #1—32、ROR #1—31；寄存器给量则使用相应低 8 位，可出现 0、32、>32。寄存器量为 0 常保留结果与 C；LSL/LSR 为 32 时结果 0，C 分别来自原 bit0/bit31，超过 32 时结果与 C 为 0；ASR≥32 则全填符号位。ROR 非零的 32 倍数结果不变但更新 C 的规则与“移位量为 0”不同。

因此“最多只能移 32 位”不是全部寄存器形式的准确限制。日常做题先明确编码/移位形式，再处理边界；图采用寄存器给量的模型并明确 S 开关。

第六章 · 第 24 节

扩展与字节反转：改变表示宽度不等于数值转换

6.4.6，第 26—27 页；习题 6.34、6.51、6.52

掌握要求：会算 SXTB/SXTH/UXTB/UXTH 和 REV/REV16/REVSH，知道符号位来自截取的数据。

背景为什么要讲：访存加载时可扩展，寄存器内部也可扩展；两者分开认识才能看懂 DSP 数据整理。

SXTB/SXTH 取源低 8/16 位做符号扩展，UXTB/UXTH 取同样的低部补零。R0=0x22AA8765 时：SXTB 和 UXTB 都得到 0x65；SXTH 得 0xFFFF8765；UXTH 得 0x00008765。符号取自被截取部分的 bit7/bit15，不是一律看原寄存器 bit31。

这些指令的某些宽形式还可先 ROR #8/#16/#24，再取低部，方便提取另一个字节/半字。保留数值的前提是解释原数据类型；不同类型使用不同扩展，否则 0x88 可能从 −120 误变 136。

REV 把四字节反序；REV16 在两个半字内部各交换字节；REVSH 只交换低半字的两个字节，再以交换后的 bit15符号扩展。输入 0x12345678：REV 得 0x78563412，REV16 得 0x34127856；输入 0x44558899，REVSH 得 0xFFFF9988。

原书示例 REVH 应写 REV16。这些是字节重排，不是把每个字节的 bit 全部倒序；位序反转用下一节 RBIT。也不是把浮点位串变为其整数数值的转换指令。

6.4.7，第 27—28 页

掌握要求：能根据 lsb 与 width 划范围，手算 BFC/BFI/UBFX/SBFX；知道 CLZ 与 RBIT 的用途。

背景为什么要讲：用于寄存器字段与压缩数据，常比连续掩码移位更直接；不需要背每个二进制操作码。

指令 功能
BFC Rd,#lsb,#width 把目标该段清 0，其余位保留
BFI Rd,Rn,#lsb,#width 把 Rn 的低 width 位放进目标该段，其余位保留
UBFX Rd,Rn,#lsb,#width 提取该段到低部，再零扩展
SBFX Rd,Rn,#lsb,#width 提取该段到低部，以字段最高位做符号扩展

背景为什么要讲：完整函数约定在第七章，本节先把控制流和返回链条建立起来。

B 跳到标号，不建立新的返回链接；BL 跳到标号并把返回信息放 LR；BX 按寄存器给出的目标分支；BLX 的相应寄存器形式还建立返回链接。M3/M4 仍在 Thumb，BX/BLX 的合法目标 bit0 应标识 Thumb。

函数自身还调用另一个函数，第二次 BL 会覆盖 LR，必须在合适位置保护原返回链接，例如 PUSH {R4,LR}、调用、POP {R4,PC}，并遵守对齐/保存约定。B 并非任何情况下都不能用于函数相关控制流：尾调用等可有意不建立新链接；习题要答的是普通可返回调用为什么用 BL/BLX 更方便。

跳转范围按编码查，不能只认助记符

B.W / BL 的宽直接分支 −2²⁴ 到 +2²⁴−2（约 ±16 MiB）
Bcond.N（块外） −256 到 +254
Bcond.W（块外） −2²⁰ 到 +2²⁰−2（约 ±1 MiB）

TBB/TBH：查表地址与跳转基准不是一回事

6.4.9 的跳转表，第 31—32 页

掌握要求：能独立完成“算表项地址 → 读取无符号项 → 乘 2 → 加分支 PC”的过程。

背景为什么要讲：用于 switch 等多分支，原书的文字把表基址与跳转基准混在一起，需要明确拆开。

TBB 访问字节表，语法 TBB [Rn,Rm]；TBH 访问半字表，语法 TBH [Rn,Rm,LSL #1]。设该条 32 位指令位于 A，表基址 B 在 Rn，下标 i 在 Rm：

TBB 表项地址=B+i,e=Mem8[B+i]
TBH 表项地址=B+2i,e=Mem16[B+2i]
目标地址=A+4+2e

表放在哪里由 Rn 决定；跳到哪里从该分支指令后的位置 A+4 起算。表项存的是半字单位的无符号偏移，不是完整 32 位目标地址。原文“相对表首地址跳转”仅在表首恰好也是那个基准时才成立。Arm M4 的 TBB/TBH 指令定义

例：TBB 位于 0x08000100，R0=0x08000200，R1=2，表地址 0x08000202 内的字节是 0x12，则目标=0x08000104+0x24=0x08000128，不是 0x08000224。

TBB 的表项最大 255，对应前向 510 字节；TBH 最大 65535，对应 131070 字节。表项索引距离和目标分支距离是两套量。Rn 可按规则用 PC 指向紧接指令的表，不能用 SP；Rm 不能为 SP/PC，并且要先检查下标范围。它们不修改条件标志；IT 内还须遵守块末等限制。

原书 DCB 用来定义字节数据，具体伪指令到第七章学习。构造表项时用 (目标−分支后基准)/2，再确认偏移非负且放得进相应表项，不能把任意标签差直接塞进去。

6.4.10，第 32—33 页；习题 6.43

背景为什么要讲：第五章讲削顶原因，本节落实到指令；饱和并不恢复已经丢失的精度。

SSAT 把输入夹到 n 位有符号范围；USAT 把其有符号输入值夹到 n 位无符号输出范围。结果仍放在 32 位寄存器，负的 SSAT 结果会符号扩展。可选移位在饱和前进行，须满足具体编码限制。

SSATn(x)=min(2n−1−1,max(−2n−1,x))
USATn(x)=min(2n−1,max(0,x))
输入位串（按有符号） SSAT #16 USAT #16
00020000 00007FFF 0000FFFF
00008000 00007FFF 00008000
00007FFF 00007FFF 00007FFF
00000000 00000000 00000000
FFFF8000（−32768） FFFF8000 00000000
FFFF7FFF（−32769） FFFF8000 00000000
FFFFFFFF（−1） FFFFFFFF 00000000

SSAT 的 n 可按规则为 1—32，USAT 为 0—31；USAT #0 的合法输出只有 0。USAT 不是先把 FFFFFFFF 当 4294967295，再夹到最大值，本例它按 −1 夹到 0。

溢出是数学结果超出表示范围的现象，截断/回绕是一种处理结果；饱和是另一种夹到上下限的处理。不能把“丢掉高位”直接当作溢出的完整定义。SSAT/USAT 发生饱和会置 Q，未饱和时通常不清旧 Q，NZCV 并非一并重算。

若先用普通 32 位加法把真实结果溢出丢掉，再做 SSAT #32，已无法恢复那个数学结果；必须在正确位宽和合适阶段使用饱和或更宽中间结果。信号幅度削顶后仍有失真，只是避免回绕导致的突然反向。

第六章 · 第 32 节

WFI、WFE、SEV：等待中断与等待事件

6.4.11，第 33—34 页

掌握要求：解释 WFI/WFE 区别，知道 WFE 会消费已记录事件，不保证每次执行都真的休眠。

背景为什么要讲：低功耗不是普通算术题重点，但与中断和实时系统有关，需要知道用途。

WFI=Wait For Interrupt，等待中断相关唤醒条件；WFE=Wait For Event，等待事件；SEV=Send Event，发送事件，作用包括本处理器的事件记录，并可由系统传播给其他处理器。

WFE 有一个简化的事件记录模型：记录为 1 时，执行 WFE 清掉记录并直接继续；记录为 0 时，才可能等待后续事件。不是把所有事件按次数排进 FIFO，已经记录时多个事件可能合并。

唤醒以后是否立即进入 ISR，与能否从等待中醒来不是同一判断，还涉及 IRQ 使能、屏蔽、优先级和电源/时钟集成。存在已满足的条件时，WFI 也不保证一定停住。原书“立即进入休眠”应按这种条件理解。

深睡眠、异常退出后睡眠等还与 SCB 的 SCR 和芯片电源控制配合。这里只需认识用途和事件记录行为，暂不要求设计无竞争的完整睡眠协议；不能不查芯片就复制一段指令宣称任何外设都能唤醒。

第六章 · 第 34 节

M4 的 SIMD：四个小加法与一个大加法不同

6.4.12 的 SIMD 与表 6.38—6.39，第 35—36 页；习题 6.46

掌握要求：理解 lane 内并行、跨 lane 不传普通加法进位，区分有无符号、饱和和半分系列。

背景为什么要讲：星号题要求理解背景和技术思想，不要求背完数十个变体，但原表各类都要见过。

SIMD=Single Instruction Multiple Data，单指令处理多份数据。图像像素、多个音频采样常用 8/16 位，32 位寄存器可装四字节或两个半字，一条相应指令对各 lane 独立运算。它不等于多核，也不意味着普通 ADD 自动隔断字节之间的进位。

原书 ADD8/SUB8 表示四对字节，ADD16/SUB16 表示两对半字；ASX 把第二源高低半字交换后，高通道做加、低通道做减；SAX 则高通道做减、低通道做加。下面前缀决定具体数值处理：

基本操作 S（有符号） U（无符号） Q（有符号饱和） UQ（无符号饱和） SH（有符号半分） UH（无符号半分）
ADD8 SADD8 UADD8 QADD8 UQADD8 SHADD8 UHADD8
SUB8 SSUB8 USUB8 QSUB8 UQSUB8 SHSUB8 UHSUB8
ADD16 SADD16 UADD16 QADD16 UQADD16 SHADD16 UHADD16
SUB16 SSUB16 USUB16 QSUB16 UQSUB16 SHSUB16 UHSUB16
ASX SASX UASX QASX UQASX SHASX UHASX
SAX SSAX USAX QSAX UQSAX SHSAX UHSAX

半分系列在扩展中间运算后按规则除 2/移位，不能先把窄结果截断丢掉进位再平均。例：无符号字节 250+10，正确半分为 130，而不是先回绕成 4 再除 2 得 2。

原书“Q/UQ 前缀的并行饱和运算都更新 Q”不准确。QADD8/QADD16 及相应并行 UQ 系列不改变 Q；SSAT/USAT、标量 QADD 等另按自身规则。S/U 非饱和系列的部分指令更新 GE，判据按有无符号、加减分别规定；不能将 GE 简化为普通“是否负数”位。Arm 作者对并行饱和标志的勘误说明

原表 SUB16 的有符号助记符缺 S，应为 SSUB16。知道命名构成并能解释 lane 独立性即达到本节基本要求，写优化 DSP 程序时再逐条查寄存器、溢出、GE/Q 细节。

M4 的半字乘加：BB、BT、TB、TT 选择哪两半

6.4.12 的乘法/MAC，表 6.40—6.41，第 36—37 页；习题 6.47

背景为什么要讲：原书只给部分 DSP 乘加例子，学习命名和适用算法即可，不要求现在实现完整滤波器。

SMULxy 选择两个源的一个 16 位半字做有符号乘法，结果为 32 位；SMLAxy 再加一个 32 位累加数。x 对应第一源，y 对应第二源，B=Bottom（低半字），T=Top（高半字）。

BB 低 16 位 低 16 位
BT 低 16 位 高 16 位
TB 高 16 位 低 16 位
TT 高 16 位 高 16 位

背景为什么要讲：SIMD 之前常要准备 lane，原书列举的几条均保留用途；旋转和扩展细节可查。

指令 主要结果
PKHBT 保留 Rn 低半字，与 Rm（可先 LSL）的高半字打包
PKHTB 保留 Rn 高半字，与 Rm（可先 ASR）的低半字打包
SXTB16 取 Rm 的 byte0、byte2，各符号扩展成半字，组成结果
SXTAB16 上述两份扩展值分别与 Rn 两个半字相加
UXTAH Rm（可先 ROR）低半字零扩展，再与 Rn 相加

例：Rn=0x11223344，Rm=0xAABBCCDD。PKHBT 不移位时得 AABB3344；Rm 先 LSL #16 后则取其高半字 CCDD，结果 CCDD3344。PKHTB 若 Rm 先 ASR #16，低半字为 AABB，结果 1122AABB。

VADD.F32 / VMUL.F32 / VSQRT.F32 单精度加、乘、平方根

星号题为什么还要讲浮点电路

定点的比例因子事先约定好，相同尺度的加减可直接用整数电路；浮点的每个数自带符号、指数和有效数。浮点加法需比较指数、对阶、有效数运算、规格化、舍入，再处理零/无穷/NaN 等情况；乘法还需指数运算与结果规格化。差别不仅是“多放一个小数点”。

整数与定点乘积共用电路，仍要按缩放选结果位并处理舍入/溢出；扩展指令则把不同宽度的 signed/unsigned 值送入更宽运算而保持原数值意义。知道这些因果，就能回答原章最后几道星号题，不必在本章手绘完整浮点加法器。

习题 6.51 / DSP 为何需要扩展 *

DSP 为什么需要符号扩展和补零？

展开答题要点

短采样/系数搬到宽寄存器计算时要保持原数值。signed 窄值应复制符号位，unsigned 应补零；否则负采样会误作很大的正数或无符号数误作负数，后续 MAC 再准确也处理错了输入。

为什么数据扩展用不同指令？
